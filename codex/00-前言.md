# 前言

<!-- block: codex-front.b-opening -->
这本书从命令、文件和会话的实际变化解释 Codex CLI，重点是让自动开发过程可检查、可恢复。

假设代理修一个测试，改了三份文件，终端上出现绿色提示，最后回答“完成”。审阅时仍需核对：测试是否在当前工作树运行，失败命令是否被正确报告，安装依赖时批准的权限是否仍然生效。重新打开会话，还要确认历史记录与磁盘内容是否一致。本书从这些日常操作出发，解释 CLI 在背后做了什么。

Codex CLI 值得研究的地方，是它把终端界面、非交互执行、协议服务、工具与平台约束放进同一个开源 Rust 工程。你既可以把它当成终端助手，也可以把它接进自己的客户端。两种用法都要经过真实的进程、文件系统和网络，不能只看模型回答。

## 本书固定哪一版

本书使用 `rust-v0.167.0`，源码提交为 `086ccc833bc9cf01024ad2dd6af7dbd421b6bf9a`，上游许可证为 Apache-2.0。标签对象与提交不是同一种 Git 对象；引用正文实现时，链接固定到这个完整提交。当前官网会继续更新，书中引用官网时会注明；涉及所用版本的实现，仍以对应源码为依据。

本机实际运行的是 `codex-cli 0.167.0` Windows x64 发布程序。没有登录新账号，没有向外部模型发送任务。已经完成的实验包括执行策略匹配、错误规则加载和 app-server 静态协议生成。它们经过真实二进制，既不是重写的教学匹配器，也不证明整条模型到工具的链路都已运行。完整清单在附录 C。

函数怎样接收配置、构造审批请求，按上述版本的源码讲解；命令在本机返回了什么，附上运行记录。两类材料会放在对应段落，便于读者回查。

## 从一个小仓库读起

全书跟做项目是一份运费计算器：1001 克错误地按首千克收费。随书模板包含一个纯函数、一组测试和一份简短的 `AGENTS.md`，不需要自己另造项目。先在独立副本里复现失败，再修改公式，就能对照命令、补丁、测试和最后答复。

每次运行前记下分支、提交与 `git status --short`；新建仓库还没有提交时，也把这个状态记下来。结束后读差异，运行项目要求的检查。会话历史解释修改理由，Git 差异展示实际改动，审阅时可以相互对照。

第一次跟做，可以沿第 1 章的离线检查进入第 3 章，复制模板并复现失败，再到第 11 章手动修复一行公式。这部分不用模型账号，Python 负责运行练习，Git 用来保留修改前后的状态。第 12 章接着把检查方法写成技能，用固定输入运行 Hook 处理器；它可以单独练习，不要求先把插件装进宿主。

准备让真实 Codex 做同一修复时，另取一份仍会失败的副本，按第 14 章保存执行日志，再到第 17、18 章练习恢复与交付。已有模型配置的读者也可直接走这条路线；本书没有运行这段模型任务。随书驱动已经确认的，是本地 Python 练习中错误版失败、修复版通过。

遇到运行机制问题，再回到第 4 至 10 章查会话、工具、审批、沙箱和命令规则。要接入外部服务或编写客户端，继续读第 13、15 章。这些章节解释练习背后的实现，不必在第一次修改公式前全部读完。

## 怎样读代码例子

带实际文件名的原创示例都放在 `codex/examples/`。`review.rules` 可以直接交给固定 CLI 检查；`check-local-cli.py` 会核对版本并保存脱敏结果。正文中的 JSON-RPC 消息用于说明协议字段，有些方法需要启动会话，不能据此说本书已经调用模型验证。

另有 `check_workshop.py` 检查运费、Hook 子进程和 JSONL 练习，`check_protocol.py` 检查消息与固定 schema 的一致性。前一个驱动只需 Python 标准库，适合先运行；协议检查需要额外依赖与对应版本的 schema，可到第 15 章再准备。

书中会切换两个目录。“书籍仓库根目录”是含有 codex 目录的本书源码目录；命令中出现 codex/examples/ 时，从这里运行。“运费项目目录”是第 3 章复制出的独立目录，例如 parcel-lab；运行项目单元测试、修改公式、查看项目 Git 差异和启动修复任务时，进入这里。不要把随书检查器的路径直接粘贴到运费目录中运行。

仅写 fixtures/、workshop/ 或 plugin-example/ 的示例文件位置，均以 codex/examples/ 为起点。随书驱动会自己创建临时副本，不会修好你手边的运费项目；后者的修改与测试仍需在项目目录完成。

Windows 的 PowerShell 与 Bash 在引号、环境变量和命令拼接上不同，因此书中尽量把动态参数交给结构化数组。遇到较长提示词、JSON 或规则正文，先存文件，再传文件路径。少一层壳解析，就少一类“明明写对了却被改成另一条命令”的问题。

读到一次工具调用时，可以沿着发起者、执行器、错误处理和保存结果往下追。后面讲 exec 和 app-server 时，也会沿这条路径核对它们的差别。
