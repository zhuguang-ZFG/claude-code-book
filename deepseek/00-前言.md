# 前言

<!-- block: deepseek-front.b-opening -->
编程代理能读文件、执行测试、修改代码。等到需要换模型、接入公司的权限规则，或停下一次出错的工具调用时，仅知道这些功能还不够：还得找到负责它们的模块，弄清替换或卸载之后有哪些工作需要收尾。

在 DeepSeek Harness 中，模型适配器、工具注册表、会话日志和默认 Agent 循环都由插件提供。负责加载这些插件、协调依赖和清理资源的框架叫 Cordis。例如，审查插件需要先取得工具表，才能登记自己的工具；工具表被移除时，依赖它的插件也要停止。本书从这样的关系入手，再读模型请求、会话恢复与完整任务循环。

## 本书读的是哪一个版本

本册固定仓库提交 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`，根 package.json 声明版本为 `0.2.2-rc.1`。这是一份开发者预览快照，不是“今后所有 dsh 都这样”的保证。文中的源码链接指向这份提交；滚动官网只作为查阅入口。你安装了另一个版本时，应先核对版本、配置结构和插件导出，再照着命令操作。

本书的实跑证据集中在这份提交内的 Cordis 框架组件。我们加载未经逻辑修改的 vendored TypeScript 源码，验证依赖等待、重新激活、失败清理、事件中间件与隔离作用域。它是真实上游组件，但没有把完整 Web 应用、远端模型、浏览器 UI 一起启动。相关章节分别标出源码契约、组件实跑和建议练习，避免读者把一种证据误当成另一种。

## 三条阅读路线

想先在本机看到结果，可以直接从第 1.5 节准备组件环境，运行七项基础场景，再带着输出读第 2、3 章。这条路线只需要本地运行工具，不需要安装完整 dsh 或配置模型账号；下载源码和依赖时需要网络。接着运行同一节的十三项连续实例，便能顺着文本统计工具读第 7、10、11、12 章，最后到第 16 章检查打包后的入口。

已经装好 dsh、想理解实际任务的读者，可以从第 1.1–1.4 节确认启动身份，再读第 6 章的任务循环、第 7 章的日志和第 15 章的权限。准备替换循环或接入已有系统，则把第 5、12、13、14、17 章连起来；这部分包含尚待读者在完整宿主中验证的集成设计。

阅读时可以跟住一次操作：找到接收请求、执行工具、记录结果和停止任务的代码。权限判断与提示词要求、聊天记录恢复与文件回滚，往往就在这条路径上分开。

## 贯穿全书的实验

从七个基础场景认识 Cordis 之后，我们会搭起一个完整的小实验：把文本交给 review_text 工具，返回行数、字符数和 TODO 标记。ReviewTools 提供工具表，ReviewJournal 保存事件，审查插件拥有自己的定义和监听。给它加策略、故障注入和延迟清理，就能沿同一条调用链看见依赖、执行、停止与重新激活。

连续实例的十三项场景与原七项基础实验分别留有记录，合计二十项。第 2、3、7、10、11、12 章逐步拆开实例，第 16 章把它打成本地包，第 17 章把各条路径重新连起来。完整代码在 examples 目录；正文中的短代码只解释其中一处机制。

这组实验不需要模型凭据。完整 dsh 应用的配置、模型恢复、远程 UI 和系统沙箱尚未实跑，对应章节给出源码位置、配置方法与观察步骤；读者自行运行后，可把结果补进附录 C 的矩阵。

本版提供中文正文。书中用源码位置配合讲解，不整段复制上游实现；需要继续查阅时，可从章末链接进入。本书是独立技术教程，与 DeepSeek 官方没有出版隶属关系。
