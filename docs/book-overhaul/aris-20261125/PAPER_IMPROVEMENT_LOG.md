## 第一轮问题与处理

**反向传播转置错误。** `train_demo.py` 前向采用行向量，`Y = X·W` 的输入梯度应是 `G·Wᵀ`。注意力输出投影漏了转置，Q/K/V 投影向输入回传时也把权重索引转置了。平方矩阵让错误在形状检查中不可见；小初始化下的少量梯度抽查和 loss 下降也没能排除错误。

修正两个计算位置，并新增全参数差分回归：两组 seed、`d_model=4`、FFN 宽 6、上下文长 4，放大非对称权重，输入包含重复 token。旧实现有 152 处参数梯度不一致；修复后全部通过 `1e-7` 绝对误差检查。此测试检验指定配置，不是对全部输入的数学证明。

重新运行原训练配置和恒定学习率对照，初始化与窗口抽样保持一致：

| 量 | 修复后结果 |
| --- | ---: |
| 固定窗口训练前 loss | 3.9886223903 |
| 8 个抽样权重最大梯度偏差 | 6.9321e-12 |
| 调度学习率，240 步后固定窗口 loss | 1.4882263073 |
| 恒定 `lr=0.6`，240 步后固定窗口 loss | 1.1210079168 |
| 调度训练的 step 60 / 120 / 180 / 240 loss | 3.92 / 2.19 / 2.32 / 3.20 |

正文和 `llm/VERIFY.md` 已更新。旧修订记录保留并追加纠错说明，防止把修复前的数字继续作为实现正确性的证据。第 7 章补上行向量反向公式及为什么形状、训练下降和小梯度抽查都不够；代码注释删除“数值检查证明公式正确”的断言。

## 第二轮问题与处理

**Chinchilla 的预算条件。** 原稿把“参数量与训练 token 数大致同比例增长”放在固定算力条件下，与 `C≈6ND` 冲突。对照论文摘要，改为随预算增加，各预算的计算最优配置中两者大致同比例增长；固定某个预算时两者仍需取舍。正文补充两者均翻倍会使这部分计算增至四倍，术语表同步。

**量纲与指标。** 练习明确 `EFFECTIVE_FLOPS` 只能填有效 FLOP/s，token/s 必须另用 token 总数估时。GPU-days 改为累计 GPU 使用天数并列出秒到天的换算。precision/recall 分别写明分母，弃权表沿用“回答内准确率”；SFT 定义扩回带监督目标的示范样本，再说明本章以对话 SFT 为重点。
