## 3. 主要优点（Ranked Strengths）

   - 明确反对“按频段把某几维固定指派给特定语义任务”的机械臆测（`ch04.md:105`）；

  1. 经逐元素坐标解析，SVG 左侧主干为 `y=120` 水平线（`x=28..388`），但在 `x=100, y=120` 处同时向上（`y=70`）和向下（`y=170`）分出两条**并行**支路；每条支路**先经过一个带 `+` 号的圆**（`(100,70)` 与 `(100,170)`），再进入矩形框（`128..220`），最后从矩形框右侧画出的箭头停在 `x=244` **悬空结束，完全没有接回 `y=120` 的残差主干**。这与正文 `h = Norm(x); x = x + Attention(h); h = Norm(x); x = x + FFN(h)` 的**串行两次“归一化 → 子层 → 加回主干”**拓扑不符（而且 `+` 号被画在了模块之前而非输出汇合点）。

#### [MAJOR-3] 关键符号重名与机制衔接缺口（`d` 与 `head_dim`、HF `rotate_half` 兼容边界、Pre-LN 末尾 Norm、`Swish` 定义）

- **位置**：`round0/source/ch04.md:10-20, 62, 65, 68, 105, 117`
- **核查事实**：
  1. **`d` 符号在相邻两节重名且漏掉“逐头作用”前提**：§4.3 (`ch04.md:65`) 刚用 `4d` 指代 `4 × d_model`（`4096`），§4.4 (`ch04.md:105`) 紧接着写出 `θ_i = base^(-2i/d)` 并只解释“`d` 是参与旋转的维度”，却未说明 RoPE 是在**每个注意力头（per-head）**上计算的，通常等于 `head_dim`（例如 7B 对应 `128`，共 `64` 对频率；若有 `partial_rotary_factor` 则是其中旋转部分），而非 `d_model`（`4096`）。若读者误代 `d = 4096`，所有 `i > 0` 的频率指数都会错 32 倍。
  2. **引用 HF 实现时遗漏 `rotate_half` 与相邻对配对的权重不兼容差异**：`ch04.md:96` 与 `transformer_demo.py:78-83` 按 RoFormer 原论文旋转相邻对 `(x_{2i}, x_{2i+1})`，而本章引用的 Transformers 实现（`sources/hf-llama.py:109-140`、`sources/hf-qwen2.py:50-81`、`sources/hf-mixtral-pinned.py:163-194` 配合 `hf-rope-utils.py`）全部使用 `rotate_half` 将向量拆成前半 `x[:d/2]` 与后半 `x[d/2:]` 配对 `(x_i, x_{i+d/2})`。虽然两者在权重行重排下数学等价，但若对同一套向量/已训练权重混用两种实现，点积会彻底算错（Python 实测 `q4=[0.4,-1.2,0.7,2.0]` 两种实现直接调用点积为 `+0.854` vs `-1.316`，重排后才回到 `+0.854`）。
  3. **§4.1 漏掉“末尾 Norm”的机理交代**：`ch04.md:12-17` 只给出 block 内部两次 `Norm`，到 `ch04.md:68` 才突然出现“省略偏置与末尾 Norm”。实际上 Pre-LN 论文（`sources/preln-2002.04745.txt:387, 594-595`）与所有真实模型（`hf-llama.py:344, 405`、`hf-qwen2.py:320, 395`、`hf-mixtral-pinned.py:411, 475`、`nanogpt-model.py:182`、`raschka-gpt.py:195`）都必须在最后一个 block 之后再接一层 `Final Norm` 才能进 `lm_head`——正是因为残差流在层间不归一化、模长会随更新累积（如脚本输出 `norm: 3.742 -> 3.850 -> 4.030`）。
  4. **`Swish` 未定义且未说明与 `SiLU` 的对应关系**：`ch04.md:62` 写 `Swish(W_gate · x) ⊙ (W_up · x)`，但全文和 `ch16.md` 均未写明 `Swish(x) = x · σ(x)`（`β = 1`），也没有告诉读模型卡的读者：在 Hugging Face `config.json`（`hf-llama-config.py` / `hf-qwen2.py`）里，它对应的配置字段值叫 `hidden_act: "silu"`。
- **具体修改建议**：
  1. 在 `ch04.md:105` 明确改写为“通常在每个注意力头内旋转，`d` 是参与旋转的每头维度（通常即 `head_dim = d_model / heads`，如 7B 中为 `128`，共 `64` 对坐标；若启用部分旋转则为乘以旋转比例后的维度），注意这里的 `d` 不是残差流总宽 `d_model`”；
  2. 在 `ch04.md:96` 或 `117` 补一句工程提醒：“脚本与 RoFormer 原论文按相邻坐标 `(2i, 2i+1)` 配对，而 Hugging Face Llama/Qwen2/Mixtral 常用 `rotate_half` 按前后半区 `(i, i + d/2)` 配对；两者差一次维度重排，自写推理核对齐权重时必须匹配原模型实现”；
  3. 在 `ch04.md:19` 末尾补一句：“正因为残差流本身在 block 之间不做归一化，现代 Pre-LN 架构会在全部 block 堆叠结束后、送入输出投影（`lm_head`）前额外加一层最终 Norm（参数量为 `d_model`，如 7B 模型多 `4096` 个参数，加上后为 `6,738,415,616`）”；
  4. 在 `ch04.md:62` 补一句括注：“其中 `Swish(x) = x · σ(x)`（取 `β=1` 时与 PyTorch/Transformers 配置里的 `silu` 相同）”。

#### [MAJOR-4] 参数表附注指向含混（`ch04.md:75`）与 `transformer_demo.py` 代理实现及死代码落差

- **位置**：`round0/source/ch04.md:70-75, 184`、`round0/source/transformer_demo.py:13-16, 39-40, 43-49`
