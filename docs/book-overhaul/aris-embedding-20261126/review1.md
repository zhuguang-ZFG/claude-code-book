## MAJOR-1：输出词向量用到了已经更新的中心词向量，不是所声明损失的同一步 SGD

**位置：** `source/llm/examples/embedding_train_demo.py:104–110`，尤其 109、110 行；声明见 `source/llm/ch02.md:70` 和脚本 127–128 行。

代码先计算 `score = u·v`、`grad = sigmoid(score) - label`，随后：

```python
vec[c][d] -= LR * grad * out[o][d]
out[o][d] -= LR * grad * vec[c][d]
```

第二行使用第一行更新后的 `vec[c][d]`，而 `grad` 仍来自更新前的 score。对一个二元损失 `L = softplus(u·v) - y(u·v)`，梯度应为 `dL/du = (sigmoid(u·v)-y)v`、`dL/dv = (sigmoid(u·v)-y)u`，其中两个向量均来自同一前向状态。这也不是完整的交替坐标梯度更新，因为更新 `v` 前并未重新计算 score。

**实际数值证据：** 隔离一个正例，`u=0.4`、`v=0.7`、`LR=0.03`，中心差分步长 `1e-6`：

| 项目 | 数值 |
| --- | ---: |
| 数值 `dL/du` | -0.301317643225385 |
| 数值 `dL/dv` | -0.1721815103272739 |
| 正确 SGD 更新后 `u` | 0.4090395292967616 |
| 代码更新后 `u` | 0.4090395292972762 |
| 正确 SGD 更新后 `v` | 0.7051654453098182 |
| 代码更新后 `v` | 0.705282178298324 |
| 代码对 `v` 实际施加的梯度 | -0.17607260994413343 |

输出侧梯度约有 2.26% 相对偏差，远超差分误差。默认语料仍能收敛和分组，因此现有“主题分组成功”测试不能发现它。

**最小修复：** 每个维度先保存更新前的中心值和输出值，两个更新都基于保存值；或先计算完整的两组梯度再更新。增加一个正例和一个负例的单步数值梯度检查，检查两张表。修复后重跑训练并同步正文中实际变动的四舍五入数字，不必扩展成自动微分框架。

## MAJOR-2：按向量值排除“查询自身”，会删除身份不同的正确候选

**位置：** `source/llm/examples/embedding_demo.py:40–45`，尤其 `if vector != query`；调用处 70–74 行；正文自身排除说明 `source/llm/ch02.md:46`。

向量相等不等于文档身份相同。当前函数只有查询向量，没有查询条目 ID，却把所有与查询逐元素相同的候选都删掉。

**实际数值证据：**

```python
query = [1.0, 0.0]
top_k(query, {
    "best_document": [1.0, 0.0],
    "weaker_document": [1.0, 1.0],
}, 2)
```

只返回 `weaker_document`，余弦约 0.707；完全匹配的 `best_document` 消失。把库改为 `query`、`distinct_document` 两个相同向量条目加一个较弱条目，同样把两个相同向量条目全部删除。默认七个向量没有完全相等的行，所以正文表格不受影响，但读者按 2.10 节增加条目或把函数用于外部查询即可能遇到此问题。

**最小修复：** 增加可选 `exclude_name`／`exclude_id`，默认不排除候选；示例内部查近邻时显式传入查询名称。按 ID 排除，不能改成对象 `is` 比较。增加“相同向量但不同 ID 应保留”和“外部查询完全匹配应排第一”两个针对性检查。

## MINOR-1：ANN 与 exact 的同距排序规则不同，会产生假的 recall 损失

**位置：** `source/llm/examples/ann_demo.py:46–49` 与 84–91 行；相关保证测试为 `source/tests/test_llm_examples.py:1288–1298`。

exact 从递增 ID 列表稳定排序，同距时按 ID；IVF 从桶的探测顺序拼接候选，同距时保留桶顺序。因此全桶扫描也可能返回不同的 top-k ID。

**有限反例：** 内存中令 `K=1`，查询 `(0,0)`，点为 `[(-1,0),(1,0)]`，桶为 `[[1],[0]]`，中心为 `[(1,0),(-1,0)]`。exact 返回 `[0]`；`nprobe=2` 已扫描全部两点，IVF 仍返回 `[1]`。两者几何距离同样正确，但按本例 ID 集交集算 recall 会得到 0。

默认连续随机点未出现该现象，现有结果表正确，因此定为 MINOR，不把它表述为搜索距离算错。**最小修复：** 两条路径使用相同的 `(distance, point_id)` 排序键，并加一个对称同距案例；这样教学指标不会把任意 tie-break 误报为近似误差。

## MINOR-2：术语表把预测目标简化成同表向量拉近，把采样负例写成确定非共现词

**位置：** `source/llm/ch16.md:24–25`；实际实现是 `embedding_train_demo.py:82–83` 的输入／输出两张表和 104–110 行的跨表点积；正文较准确的解释在 `ch02.md:70–74`。

“skip-gram：用窗口内上下文词拉近中心词的 embedding 训练目标”容易让初学者以为直接优化最终返回输入词表中两词的余弦；代码实际优化中心输入向量与上下文输出向量的预测分数。相似上下文促成输入表示相近是本例的学习结果，并非每个正对直接约束两条输入向量。

“negative sampling：随机负对把非共现词推开”还把被抽作负例等同于真实不共现。此脚本只排除当前句子中该中心的已知上下文和中心自身；默认受控语料恰好使负例全来自其他主题。一般负采样不保证不存在假负例，正文 2.6 已明确讨论这一点。

**最小修复：** 两行分别改成“用中心词预测窗口内上下文词、学习静态词表示的训练目标”和“抽取词作为负例，降低中心—负词配对分数；采样项可能是假负例”。如保留“拉近／推远”，应限定为所用配对分数，不保证最终输入表余弦。

## 已核实成立的内容

- 两组 embedding 参数量与 fp16 体积、10 万 × 4096 维 fp32 的约 1.5 GiB、409,600,000 次点积乘加均与脚本一致。这里是向量本体／点积扫描账，不应额外要求它包含索引元数据或排序开销；正文已限定存储范围。
- A/B 点积和余弦排序不同的示例正确；“退款”与“不退款”余弦实值为约 0.9997，表格保留三位后为 1.000。正文明确是几乎同方向，未把舍入值当严格等同。
- 默认训练 36 句、12 词、16 维、30 轮结果可复现；退款近邻为售后 0.9933750、换货 0.9915550、退货 0.9820440。独立检查全部 12 个词，各自三个近邻均属于同主题，正文“全部”在本冻结版本上真实成立。
- 代码现有统计和测试仅要求 top-3 中至少出现一个同主题词，比正文结论弱；不因此推翻已独立核实的结论。修 MAJOR-1 时宜把回归检查加强到实际声明的三个邻居都同主题。
- 对每句、每个中心枚举允许采样集合，默认语料的允许负例全是其他主题；“排除当前句子的已知上下文”与实现相符。没有把该定制采样策略等同于完整经典 word2vec 实现。
- InfoNCE 公式、批内负例复用文档编码但仍需算相似度、假负例风险和 Matryoshka 必须专门训练后才能按前缀截断，表述基本准确。
- IVF 默认结果复现：扫描比例 13.2%、25.0%、51.9%、100.0%，recall@10 为 0.865、0.997、1.000、1.000；最差查询 0.30、漏 7 个 ID。正文区分了近似邻居召回与后续完整检索质量指标，没有声称这是生产性能基准。
- 训练损失由 epoch 1 的 0.5398529 降到 epoch 30 的 0.0004892；输出 `0.000` 是三位小数舍入，未据此判定真实损失为零。正文也未把训练损失下降当泛化能力证明。
