## MAJOR

### MAJOR-1：固定 seed 示例反复重置随机状态，没有演示连续抽样的可复现性

**位置：** `source/llm/examples/sampling_demo.py:102`、`:104`；`source/tests/test_llm_examples.py:763`；`source/llm/ch05.md:72`（§5.4，PDF 第 47 页）。

**证据：** 两个列表推导式都把 `random.Random(11)` 放在每次 `sample()` 调用里面。八次调用创建八个相同初态的生成器，每次消费的都是同一个首个随机数；这不是一个 seed 初始化后产生的连续八次抽样。`test_same_seed_and_order_repeat` 复制了同一写法，仅比较两个退化列表相等，因而没有发现问题。

独立执行结果：

```text
每次重置：['首都', '首都', '首都', '首都', '首都', '首都', '首都', '首都']
持续使用同一生成器：['首都', '首都', '城市', '首都', '首都', '首都', '首都', '首都']
```

**影响：** “同 seed、同调用顺序可重放序列”这一正确概念，被一个重复首次抽样的实现支撑。读者照抄后会人为消除随机序列的变化，尤其违背本章解释随机性的目的。

**修正：** 在两轮实验开始时分别创建 `rng_first = random.Random(11)` 与 `rng_second = random.Random(11)`，各自在自己的八次抽样中持续使用。预先构造同一分布即可。相应测试应验证两个完整序列相同，并验证随机状态确实推进；可用可控的随机数序列或此固定夹具验证第三次抽到“城市”。不要把“所有随机实验必须出现多个 token”写成通用断言。正文保留 seed 的正确结论，只同步真实演示输出。

### MAJOR-2：束搜索被写成保证“整体最优”，并附带证据不足的任务概括

**位置：** `source/llm/ch05.md:20`（§5.1，PDF 第 45 页）；相关定义 `source/llm/ch16.md:81`（PDF 第 129 页）；来源注册表 `text-degeneration.scope`。

**证据：** 正文写“每步保留联合概率最高的前 k 个候选序列，最后取整体最优”“整句联合概率和任务目标一致”“现代 LLM 的解码几乎都用采样”。有限宽度束搜索只扩展当前保留的路径，被剪枝的路径可能包含全局最优解；“整体最优”没有这一限制。句子概率与翻译/摘要的任务质量也不是同一个目标。

可直接构造反例：第一步 A、B、C 的概率为 0.5、0.3、0.2，束宽 2 删除 C。第二步 A 和 B 后各有 10 个等概率后继，最佳完整路径概率分别只有 0.05、0.03；C 后若只有一个确定后继，完整路径概率为 0.2，却早已被删掉。这说明“最后取整体最优”作为算法保证不成立。

重新取得的 Holtzman 等作者摘要支持“在其开放生成研究中，似然最大化解码会产生平淡、重复的文本，并由此提出 nucleus sampling”。该摘要没有证明所有现代 LLM 的解码采用比例，也没有证明“多峰”必然导致“最平庸的峰”，更没有把结构化抽取限定为束搜索的主要归宿。正文的经验观察应保留，后续泛化不应借同一引文扩张。

**修正：** 改成“每步扩展保留下来的候选，按累计对数概率或带长度校正的分数保留 k 条；最后从搜索到的候选中选最好的一条。有限束宽不保证全局最优。”可保留 k=1 对应贪心的基础解释，不必展开所有工程停止条件。用途改为“常用于翻译等条件生成任务；开放生成中，高似然搜索可能降低多样性并出现重复，Holtzman 等据此研究 nucleus sampling”。删除无数据的行业比例断言及概率目标等同质量的说法，术语表和来源 scope 同步。

### MINOR-4：术语表的局部定义与正文预算口径不完全一致

**位置：** `source/llm/ch16.md:23`、`:76`、`:87`；生成/上下文词条在 PDF 第 129 页。

- `output reserve` 写成含“安全余量”，而第 1、6 章和脚本把二者分别相加。改成“预留给模型本次生成的回答或工具参数的 token”，安全余量另说，避免双算。
- `softplus` 被定义成“log(1+e^x) 的分段稳定实现”。softplus 是函数本身，分段计算是稳定实现方式。建议“函数 log(1+e^x)；可用稳定形式计算，log σ(x) = −softplus(−x)”。
- `tokenizer fertility` 只有“切分粒度”而没有计量方式。建议明确常用含义是平均每个词被拆成多少子词 token，并说明中文需先约定词/字等分母；第 1 章的 `tokens / 字符` 是本表采用的具体比率，不能省掉分母。

### MINOR-5：字符切片与字节截断混为一谈

**位置：** `source/llm/ch01.md:159`，及 §1.5 截断段；PDF 第 18 页。

“直接切字符串截断 → UTF-8 半个字符”在本章的 Python 环境中不准确：普通 `str` 切片按 Unicode 码点进行，不会切出半个 UTF-8 字节序列；`bytes` 切片才有该问题。Python 字符串切片仍可能破坏组合字符、JSON 和消息结构。建议表格区分“按字节截断可能破坏 UTF-8”与“按字符串长度硬切可能破坏消息/结构”。正文也可说“按 UTF-8 字节切片时，截断可能导致严格解码报错，或在替换模式下出现替换字符”，避免暗示默认解码一定自动替换。

1. **补 FlashAttention 的直接出处。** 第 6 章明确解释了 FlashAttention，却在本范围注册来源中没有对应条目。可加 [FlashAttention, arXiv:2205.14135v2](https://arxiv.org/abs/2205.14135v2)，注册版本和用途。已独立读取作者摘要，支持其 IO-aware、分块及减少 HBM 读写的描述。正文“没有把精确密集注意力的算术量变成线性”值得保留。

4. **prompt caching 有必要给一个具体一手入口。** 本章的抽象解释合理；可链接已注册的固定版 vLLM prefix-caching/APC 文档或明确访问日期的提供方文档，让读者核对缓存匹配、命中和定价。不要用一个实现的细节替代跨提供方结论。
