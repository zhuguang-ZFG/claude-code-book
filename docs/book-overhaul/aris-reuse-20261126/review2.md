## 总评

两章已形成清楚的教学链条：第 1 章把码点、字节、token 和预算口径分开，第 3 章从可手算的注意力推进到多头、参数和缓存。主要算术、代码输出、遮罩位置以及 minbpe 复用范围都可信；没有发现关键机制错误、数字造假或遗漏 MIT 许可的问题。

未给出 Ready 的主要原因是一项实际复现障碍：BPE 示例使用了 Python 3.12 才允许的 f-string 写法，Python 3.11 在解析时即失败，而当前章内只给出普通 `python` 命令和“只用标准库”的说明。另有手机表格、PDF 代码颜色和几处措辞可做小幅调整，不需要增加生产系统复杂度。

## 优点（按重要性排序）

1. **算术能从正文追到可执行结果。** 五组 BPE 样本的码点、字节、token、比率全部匹配；单头、无因果遮罩、两个头的输出以及 MHA/GQA/MQA 参数表均与脚本一致。128 KiB/token × 131072 token = 16 GiB，累计输入与单次窗口也没有混淆。
2. **缓存解释抓住真实的容易出错处。** `query_start` 将非方阵查询的绝对位置讲清楚；单行和分块追加与完整因果计算对照，并明确不把该核对当作加速比实验。固定版本 PyTorch 的左上对齐说明与文字一致。
3. **复用是真实而且边界明确的。** 脚本实际调用 vendored `merge` 与 `BasicTokenizer.encode`；多文本边界、字典序并列处理、严格 UTF-8 解码则留在本地。上游三份文件与固定提交逐字节一致，完整 MIT 版权及许可随文件保留。
4. **因果表述克制且具体。** 客服地址配错并未被直接归因于某个注意力头；文本区分“可见”“混合比例”和故障归因。MLA 也没有被简化为固定比 MQA 再省一档的配置开关。
5. **图示承担实际教学任务。** 第 3 章两张 SVG 分别展示下三角可见关系及分数到权重再到加权输出，标题、图内数字与正文一致。图形通过实心点、叉号和文字区分状态，不依靠颜色。

## 分级问题

### CRITICAL

未发现。

### MAJOR 1：BPE 示例有未声明的 Python 3.12 语法门槛

- 位置：`source/llm/examples/bpe_demo.py:105`；第 1 章 §1.3、§1.4 的运行说明。
- 实际复现：使用本机 Python 3.11.15、`-X utf8 -B -S` 执行冻结脚本，在任何示例输出之前报错：

  ```text
  SyntaxError: f-string expression part cannot include a backslash
  ```

- 原因：`{len('e\u0301')}` 把含反斜杠的字符串字面量放在 f-string 表达式中。Python 3.13.14 可以解析，3.11 不行。标准库依赖说明不能让读者知道这个语法版本要求，故这里是运行契约缺口，不是算法错误。
- 最小修复：先定义 `combining_text = "e\u0301"`，输出时写 `{len(combining_text)}`。这样不改变示例内容，也不增加依赖。另一选择是在章节给出明确的 Python 3.12+ 前提，但这对一个演示 Unicode 计数的小程序没有必要。
- 验证建议：对修改后的文件用 Python 3.11 做一次直接执行与包导入即可，无需建立复杂版本测试矩阵。若全书在本次范围之外已明确硬性要求 Python 3.12+，此项可降级为章内环境提示问题；本次没有借用未获授权的外部本地文件来假定该前提。

### MINOR 1：手机多头表把向量拆碎，读者难以比较各头

- 位置：第 3 章 §3.3 的“头 / 青禾 / 工作坊 / 报名”表；证据 `review2-mobile-head-table.png`。
- 390 × 844 视口下，“维度 0 的权重”几乎逐字竖排，`[1.000, 0.000, 0.000]` 被拆成多行，个别逗号独占一行。数字没有丢失，但矩阵行的整体形状被破坏。
- 同一页面的参数表已经能在独立容器内横向滚动；多头表却被压缩到 324 px，未触发横向滚动。全页宽度为 390 px，没有页面级溢出。
- 修复：给这一张向量表适当最小宽度并保留容器内横向滚动，或把两个头的三行权重各自列成小表。不要为适配手机进一步缩小文字。

### MINOR 2：PDF 代码高亮沿用浅色，弱化了字符串和符号

- 位置：PDF 第 15–17 页，特别是第 16 页长 BPE 程序；也可见于第 34–35 页缓存代码。
- 实际视觉：浅绿字符串、浅橙导入标记与浅米色背景接近，正常页面缩放下比正文和黑色标识符明显难认。第 16 页完整代码没有裁切，但颜色削弱了阅读质量。
- 浏览器 print 样式核对显示字符串色为 `rgb(169, 196, 108)`；在页面近白背景上对比度不足约 2:1。这是观察到的颜色问题，不是未实测的排版推测。
- 修复：打印样式中使用更深的字符串、数字、标点颜色；也可统一为深色代码，仅保留字体粗细区分。无须改动代码正文。

### MINOR 3：实验收尾把“算出的注意力权重”说成“手设权重”

- 位置：`source/llm/ch03.md:189`：“这些权重是手设的”。同章开头与代码已经说明输入向量和投影矩阵是手设的，而权重由点积与 softmax 计算。
- 影响：本章正在帮助读者区分投影参数和 attention weights，结尾使用同一个“权重”称呼会重新混淆二者。
- 修复为：“输入向量和投影矩阵是手设的；注意力权重由上述公式算出。这个例子验证算术和形状，不代表真实模型学到的模式。”不需要再增加额外限制段落。
- 同处小笔误：`ch03.md:182` 写“然后试三组改动”，实际有四项，改为“四组”或“下面几组”。

### MINOR 4：术语表把常见头维度关系写成无条件定义

- 位置：`source/llm/ch16.md:47`：`head dimension` 被定义为“每个注意力头的宽度，d_model / heads”。
- 第 3 章正文准确限定了“常见的等宽多头结构”，但术语表省略了这个前提。读者刚学到 MLA 等不同结构，可能将该等式推广到所有模型的 query/key/value 维度。
- 修复：改为“每个注意力头的宽度；常见等宽结构中为 d_model / heads”。这只需补回正文已有的限定，不必展开新架构。
