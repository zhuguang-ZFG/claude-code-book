# 规格：提示词工程分册与跨项目系列

建立：2026-11-10。用户同意新增提示词工程分册，并询问 `dmx` 项目是否适合同属一个系列。按“先定系列定位和目录，再写新册”的次序完成规划与试章后，用户继续授权全稿、并行写作和去 AI 味审读；当前交付中文技术试读版及本地配套材料。

## 产品目标

新增《提示词工程：从提问到 Agent 协作》，作为“大模型与智能体工程”系列的通用方法册。用原创“青禾工作坊报名助手”连接需求说明、材料选择、工具执行、协作和评测，读者最终能交出可复做的任务及接手说明。

系列内容分工与调研依据见[系列定位](../../series/README.md)，前言、四篇十八章和附录 A–D 的范围见[目录](../../series/prompt-engineering-outline.md)。

## 定位阶段完成条件（已完成）

1. 确认 `dmx` 中适合加入的具体课程，而不是仅凭目录名判断。
2. 阅读实际章节与实验记录，列出与新册的重复内容及深化方向。
3. 给出按读者目标选择的跨书路线，保留原课程先修和验收要求。
4. 完成新册目录、贯穿案例、各章交付和后续工作次序。
5. 记录已有成品和仍未验证的范围；规划不伪装成正文或出版完成。

定位、目录、原创材料和三篇试章已经完成。当前范围包括前言、十八章、附录 A–D、离线练习，以及本地 HTML/PDF/EPUB 与独立练习 ZIP；完成依据为材料可独立阅读、离线示例可运行、正文可跟做且实测范围清楚。课程仓库继续按自身任务推进，两个构建系统保留；对外发布、目录改版和内容迁移属于后续实施。

## 写作与实验要求

前两篇适合非程序员。第一次使用术语就在当前情境解释；进入脚本和 Agent 任务前补目录、文件、JSON、退出码和工具回执所需知识。每章包含足以跟做的材料及失败情况，具体结构由内容决定。

以同一项目展示提示修改前后的差异。真实对照保存输入、提示版本、运行环境、参数、响应和判据；无法固定的因素单独说明。运行失败、没有提高、结果有波动都按原样保留，不删题或重复到满意后只留最好结果。

格式检查、原文匹配、业务断言与自然语言正确性分别说明。程序不能替任意陈述做事实裁判；模型自检也不能直接当作独立验证。要求可核验的理由、算式、引用和中间产物，不要求披露隐藏推理过程。

关于工具权限、项目规则、Skill、MCP 和会话的实际行为，使用对应工具分册的固定版本和可定位来源。通用提示没有被全部宿主实测之前，不声称可以原样跨工具运行。后续涉及具体模型与 API 时，继续逐项核对固定版本资料；本阶段离线示例不依赖模型 API。

人工教学材料、程序结果、真实模型输出分别标注。新册不自动继承其他项目的模型调用或收费权限；需要实际服务时按当时可用环境与用户授权运行。未实测章节可以提供读者练习，但不能用占位结果交付成“效果对照”。

## 与大模型课程的关系

大模型课程已有 C02 任务约定、C14–C15 检索、C18 评测、C20 上下文、C21 Agent 和 C22 成本取舍。新册展开任务的连续修改、示例选择、交接、跨工具迁移及提示变更回归；原理、完整应用和训练回查原课程。

对方 EVALUATION-04 中“消除提示冲突但分数未提升”的记录可作为候选案例，引用时注明出处、原环境和未在本册复跑的事实。原始八题包含不同类型的检查，不能把总分差异简化为通用提示效果。

材料、图片与代码的复用逐项确认来源和许可。既有来源声明保持。共同品牌、阅读导航和交叉引用不代表合并所有内容的授权，也不把技术试读版改称教学验收完成。
