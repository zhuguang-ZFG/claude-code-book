# 十二卷书稿与插图深度精修设计

**日期：** 2026-11-24

**状态：** 设计已获用户确认，待用户审阅本文后再制定实施计划

**范围：** 十二卷中文正文及其所属插图源稿；不直接编辑合订本生成物

## 目标

系统审阅十二卷的行文、教学路径、技术说明与插图，在保留事实依据、版本边界、各卷结构和视觉个性的前提下，精修影响理解与阅读体验的内容。不是为了增加篇幅或制造统一模板而改写；每项修改都应解决可说明的阅读、准确性或视觉问题。

## 编辑标准

### 正文

- 逐章检查问题提出、概念解释、论证顺序、例子与结论之间的关系，以及章节间的承接。
- 修正含混、重复、术语首次出现缺少解释、结论缺少推理支撑和阅读节奏不当之处；只在知识缺口确实妨碍理解时补充内容。
- 按各卷来源登记和版本钉点核对技术行为、命令、接口、指标与时间敏感结论。区分上游事实、作者推断、教学简化和建议；没有依据时不擅自改事实或更新版本。
- 保留仍有效的代码示例及其验证语义。确需修改时，应检查相关测试或以实际执行结果验证。
- 保持 `<!-- block: ... -->` 等稳定块标识、跨章引用和构建器派生结构；不手改生成的锚点、编号、索引或脚注。
- 依照 `CONTRIBUTING.md`、分册指南、来源清单及现有术语契约维护标点、空格、围栏和书内术语，不用统一套话抹平各卷差异。
- 按各卷既有约定更新版本说明或修订记录；没有相应维护页的分册不另造一套重复机制。

### 插图

- 检查每卷封面、篇题图、章徽、正文插图、Mermaid 图及其图注，重点看语义正确、图文对应、视觉层级、字和线条的可读性、版面放置、无障碍说明、暗色屏幕和打印效果。
- 不把「所有图都重画一遍」当成目标。每张图都经过审阅；仅当有明确的语义、可读性、一致性或技术契约问题时才修改，并记录修改理由。
- 保留各卷既有视觉身份、资产所属关系和适合内容的图型；不强行统一跨卷画风。
- 遵守各资产管线约束。需要手绘修整时按项目 SVG 约定修改；保留已验收的透明墨版 PNG。此轮不调用生图服务，不新增生成式图像资产。
- 保持插图命名、图注、`ill` 围栏、可访问性、动画与资产目录归属的一致；符合每卷的体积、颜色和 SVG/PNG 检查规则。

## 执行顺序

1. **全量基线审计：** 按 manifest 枚举十二卷的所有单元、来源、例子、图稿和对应测试。先汇总各卷问题与优先级，不先动稿。
2. **校准卷：** 以《御舆》作为首卷，完成正文与关联插图的精修，验证审稿标准是否能改善理解而不破坏内容契约。若发现标准需要调整，先更新本设计与审计记录。
3. **逐卷精修：** 按合订本顺序处理其余分册。每卷按“正文段落—关联图稿—图注与排版”整组检查，避免图文各自完成后语义失配。每完成一卷，立即跑该卷检查与目标构建。
4. **全集成：** 所有分卷完成后运行全仓快速检查、重建十二卷合订本，并核对最终构建中引用、图像、导航及内容均来自最新源稿。

## 验收

- 十二卷中 manifest 登记的所有正文单元和所属插图均完成审阅；审计问题有已解决状态或明确的证据型结论。
- 正文修改提升了清晰度、连贯性或准确性，没有为扩写而扩写；事实和技术行为仍可追溯到书内证据或登记来源。
- 插图均检查了语义、图文对应、可读性与适用的屏幕/打印约束；所修改图稿符合该产品资产管线和无障碍约定。
- 每卷适用的单元测试、内容检查及 HTML/PDF/EPUB 构建通过。若仓库的官方构建入口与此处文字不一致，以当时的 `yuyu-book/PRODUCTS.md` 和分卷 `VERIFY.md` 为准。
- `python scripts/bookctl.py check --fast` 通过；十二卷合订本的 HTML/PDF/EPUB 构建通过；新增或修改的示例测试通过。
- 保留独立的修改记录，按分卷列出主要文字与插图变化、未改动的合理原因及验证证据。

## 明确不做

- 不修改书籍构建器、CI 架构、manifest 产品拓扑或十二卷组成。
- 不自动刷新上游来源、不重钉版本、不把作者解释改成上游事实。
- 不修改停止维护的英文整书镜像，也不因语言或视觉对称而制造重复资产。
- 不用生成式图像替换或补充现有图稿。
- 不把合订本生成文件当作内容真源直接修改。

## 风险与控制

| 风险 | 控制方式 |
|---|---|
| 事实或版本敏感的段落被过度润色 | 改动前确认来源钉点，无法核实的内容保留并列为审计项 |
| 全书级编辑导致稳定标识、引用或派生结构漂移 | 使用内容门禁和 block marker 检查；改后重建各产品 |
| 跨卷套用单一叙事模板削弱作者声音 | 以清晰、连贯、准确为共同尺度，不规定固定章节模板 |
| 视觉统一抹去分册识别度，或图义与正文脱节 | 按卷审阅并与文字一起精修，只处理有证据的问题 |
| 合订本构建耗时或暴露集成问题 | 先完成逐卷验证，最后执行全集成构建；保留逐卷失败证据便于定位 |
