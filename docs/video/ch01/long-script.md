## 块 1｜开场钩子

大家好，这里是小电讲电路。今天开一个新系列——驭者·Agent Harness。第 01 讲先打地基：为什么做 Agent，不能只包一层 API。

[ANIM:chatbot-glue]

二零二三年前后，大家跟大模型打交道多半是这样：打开网页，敲一段提示词 Prompt，等它吐出文字。代码自己复制进编辑器，命令自己切到终端跑，报错再贴回对话框。人成了系统胶水。同步、单轮、纯文本——LLM 只会说话，不会做事：读不了文件系统，跑不了测试，建不了分支，更别提出错后自己改策略。

现在不一样了。Agent 会自己决定调哪个工具、传什么参数、结果怎么接回去。LLM 的价值不再只是生成段落，而是当推理引擎去编排工具调用。可工具一多、失败一多、权限一乱，简单封装立刻撑不住。这就是本集要讲的 Agent Harness——围绕大模型的运行时框架，也是「驭者」隐喻的核心：模型是马，Harness 是缰绳和鞍具。

## 块 2｜§1.1 范式转移

先从范式转移说起。书稿第一节就叫：从 Chatbot 到 Agent。

[ANIM:llm-roles]

过去，LLM 更像被关在房间里的博学参谋：只会口述，拿不到听诊器，也抓不了扳手。知识停在训练截止日，推理困在上下文窗口，输出只能是人能读的文本。有了工具调用 Tool Use，边界被打开：可以搜网拿实时信息，可以调代码解释器做计算，可以读写文件系统，可以操作 Git。每一次工具调用，都是跟真实世界握一次手。那个困在房间里的朋友，现在有了电话、机械手臂，还有连向整个互联网的线。

参谋和指挥官的差别也在这里。参谋的指令要传令兵逐级传达；指挥官的命令可以毫秒级落到作战单元。当模型从「回答问题的人」变成「决定调什么工具、传什么参数、怎么处理返回」的决策中枢，能力边界就被拉开了。

但握手一多，工程问题就来了——而且已经不是模型层，而是系统工程层。

[ANIM:six-challenges]

书稿列了六大挑战。第一，工具注册与发现：谁管注册表，模型怎么知道有哪些工具，能不能动态加。第二，参数校验：类型错了、缺字段、越界，校验放哪一层。第三，权限管控：模型可能要求执行高危命令，什么时候该拦。第四，错误恢复：超时、格式不对、工具失败，没有策略就会死循环重试。第五，状态一致性：多轮操作同一资源，怎么避免读到过期数据。第六，并发与调度：哪些能并行读文件，哪些必须先建目录再写。这六个问题，一起催生了 Agent Harness。

很多人以为 Harness 就是 API 外套个壳，再加 while 循环：调模型、解析工具、执行、拼回 Prompt、再调。听起来够用，其实默认了理想世界——永不超时、格式永远对、用户不看进度、上下文无限、操作全安全。生产里这些假设会被逐个打破。

[ANIM:car-remote-vs-autonomous]

真正的 Harness 要正面硬刚这些事。流式输出怎么边想边画，还不把主线程卡死；权限拦在外层还是嵌进每个工具，如何既安全又不太烦用户；上下文满了怎么压缩，还不丢掉关键决策信息，并和缓存协同；错误怎么有统一恢复框架，而不是每种失败写一段补丁；会话中断后状态怎么接，子智能体怎么共享还不互相踩；第三方怎么安全注册新工具，怎么接 MCP，也就是 Model Context Protocol。每一项都够单独开工程专题。Harness 的价值，是用统一框架系统地收进来。

打个比方：简单封装像给汽车装遥控器，能进能退，却没有助力、刹车和气囊。Agent Harness 是整辆能跑、能停、能诊断的自动驾驶车——不光有引擎，还有悬挂、制动、约束和诊断。

一句话定义：**Agent Harness 是围绕 LLM 构建的运行时框架，把文本生成器提升成能安全、可靠、高效与外部世界交互的自主智能体。**

[CODE:anti-pattern-while]

反模式警告也原样提醒你：如果核心循环还只是 while true、call API、parse、execute，请先停一下。流式、上下文、错误恢复想清楚了吗？没想清楚，你需要的不是再多写几行胶水，而是一套 Harness。

## 块 3｜§1.2 全景架构

概念有了，用 Claude Code 当标本看全景。先从宏观尺度看代码库——数字本身就有信息量。

[ANIM:ai-tools-timeline]

时间线很清楚。二零二一年六月 Copilot 技术预览，把 LLM 推进编辑器；ChatGPT 证明通用对话能力；GPT-四加上 Function Calling，模型从文本生成器变成指令编排器；Code Interpreter 首次给了代码执行能力；Claude 支持 Tool Use 并拉大上下文窗口。二零二四年前后，Devin、Cursor Agent、Computer Use 一路给模型加行动力。二零二五年 Claude Code 以终端原生 Agent 出场，随后 MCP 推动通信标准化；源码公开后，社区才把 Agent Harness 摊开细看。规律只有一句：演进方向始终是给 LLM 更多行动能力——从看见当前文件到整个项目，从给建议到执行命令，从单步到多步自主规划。Harness 是这方向在架构层面的必然产物。

[ANIM:scale-1884-512664]

再看体量。src 里有 **一千八百八十四** 个 TypeScript 文件，合计 **五十一万两千六百六十四** 行。一个终端工具，体量接近 VS Code 核心那一档。这说明可靠 Agent 的工程复杂度不亚于完整编辑器框架。它不是臃肿，而是高度模块化：工具独立、子系统边界清楚。模块化，正是 Harness 可维护性的关键保障。

[ANIM:arch-layers]

架构从上到下几层。入口 Entry：CLI 解析、启动优化、React 加 Ink 初始化。查询引擎 QueryEngine：会话状态、消息历史、文件缓存、用量统计，同时服务交互式终端和无头 SDK。心脏是对话主循环，一个 AsyncGenerator：预处理压缩裁剪，调 API 流式收，工具检测与权限检查，再构建状态、回填消息。旁边是工具系统——约五十五个工具、编排与并发分区；权限管线——四阶段检查、多种模式、规则可持久化；再外是扩展层：MCP、子智能体、插件、Hook。主循环是心脏，驱动数据在子系统之间流转。

[ANIM:tech-stack-table]

技术栈也很克制。运行时 Bun，图启动快和原生 TypeScript。终端 UI 用 React 加 Ink，声明式组件——终端不该是二等公民，进度条、权限框、多列结果背后都是组件树。CLI 用 Commander.js。校验用 Zod 第四版：运行时类型安全，还能生成 JSON Schema 喂给模型，让参数含义和约束写进类型。LLM 侧用 Anthropic 官方 SDK，吃流式和重试。Zod 尤其关键：模型参数不可预测，校验就是第一道闸。启动路径上，性能探针先挂，可并行的预取重叠执行，重量级模块最后加载——五秒才出提示符和半秒响应，用户心理完全不同。

[CODE:async-generator-steps]

主循环每轮大致七步：组请求（系统 Prompt、历史、工具定义）；流式收响应；解析工具调用；过权限校验；执行允许的工具；把结果写回历史；决定继续还是收束。用生成器而不是回调，上层才能 for await 消费整段对话，也能中途打断。跨轮状态用不可变对象整体替换。五个关键模块——入口、QueryEngine、主循环、工具类型、工具注册——层次关系记牢，宏观骨架就立住了。注册中心还是单一事实来源：条件注册、延迟加载、发送前按权限过滤，模型甚至看不见不该用的工具。细节后面几章再拆。

## 块 4｜§1.3 五大原则

架构背后是五条互相支撑的原则。每条都在回答：为什么不选更简单的做法；不这样会怎样。

[ANIM:principle-async]

原则一：异步流式优先，Async Generator First。传统调用是请求—响应：发完 Prompt 干等到整包回来。Agent 不是这样——一轮用户请求里可能多跳工具，思考过程、调用计划、执行进度都要实时给用户看。生成器刚好匹配：用 yield 增量吐事件；调用方可以 return 或 throw 打断；消费者慢了还有背压，避免内存被冲爆。回调易变地狱；Promise 链好看些，但用户按 Ctrl+C 时很难优雅停掉正在飞的请求；事件总线能取消，却容易忘了卸监听。同时要流式、可取消、类型安全——AsyncGenerator 几乎是唯一解。

[ANIM:principle-security]

原则二：安全边界内嵌，Security at the Perimeter。权限不是外挂，是管线正中的检查点。先过滤工具可见性，模型看不见禁用工具；再 validateInput；再 canUseTool 综合模式与危险等级，给出允许、拒绝或询问；执行时还有沙箱、超时、输出大小限制。纵深防御，没有银弹，但每层都能独立短路。白名单不够用：安全性看上下文——删 node_modules 和删 etc，同一个 Bash，风险完全不同。

[ANIM:principle-cache]

原则三：缓存感知，Cache-Aware。Prompt Caching 能砍成本和延迟。系统 Prompt 尽量字节稳定才能命中缓存；Fork 出的子智能体继承父级已渲染的系统 Prompt；已发送消息只追加不改写，缓存键才稳。不关心缓存，每次重拼 Prompt，子智能体重复计费——生产里一天几百次调用，浪费会堆成山。

[ANIM:principle-progressive]

原则四：渐进式能力扩展，Progressive Capability。四级阶梯，从内建到外部：Tool 实现类型接口，给核心开发者加原子能力；Skill 用 Markdown 加脚本做声明式任务模板，适合高级用户；Plugin 带生命周期打包相关工具和配置；MCP 服务器用标准化协议接第三方，Agent 边界可以在运行时被发现和拉开，而不是写死在发布日。简单需求别逼人搭服务器，复杂集成也别逼人改核心。只有 Tool，生态长不大；只留 MCP，小需求门槛又太高。让每类贡献者站在合适抽象层上工作，扩展才可持续。

[ANIM:principle-immutable]

原则五：不可变状态流转，Immutable State Flow。更新走 updater，基于 prev 算 next，减少竞态；引用相等才通知；订阅可清理。对话里跨轮状态整体替换，每轮用只读快照。可变对象在并发和子智能体场景下，容易读到改一半的脏数据，父状态还可能被误改——这类 bug 取决于调度时序，极难复现。不可变，是可预测、可回滚、可安全传快照的底气。

五条连起来：流式解决怎么边跑边展示，安全解决怎么敢让它跑，缓存解决怎么跑得起，扩展解决怎么越跑越强，不可变解决怎么跑得可追溯。后面章节里，你几乎总能把「为什么这样设计」追回其中一条。

## 块 5｜实战练习速览

理论先放这儿。按安装、诊断、一次工具调用，快速建立手感。

[CODE:install-claude]

机器上有 Node 十八加或 Bun，全局安装 Anthropic 的 claude-code 包，再跑 claude 的 version 确认。项目里也可用 npx 或本地安装钉版本，避免互相抢版本。

[CODE:doctor-flow]

进任意项目启动 Claude Code，输入斜杠 doctor。它会查环境、权限配置、MCP 连接、API 连通、文件系统访问。观察方式比结果更重要：检查是一项项冒出来的，不是等全部做完一次性刷屏——这是异步流式优先在日常功能里的样子。有的检查会请求确认，说明诊断也走权限管线。

[ANIM:one-tool-call]

再发一句简单请求，比如列出当前目录所有 TypeScript 文件。看三阶段：思考里说明打算用哪个工具；调用阶段出现工具名和参数，常见是 Glob 配上星号 ts；然后是结果和基于结果的回复。心里对照主循环：哪步在 QueryEngine，哪步过权限，哪步在工具执行。顺带想三问：哪些工具并发安全；按 Ctrl+C 时谁在响应、对应哪条原则；连发很多轮上下文满了怎么办。这三问，后续章节会拆开。

## 块 6｜总结 + 片尾出处

收束四点，也当作本集口诀。

第一，范式已转移：助手从对话伙伴变成自主智能体，引擎是工具调用，地基是 Agent Harness——要的不是一次 API 调用，而是一整套运行时环境。第二，Harness 是复杂工程系统：五十多万行不是吓唬人，流式输出、权限管控、上下文管理、错误恢复、状态持久化、可扩展性，哪个都不省；模型变强不会让这些问题消失，任务越复杂，工程反而越尖锐。第三，五模块搭起骨架：入口、查询引擎、对话循环、工具类型、工具注册；层次是入口创建引擎，引擎驱动循环，循环使用工具，工具由注册中心统一管理。第四，五原则是红线：异步流式优先、安全边界内嵌、缓存感知、渐进式扩展、不可变状态流转。遇到「为什么这样设计」，答案几乎都能追回其中一条。
