# 附录 D：术语与常见误解

<!-- block: kimi-apxd.b-opening -->
术语相近时先看它由谁读取、何时生效、保存在哪里，再判断能否从一个机制推导另一个机制。

## D.1 关键概念

| 术语 | 本书中的含义 |
| --- | --- |
| CLI | 接收终端命令和参数的入口 |
| Agent | 持有角色、上下文与工具能力的执行单元 |
| Skill | 可被发现并加载的工作步骤与辅助材料 |
| 插件 | 组织技能、角色、命令、Hook 和 MCP 等资源的安装单元 |
| Hook | 在生命周期事件发生时启动的本地处理器 |
| MCP | 把服务能力暴露为模型可调用工具的协议 |
| ACP | 客户端驱动 Agent 会话与交互的协议 |
| JSONL | 每行一条 JSON 的记录格式 |
| fail-open | 处理器失败时继续主流程的策略 |
| 工作树 | 当前文件系统中的项目文件状态 |

## D.2 相近机制的差别

Skill 说明怎样做事，工具配置决定可用入口。插件命令保存一段可复用提示词，Hook 则真的启动本地程序。Agent 文件正文可以成为系统提示词，项目说明则提供任务参考材料。

会话恢复接续对话与运行状态，Git 恢复代码版本。会话分叉不会自然复制工作树。`KIMI_CODE_HOME` 改变 Kimi 专用数据位置，也不会自动改变所有通用 `.agents` 资源的位置。

MCP 连接成功只表示服务通信达到相应阶段，Agent 工具允许列表仍会影响可用性。ACP 握手成功只说明双方可以交换初始化消息，后续会话、审批和文件操作各有自己的契约。

## D.3 阅读其他工具教程时

不同产品可能都使用 `AGENTS.md`、Skill 或 `PreToolUse` 这些名称，但目录优先级、字段、权限语义和重载时机会不同。迁移时先保留业务规则，再逐项适配运行时入口。

本系列的 OpenCode、DeepSeek Harness、Hermes、Codex CLI、Pi 和 Omp 分册分别固定自己的版本。可以用它们比较设计取舍，不能把一册的配置直接当作另一册的有效接口。

## D.4 排查前先写下四个事实

程序版本、启动入口、工作目录和当前会话，是理解大多数行为差异的起点。插件问题再补安装版本与生效方式；模型问题再补别名、协议和脱敏错误；客户端问题再补请求与响应。

信息不需要很长，但应能对应具体文件和实际操作。别人按照这些材料复现之后，讨论才会落在同一个问题上。
