CLI 的版本和实际入口决定可用参数；先运行库存案例，可以给后续审查建立可重复的起点。

在终端里看到 `kimi` 可以启动，还不足以确定你用的是本书的程序。同一台机器可能保留旧 Python 安装、npm 包装器和独立可执行文件。PATH 选择的是它找到的第一个入口。

## 1.1 记录真正启动的程序

尚未安装时，可按[钉版入门文档](https://github.com/MoonshotAI/kimi-code/blob/1c142a007c10e881602690def96057c23a2baa12/docs/en/guides/getting-started.md)使用官方安装脚本。Windows 首次启动前还需安装 Git for Windows，Kimi 使用其中的 Git Bash；若安装在自定义位置，将 `KIMI_SHELL_PATH` 指向 `bash.exe` 的绝对路径。

```powershell
irm https://code.kimi.com/kimi-code/install.ps1 | iex
```

macOS 或 Linux 对应的命令是：

```bash
curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash
```

官方脚本下载当前发布版，并不固定安装本书的 2.5.2。安装后重新打开终端，核对实际版本；若需严格复现实验，应使用对应发布版本。在线安装步骤来自固定文档，本次没有重新安装程序。

在 PowerShell 中执行：

```powershell
Get-Command kimi | Select-Object Source
kimi --version
kimi --help
```

本书实测输出为 `2.5.2`。在 macOS 或 Linux 中，用 `command -v kimi` 查询入口。若版本不同，先保留自己的版本记录；不要只因某个参数缺失就改用另一个教程中的名字。

固定源码的包位于 `apps/kimi-code/`，核心引擎位于 `packages/agent-core-v2/`。发布程序与从源码启动的开发环境也有区别：仓库根 `package.json` 声明 Node 至少为 `24.15.0`，而独立发布程序不要求用户手工启动 Node。本书使用本机已安装的 Windows 发布程序，首次在线安装不计入实测。

后文的 `kimi` 都指你刚核对过的入口。如果 PATH 尚未调整，可以使用完整路径。升级后先重跑这三条命令，保留版本与路径，再检查行为变化。

## 1.2 先不调用模型

在书籍仓库根目录运行：

```powershell
python kimi/examples/check_inventory.py
python kimi/examples/check_inventory.py --fixed
python -m unittest discover -s kimi/examples -p "test_*.py" -v
```

第一条命令检查故意保留错误的实现，退出码为 `1` 是预期现象；它应显示 8 个场景中 3 个通过。第二条检查参考实现，8 个场景全部通过。第三条检查业务案例、Hook 输入输出和 MCP 子进程通信，不需要 Kimi 账号。

如果终端中的 `python` 没有输出，先检查 `python --version` 和 `Get-Command python`。Windows 应用执行别名可能与实际 Python 安装不同。明确解释器入口后，再排查书中的程序。

## 1.3 一行比较带来的两种业务结果

练习文件 `inventory.py` 的核心如下：

```python
def reserve(stock: int, quantity: int) -> int:
    if quantity >= stock:
        raise ValueError("insufficient stock")
    return stock - quantity
```

库存 10、预留 10 应当留下 0，但 `>=` 会抛出异常。库存 10、预留 -2 更隐蔽：条件不成立，函数返回 12。两者都不是语法错误，类型注解也不会在运行时自动验证整数范围。

这就是审查任务需要业务规则的原因。没有“允许恰好用尽”的规定，助手只能猜测比较符号的意图；没有“预留量必须为正整数”的规定，测试也没有可靠的预期结果。

| 输入 | 业务预期 | 练习实现 |
| --- | --- | --- |
| `stock=10, quantity=3` | 返回 7 | 返回 7 |
| `stock=10, quantity=10` | 返回 0 | 抛出异常 |
| `stock=10, quantity=11` | 拒绝 | 拒绝 |
| `stock=10, quantity=-2` | 拒绝 | 返回 12 |

检查驱动还包含零、小数、布尔值和负库存。Python 中 `bool` 是 `int` 的子类，所以参考实现用精确类型检查表达本练习的规则。若你的业务允许其他数值类型，应修改规则与测试，而不是照搬这个选择。

## 1.4 把第一次请求写得可检查

准备好第 4 章的副本后，可在交互界面提交：

```text
只读审查 inventory.py。业务规则见 review-plugin/skills/
review-inventory/references/rules.md。先不要读取 inventory_fixed.py。
每条发现说明触发输入、实际行为、预期行为和文件位置。
没有运行的检查请标为静态推演，不要修改文件。
```

这里的“只读”是工作要求，还不是操作系统权限。第 10 章会用 Agent 工具列表落实更具体的限制。首次练习先观察助手有没有正确读取规则，是否把静态推演说成实际执行，以及报告能不能被现有检查复现。

把模型报告与终端结果并排看，比比较回答长短更有用。如果它发现了 `>=` 却漏掉负数，不必立即加长提示词；先检查规则是否进入上下文、输入域是否被讨论。
