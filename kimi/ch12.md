# 第 12 章：Hook 的输入、拒绝与失败放行

<!-- block: kimi-ch12.b-opening -->
Hook 在生命周期事件发生时启动本地程序；明确拒绝会影响可阻断事件，错误和超时则按 fail-open 放行。

现在给审查流程加一道提醒：当模型想调用写入或命令工具时，返回“当前任务只读”。这能让用户看到工作流怎样介入执行，但也必须理解处理器失效时会发生什么。

## 12.1 事件先匹配，再启动处理器

插件清单中的规则监听 `PreToolUse`，matcher 为 `^(Write|Edit|Bash)$`。matcher 是正则表达式，锚点让它只匹配这三个完整名字，避免误把另一个含有相同片段的名称算进去。

宿主通过 stdin 发送 JSON。事件基础字段包括 `hook_event_name`、`session_id`、`cwd` 等，工具事件还包含 `tool_name` 与 `tool_input`。字段采用 snake_case。

随书处理器再次核对事件名与工具名，然后输出：

```json
{
  "hookSpecificOutput": {
    "permissionDecision": "deny",
    "permissionDecisionReason": "This review only reads files; start a separate repair task."
  }
}
```

输出说明了拒绝原因，也给下一步留下明确方向。它没有建议模型换一条等效命令继续写入。

## 12.2 先直接运行处理器

在练习目录中执行：

```powershell
'{"hook_event_name":"PreToolUse","tool_name":"Edit"}' |
    python review-plugin/hooks/review_only.py
```

把 `Edit` 换成 `Read`，输出应为 `{}`；把事件改成 `PostToolUse`，同样不返回拒绝。这个实验验证原创处理器的输入输出，不需要启动 Kimi。

处理器解析失败时退出 `1`。它没有偷偷把所有未知输入都当成拒绝。这与宿主的错误放行语义一致，也让坏输入与业务拒绝在实验结果中可区分。

## 12.3 退出码和结构化输出的优先关系

固定源码 `runHook.ts` 先处理退出码 `2`，将 stderr 作为拒绝原因。只有退出码为 `0` 时，才尝试把 stdout 解析成结构化输出，其中明确的 `permissionDecision: deny` 可以产生阻断。

| 处理器结果 | 执行器判定 |
| --- | --- |
| 退出 0，输出 `{}` | 放行 |
| 退出 0，输出结构化 deny | 阻断 |
| 退出 2 | 阻断，读取 stderr 原因 |
| 退出 1 或其他错误码 | 放行，并保留错误信息 |
| 超时、启动失败 | 放行，并记录失败状态 |

因此，一个程序把 deny JSON 打印出来后又以 `1` 退出，不能只凭 stdout 推断宿主会阻断。退出状态是解释输出的前提。

## 12.4 不是所有事件都能阻断

固定文档将 `PreToolUse`、`Stop` 和 `UserPromptSubmit` 列为可阻断事件。其他事件用于观察，例如 `PostToolUse`、`PermissionResult` 和 `SessionEnd`，它们的返回结果不会按相同方式中断主流程。

在操作完成后发出通知，与在操作之前拒绝执行，是两种不同能力。若用 `PostToolUse` 检查一个已经写入的文件，即使发现问题，也不能把它描述成“阻止了写入”。

用户手动中断会触发 `Interrupt` 的相关路径，不能简单假定所有结束情况都触发 `Stop`。排查事件遗漏时，应先看实际结束原因。

## 12.5 并行与超时会影响设计

多条规则匹配同一事件时，固定实现并行运行匹配 Hook，并对相同命令去重。不要依赖配置列表顺序，让第一个 Hook 生成文件、第二个 Hook 马上读取它；这种隐式依赖不适合并行执行。

超时单位是秒，配置范围为 1—600，默认 30。短小的审查提醒不应该调用慢速外部服务。否则一个偶发网络延迟就会把提醒变成超时放行。

Hook 在运行 Kimi 的机器上执行。即使会话绑定远程环境，它也不是自动迁移到远端项目目录的脚本。插件 Hook 的工作目录又是插件根目录，与普通会话 Hook 的本地项目目录不同。

## 12.6 真实执行器实验

随书实验直接编译钉版 `runHook.ts`，注入本地进程适配器，再启动真实子进程。它验证了普通放行、JSON 拒绝、退出码 2、错误退出、超时和启动失败。结果记录在 `facts/source-probes.json`。

这组结果证明执行器怎样解释处理器结果；事件调度、权限系统和完整模型回合仍属于更大的宿主流程。Hook 失败会放行，所以本书同时使用受限 Agent，而不会将处理器称为安全沙箱。
