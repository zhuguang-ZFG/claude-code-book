# 前言

<!-- block: llm-front.b-opening -->
Agent 工程师每天都会碰到一组看似分散的问题：为什么这段中文按 token 计费比英文贵；为什么同一个提示每次生成的 JSON 略有不同；为什么上下文窗口标着 200K，塞到一半就开始变慢、变贵、漏掉关键信息；为什么 KV cache 会决定并发数；RAG 和 Agent 记忆到底怎么分工。

这些问题的答案不在某一款 Agent 的配置里，而在模型这一层。本书用可以在一台普通笔记本上运行的 nano 尺寸例子，把这些机制拆开：token、embedding、注意力、Transformer、采样、上下文成本、预训练、后训练、推理部署、RAG、工具调用、思维链、评测与蒸馏。全书不训练 SOTA 模型，也不要求 GPU；目标是让 Agent 工程师能读懂模型卡、算清预算、判断一项优化是否值得做。

## 这套书在讲什么

“大模型与智能体工程”系列有几条入口：

- [《御舆：解码 Agent Harness》](../00-前言.md)从对话循环、工具、权限、上下文和记忆讲 Agent 的整体结构；
- [《提示词工程》](../prompt/00-前言.md)讲任务说明、材料组织、工具协作与评测；
- OpenCode、DeepSeek、Hermes、Codex、Kimi、Pi 等分册讲具体 Harness 的实现；
- 本卷回到模型本身，解释 Harness 每天调用、计费和约束的那个对象。

如果你已经会写 prompt、会调 API，但没系统学过 attention 推导，本卷按“机制 + 最小实现 + Agent 工程落点”来写。每章只引入必要的数学，代码尽量限制在 Python 标准库或最小依赖内。

## 怎样读

- **先解决眼前问题**：按上表选一章，先跑示例，再读解释；
- **按原理主线**：第 1–16 章按顺序读，建立从 token 到多模态的完整链路；第 7 章算训练账并用一个 7 440 参数的小模型把反向传播真跑一遍，第 8–9 章讲怎样把基座改成助手，第 10 章算服务端成本，第 11–12 章讲 RAG 与工具协议，第 13 章讲测试时计算，第 14 章讲怎么判断是否变好，第 15 章讲模型怎样看图，第 16 章用来查词；
- **按工程任务**：第 1、6 章处理预算与上下文，第 2、11 章处理检索与语义相似度，第 5、13 章处理采样、投票与稳定性，第 7–9 章处理训练、微调与对齐，第 10–12 章处理部署、RAG 与工具调用，第 14 章处理评测与蒸馏，第 15 章处理截图、UI 与文档识读；
- **只想知道概念**：先读每章开头的场景和末尾的“常见翻车”，再回到中间看机制。

### 一次请求的旅程

把 Agent 的一次请求摊开来看，全书的章节就有了位置：

1. 你说的一句话先被 **tokenizer** 切成 token（[第 1 章](ch01.md)）——计费和窗口从这里开始；
2. token 变成**向量**，语义相似的词在向量空间里靠近（[第 2 章](ch02.md)）；
3. **注意力**让每个位置看见该看的位置，Transformer 一层层堆出表示（[第 3](ch03.md)–[第 4](ch04.md) 章）；
4. **采样器**从概率分布里挑出下一个 token，温度、top-k、top-p 决定这次输出是稳定还是多样（[第 5 章](ch05.md)）；
5. 每次请求都要付**上下文与 KV cache** 的账（[第 6 章](ch06.md)）；训练侧先用一笔算力攒出基座（[第 7 章](ch07.md)），再用 SFT、偏好对齐和拒绝采样把它改成助手（[第 8](ch08.md)–[第 9](ch09.md) 章）；
6. 服务端用 **prefill/decode、批处理、量化与缓存**把这条请求变便宜（[第 10 章](ch10.md)）；
7. 知识不在模型里时先**检索**（[第 11 章](ch11.md)），需要动作时**调用工具**（[第 12 章](ch12.md)），难题多想几步（[第 13 章](ch13.md)）；
8. 最后用**评测**判断它是否真的变好，并决定什么时候交给小模型（[第 14 章](ch14.md)）；看图的任务在最后（[第 15 章](ch15.md)），术语在[第 16 章](ch16.md)查。

一条链走完，每章都回答“这一次请求为此多花了什么”。

### 把旅程算成一张账单

这条链落到一次四轮编码会话上，数字是可以算出来的。`llm/examples/session_ledger.py` 的假设是：system 1,200 token、任务 300 token、检索 3 段共 1,800 token，前三轮各输出 250 token、最后一轮 400 token，每次工具结果 800 token；单价假设为输入每百万 $3、缓存命中每百万 $0.30、输出每百万 $15。四轮下来，模型一共看见 19,500 个输入 token，其中只有 6,450 个（33.1%）是新内容，其余 13,050 个（66.9%）是把上一轮的内容原样再发一遍。

| 策略 | 输入账单 | 总账单 | 相对无缓存 | 模型计算时间 |
| --- | ---: | ---: | ---: | ---: |
| 无缓存 | $0.05850 | $0.07575 | — | 32.75 s |
| 只缓存稳定前缀（system + 文档） | $0.03420 | $0.05145 | −32.1% | 28.25 s |
| 缓存整段前文（历史只追加） | $0.02327 | $0.04052 | −46.5% | 26.23 s |

按这个示例的参数，6,850 token 峰值上下文对应 2.1 GiB 的 KV cache，八路并发为 16.7 GiB。上表还说明，缓存命中的输入仍按假设的缓存读取价格计费，只是费用低于重新处理输入。显存占用与费用需要分别计算，详见[第 6 章](ch06.md)和[第 10 章](ch10.md)。

### 三档阅读路线

| 目标 | 路线 | 读完之后 |
| --- | --- | --- |
| 入门（一两天） | 前言 → 第 1、2、5 章 → 每章末尾“常见翻车” | 能解释计费、相似度、采样波动这三个最常遇到的困惑 |

跨档读法也成立：先按“入门”建立直觉，遇到具体工程问题跳到“进阶”对应章，最后用“精通”几章补上训练与评测的判断力。每章开头是场景，中间是机制与示例，末尾是“常见翻车”和“本章小实验”——三档读者都能在同一章里找到自己的入口。

## 证据边界

书中的技术断言尽量钉到具体版本文档或论文；来源、快照日期和许可登记在 [`yuyu-book/sources-llm.json`](../yuyu-book/sources-llm.json)。GitHub 来源固定到完整 commit，见 [`llm/facts/source-lock.json`](facts/source-lock.json)。

已经实际运行的内容：二十一个示例脚本、构建检查、示例测试，其中 `train_demo.py` 用手写反向传播真训练（梯度检查通过）、`embedding_train_demo.py` 从语料真训出主题聚类、`session_ledger.py` 把四轮会话的 token、账单与 KV cache 算成一张表。尚未进行的内容：真实模型上的采样对比、生产 tokenizer 的跨模型计数、真实预训练/微调/对齐实验、长上下文质量实验、显存与吞吐压测、真实多模态模型的识读对比。这些缺口在正文中标注为练习或待测，不用“通常”“一般认为”替代证据。

生产 tokenizer 的计数与本书玩具 BPE 不同；书中引用 toy token 数时都会标明。厂商的价格、窗口和模型结构会变化，第 6 章的公式和输入参数比具体数字更值得保留。

## 开始

从[第 1 章](ch01.md)开始：先看一段中文怎样变成字节、再变成 token，以及为什么“字数”不能直接当预算。读完后，你会知道下一次该量什么，而不是只记住一个比例。
