# 第 2 章：向量空间里的“像”

<!-- block: llm-ch02.b-opening -->
用户说“钱还没退”，知识库里写的是“退款未到账”。两句话没有几个字重合，检索却应该把它们排在一起。Embedding 把文本映射成向量，方向接近表示语义接近；但“接近”不等于“正确”——否定、反义和领域词都可能骗过余弦相似度。

取几个手设的三维向量，走一遍 embedding 查表、余弦相似度、top-k 检索和一次精确扫描的成本。代码只用标准库。

## 2.1 从 token ID 到向量

[第 1 章](ch01.md)把文本变成了整数 ID。模型的第一层是一张 embedding 表 `E`，形状是 `词表大小 × d_model`；ID 是行号，查表得到这一层的输入向量。这张表是学出来的参数，不是人工编码。

| 配置 | 参数量 | fp16 体积 |
| --- | ---: | ---: |
| 词表 32000，`d_model=4096` | 131 072 000 | 250.0 MiB |
| 词表 32000，`d_model=768` | 24 576 000 | 46.9 MiB |

同一个 token 在表里只有一个向量，但经过注意力和 FFN 之后，它的上下文表示会随句子变化。检索系统用的向量通常来自单独的编码器（encoder），不是 decoder 的输入表；两者维度、训练目标和用途都不同，不能混着比。词向量的早期工作见 [word2vec](https://arxiv.org/abs/1301.3781)，句子级编码与检索的常见做法见 [Sentence-BERT](https://arxiv.org/abs/1908.10084)。

## 2.2 余弦相似度

两个向量的余弦是点积除以模长：

```text
cos(a, b) = (a · b) / (||a|| × ||b||)
```

它只看方向，不看长度，取值在 `[-1, 1]`。`llm/examples/embedding_demo.py` 用一个长度不同的例子说明点积和余弦会给出不同排序：

| 候选 | 点积 | 余弦 |
| --- | ---: | ---: |
| A：与查询同方向的短向量 | 3.000 | 1.000 |
| B：与查询不同方向的长向量 | 6.000 | 0.707 |

```ill
llm-ch02-dot-cosine
```

查询是 `[3.0, 0.0]`；A 是 `[1.0, 0.0]`，B 是 `[2.0, 2.0]`。按点积，B 排第一；按余弦，A 排第一。很多向量索引默认做内积，如果不先归一化，长度会主导排序。要按余弦检索，就在入库和查询时都归一化，或者确认索引的度量方式。

```ill
llm-ch02-vector-space
```

脚本里六个客服意图的三维向量，查询“退款”和“物流”的近邻如下（查询自身已排除）：

| 排名 | “退款”的近邻 | 余弦 | “物流”的近邻 | 余弦 |
| ---: | --- | ---: | --- | ---: |
| 1 | 不退款 | 1.000 | 发货 | 0.889 |
| 2 | 退货 | 0.991 | 换货 | 0.625 |
| 3 | 换货 | 0.827 | 发票 | 0.543 |
| 4 | 发货 | 0.220 | 退货 | 0.217 |

“退款”的第一名是“不退款”，余弦 1.000。脚本没写错：这套玩具几何里，“退款”与“不退款”的向量方向几乎相同，余弦没能把语义否定分开；若极性被编码成相反方向，余弦会给出负值。真实编码器可能在训练中学会区分否定，但不能假设它一定区分；检索结果必须回到文本和业务规则核对。

## 2.3 相似不等于相关

余弦高只说明“方向接近”，不保证“对当前问题有用”。常见的四类偏差：

- **否定与极性**：`退款` 与 `不退款`、`通过` 与 `未通过` 可能共享大量词和语境；
- **反义与对比**：`便宜` 与 `贵`、`成功` 与 `失败` 常出现在相似句式里；
- **多义**：`苹果` 是水果还是公司，要看上下文；切块太短时，向量抓不到区分；
- **领域漂移**：同一个词在客服、法律和代码库里指向不同对象。

所以检索链路很少只做“向量 top-k”。常见组合是：关键词召回（BM25）加向量召回，按来源、时间、权限过滤，再用交叉编码器或 LLM 重排，最后把来源和片段一起交给模型。向量负责“找得像”，重排和规则负责“确实相关”。

高维空间还有一些工程现象：某些向量容易成为“中心”，和谁都接近；不同模型的余弦分布不同，阈值不能跨模型照搬。阈值要在自己的查询集上校准，别直接抄一个 0.8。

回到开头那个问题：“方向接近”本身是哪来的？`llm/examples/embedding_train_demo.py` 用 30 轮 SGD 在 36 句话上真训一个 12 词、16 维的 skip-gram：同主题词共现做正对，跨主题词只做负采样。训练前，“退款”的近邻是随机取向的“换货 +0.39、配送 +0.32”；训练后变成“售后 +0.99、换货 +0.99、退货 +0.98”，12 个词的 top-3 近邻全部落回自己的主题组。2.2 节的几何不是设计出来的巧合，而是“上下文相似的词方向趋同”这条统计规律被梯度下降压进向量的结果；本节的四类偏差也在同一时刻被带进来——共现统计分不清否定与反义，学出来的向量同样分不清。真实编码器是在同一机制上多走了几个数量级的数据。

## 2.4 一个最小检索流程

一条可用的检索链路至少包含：

```text
切块 → 编码 → 建索引 → 查询编码 → 召回 top-k → 过滤/去重 → 重排 → 带来源注入
```

`llm/examples/embedding_demo.py` 还算了两笔账：

- 10 万个 4096 维 fp32 向量，光向量本体约 1.5 GiB，不含索引结构、元数据和副本；
- 一次精确扫描是 409 600 000 次乘加。数据量再大，通常要用近似最近邻索引（如 [HNSW](https://arxiv.org/abs/1603.09320)）在召回率和速度之间取舍。

切块大小、重叠、是否按标题分段，会直接影响召回。块太短，指代和条件被切断；块太长，一个向量要代表多个主题。真实系统还要处理同一文档的多个版本，避免旧版本压过新版本。

## 2.5 维度与参数

Embedding 的参数是 `词表大小 × d_model`；如果输出层与输入嵌入共享（tied），只算一张表，否则输出投影再算一张。维度不是越大越好：检索质量取决于训练数据、领域匹配和切块方式，维度只决定表示空间的上限和存储成本。

对 Agent 来说，还要区分三种“向量”：

1. **decoder 的输入 embedding**：静态查表，进入模型后会被上下文改写；
2. **检索编码器的输出**：专门为相似度训练，通常做归一化；
3. **模型隐藏层的激活**：维度、分布和训练目标都不同，不适合直接拿来当检索向量。

把三者混用，是“离线评测很好、线上召回很差”的常见原因之一。

## 2.6 Agent 工程落点

| 场景 | 用什么 | 注意 |
| --- | --- | --- |
| 工具选择 | 工具描述向量 + 名称/参数关键词 | 工具名和 schema 要结构化，别只靠语义 |
| 知识库 RAG | 切块 + 向量召回 + 重排 | 带来源、版本和时间，处理否定与冲突 |
| 长期记忆 | 向量 + 时间/权限过滤 | 过期条目要淘汰，不能只增不减 |
| 去重 | 余弦 + 校准过的阈值 | 阈值按模型和语料调，不跨模型照搬 |
| 多语言 | 多语编码器 | 跨语相似度要实测，不能假设对齐 |

更完整的 RAG 切块、索引与重排见[第 11 章](ch11.md)；上下文预算见[第 6 章](ch06.md)，token 计数见[第 1 章](ch01.md)。

## 2.7 常见翻车

| 常见翻车 | 后果 | 正确做法 |
| --- | --- | --- |
| 用未归一化向量做内积却以为在算余弦 | 长向量主导排序 | 入库与查询都归一化，或确认索引度量 |
| 余弦高就当成答案正确 | 否定、反义、旧版本混入 | 重排、规则过滤、回到原文核对 |
| 一个阈值走天下 | 换模型或语料后召回崩 | 在自有查询集上校准 |
| 只做向量召回不做重排 | 召回多、精度低 | 混合召回 + 交叉编码器/LLM 重排 |
| 拿 decoder 输入 embedding 当检索向量 | 静态表与上下文表示混淆 | 用专门的检索编码器 |
| 切块不看结构 | 条件、指代、标题被切断 | 按标题/段落切，保留重叠与元数据 |

## 2.8 本章小实验

在仓库根目录运行：

```bash
python llm/examples/embedding_demo.py
python llm/examples/embedding_train_demo.py
```

然后试三组改动：

1. 给 `VECTORS` 增加“换发票”“催发货”，观察查询“退款”和“物流”的 top-k 怎样变化；再故意加一个和“退款”方向几乎相同、含义相反的词，验证余弦能不能区分。
2. 把 A、B 两个候选都归一化，再比较点积排序；你会看到它和余弦排序一致。
3. 把查询换成“不退款”，看它的近邻是不是仍然以“退款”开头；思考真实业务里应该加什么规则或重排特征。

`embedding_train_demo.py` 再试两组：把三个主题句里混进一句两个主题的句子（比如“退款 之后 再 发货”），看跨组近邻怎样被污染；把 `EPOCHS` 调到 60，观察 pair loss 归零后向量挤进窄锥、跨组余弦也升高的过训现象——早停不只是省时间，也在保几何。

第一个示例的向量是手设的，证明的是几何和成本；第二个示例的向量是真训出来的，证明的是“相似度从共现统计里学出来”这条机制本身。接下来把向量送进[注意力](ch03.md)，看位置之间怎样混合；想先看模型卡上的参数账，读[第 4 章](ch04.md)。
