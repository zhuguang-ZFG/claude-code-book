# 第 4 章：一层一层读懂模型卡

<!-- block: llm-ch04.b-opening -->
模型卡写着“7B、32 层、4096 隐藏维、32 头、32000 词表”。采购同学按“7B × 2 字节 = 14 GB”估算显存，部署时却发现权重、KV cache 和激活值加在一起远超一张 24 GB 卡。名字里的“7B”是约数，模型卡上的每个字段都要参与预算。

一个 block 可以拆成两次“归一化—计算—加回”。看清残差流、LayerNorm/RMSNorm、FFN 和 RoPE 各做什么，再用同一套公式核对一张 7B 级配置的参数账。代码只用标准库，不训练模型。

## 4.1 一个 block 做两次加法

现代 decoder 的一个 block 通常写成 pre-norm 形式：

```text
h = Norm(x)
x = x + Attention(h)
h = Norm(x)
x = x + FFN(h)
```

先把输入归一化，再送进注意力或前馈层，算出一个“更新量”，加回原来的 `x`。`x` 这条贯穿所有层的主干叫残差流（residual stream）：每个 block 从里面读一份归一化副本，再往里加自己的更新。层与层之间没有把整个向量替换掉，原始信号有一条直通路径。

```ill
llm-ch04-transformer-block
```

也有 post-norm（先加回再归一化）和其他变体。[LayerNorm 论文](https://arxiv.org/abs/1607.06450) 之后的深堆叠实践里，pre-norm 更容易训练；[pre-LN 分析](https://arxiv.org/abs/2002.04745) 讨论了原因。具体模型用哪一种，要看实现，不能只看“Transformer”三个字。

## 4.2 Norm 在做什么

LayerNorm 对一个向量做去均值和缩放：

```text
LayerNorm(x) = (x - mean(x)) / sqrt(var(x) + eps) * gamma + beta
```

RMSNorm 省掉去均值，只用均方根缩放：

```text
RMSNorm(x) = x / sqrt(mean(x²) + eps) * gamma
```

`llm/examples/transformer_demo.py` 对 `x = [1.0, 2.0, 3.0]` 的输出：

| 操作 | 结果 | 中间量 |
| --- | --- | --- |
| 原向量 | `[1.000, 2.000, 3.000]` | 模长 3.742 |
| RMSNorm | `[0.463, 0.926, 1.389]` | 缩放因子 2.160 |
| LayerNorm | `[-1.225, 0.000, 1.225]` | 均值 2.000，缩放因子 0.816 |

RMSNorm 保留了三项的相对比例，LayerNorm 把均值挪到 0。两者都让进入子层的数值保持稳定尺度；pre-norm 把归一化放在子层之前，残差流本身不被反复缩放。

## 4.3 FFN 与 SwiGLU

注意力负责混合位置，FFN 负责在每个位置上做非线性变换。普通 FFN 是两个矩阵：

```text
FFN(x) = W_down · activation(W_up · x)
```

`d_ff` 常取 `4 × d_model`。SwiGLU 用三个矩阵，多一个门控分支：

```text
FFN(x) = W_down · (Swish(W_gate · x) ⊙ (W_up · x))
```

门控让 `d_ff` 可以取小一些；常见做法是取到约 `8/3 × d_model`，使参数量与 `4d` 的两矩阵 FFN 接近。[GLU Variants](https://arxiv.org/abs/2002.05202) 给出了这类变体的对照。

<!-- block: llm-ch04.b-params -->
脚本按 `d_model = 4096`、32 层、32 头、词表 32000 算出的每层与整模参数：

| 配置 | 每层参数 | 整模参数（tied） | 整模参数（untied） |
| --- | ---: | ---: | ---: |
| SwiGLU，`d_ff=11008` | 202 383 360 | 6 607 339 520 | 6 738 411 520 |
| ReLU，`d_ff=16384` | 201 334 784 | 6 573 785 088 | 6 704 857 088 |

同一配置下，注意力每层 67 108 864，FFN 每层 135 266 304，未共享的词嵌入 262 144 000。SwiGLU 的 FFN 比 ReLU 版略大，但两者整模规模接近；这解释了为什么“7B”可以对应不同的 `d_ff` 与激活函数，却仍然落在同一量级。

词嵌入是否与输出层共享（tied / untied）会差出一整张词表：32000 × 4096 = 131 072 000 个参数。共享时只算一张，不共享时输入嵌入与输出投影各算一张。模型卡若只写“7B”，这些细节都被四舍五入掉了。

## 4.4 RoPE：把位置变成旋转

注意力按内容配对：没有位置信息时，它分不清两个相同 token 谁先谁后，也不知道两个位置隔了多远。因果遮罩限制了“能看见谁”，但没有告诉模型距离。位置信息必须另外注入。RoPE 的做法是把查询和键按位置旋转：

```text
q'_m = R(mθ) · q_m
k'_n = R(nθ) · k_n
```

`R` 是旋转矩阵，`θ` 是一组不同频率的角速度。旋转后的点积只依赖相对偏移 `m - n`，不依赖两个位置的绝对值。脚本用一个二维向量演示（只有一组频率）：

| `m - n` | 点积 |
| ---: | ---: |
| 0 | +1.000 |
| 1 | +0.540 |
| 2 | -0.416 |
| 3 | -0.990 |

真实模型有很多组频率，低频负责长距离、高频负责局部；这也是长上下文扩展（调整 base、NTK、YaRN 等）会改动的地方。[RoFormer](https://arxiv.org/abs/2104.09864) 是 RoPE 的原始论文。具体模型是否用 RoPE、如何缩放，仍要看模型卡和实现。

## 4.5 按模型卡算三笔账

拿到一张卡，至少按顺序算三笔：

1. **权重显存**：参数量 × 每个参数的字节数。fp16 是 2 字节，4-bit 约 0.5 字节（不含量化尺度与对齐开销）。
2. **KV cache**：按[第 3 章](ch03.md)的公式算每 token 字节数，再乘上下文长度与并发数；权重省了，cache 不一定省。
3. **计算量与延迟**：前向每 token 的浮点运算量可粗略按 `2 × 激活参数量` 估算；MoE 要看激活参数，不是总参数。

用上面的 untied 配置举例：6 738 411 520 个参数，fp16 权重约 12.6 GiB；4-bit 约 3.1 GiB，但还要加量化尺度、对齐和运行时缓冲。若用第 3 章的 GQA 配置（32 层、8 个 KV 头、128 维、fp16），128K token 的 KV cache 是 16 GiB。权重加 cache 已超过 28 GiB，还没算激活值和显存碎片；一张 24 GB 卡在 fp16 下装不下这个组合。

这不是某一款真实模型的部署结论。换成真实配置，数字会变；不变的是这条预算关系：模型卡上的参数量只决定权重大小，上下文长度和并发数决定 KV cache，两者要一起算。量化权重也不会自动量化 KV cache；KV cache 的精度是另一项配置。

| 模型卡字段 | 影响 | 常见误读 |
| --- | --- | --- |
| 参数量（total / active） | 权重显存、训练成本 | 把 MoE 的总参数当激活参数 |
| 层数 × `d_model` | 深度、宽度、每层计算量 | 只看总参数，不看形状 |
| 头数 / KV 头数 | 注意力并行度、KV cache | 把 `d_model` 当每头维度 |
| `d_ff` / 激活函数 | FFN 参数与吞吐 | 假设所有模型都是 `4d` ReLU |
| 词表大小 / tied | 嵌入参数、输出层 | 漏掉第二张词表 |
| 上下文长度 | KV cache、prefill 成本 | 把“支持 128K”当“128K 免费” |
| 精度 / 量化 | 权重体积、质量、延迟 | 认为量化只省显存 |

## 4.6 Agent 工程落点

- 选模型先看任务和延迟预算，再看参数量。同一个 7B 级模型，GQA、量化、批处理和服务框架不同，吞吐可能有明显差异。
- 子 Agent 用更小的模型是常见做法：分类、路由、摘要、格式修复不需要主模型的全部分辨率；但要用评测确认质量没有掉到不可接受。
- 窗口翻倍，KV cache 也翻倍；并发再翻倍，显存再翻一倍。先算再开。
- MoE 看激活参数：总参数决定权重显存，激活参数更接近每 token 计算量；两者不要混着比。
- 模型卡只是起点：版本、量化方式、服务端实现都会改变数字；关键决策要用自己的请求压测。

## 4.7 常见翻车

| 常见翻车 | 后果 | 正确做法 |
| --- | --- | --- |
| 把“7B”当精确值 | 权重、显存、成本都算偏 | 用模型卡的确切配置重算 |
| 只算权重不算 KV cache | 长上下文一开就 OOM | 权重 + cache + 激活一起预算 |
| 把总参数当激活参数 | MoE 延迟和吞吐估错 | 区分 total 与 active |
| 以为量化只影响显存 | 质量或延迟出现回退 | 在自己的任务上做量化前后评测 |
| 忽略 tied / 词表 | 参数量少算一整张嵌入 | 核对 tied 与 vocab |
| 把 RoPE 当绝对位置编码 | 误判长上下文外推能力 | 查模型卡的 RoPE 缩放与训练长度 |

## 4.8 本章小实验

在仓库根目录运行：

```bash
python llm/examples/transformer_demo.py
```

然后试三组改动：

1. 把 `X0` 改成 `[0.1, 0.2, 0.3]`，观察 RMSNorm 与 LayerNorm 的缩放差异；再把 `ATTN` 和 `FFN` 都设成零向量，确认残差流原样穿过两个 block。
2. 把 `params` 里的 `d_ff` 从 11008 改成 16384、`swiglu` 改成 `False`，核对整模参数为什么仍然接近；再改 `vocab`，看词表对总数的影响。
3. 把 `rope` 的 `base` 从 10000 改成 100，观察点积随偏移变化得更快；这只演示频率，不代表真实模型的长上下文能力。

这一章只走前向算术，没有反向传播、损失函数和优化器。第 7 章补上预训练的算力账，第 8–9 章讲后训练。想先看采样怎样从模型输出里选 token，读[第 5 章](ch05.md)；想算上下文和 KV cache 的完整预算，读[第 6 章](ch06.md)。
