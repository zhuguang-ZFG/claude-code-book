# 第 4 章：一层一层读懂模型卡

<!-- block: llm-ch04.b-opening -->
一张模型卡写着“7B、32 层、4096 隐藏维、32 头、32000 词表”。按“7B × 2 字节 = 14 GB”只能估算 fp16 权重体积，还不能回答一张 24 GB 卡能否运行它。上下文长度、KV 头数、并发数和运行时缓冲也占显存。本章用一组教学配置把这些账分开算。

一个 block 可以拆成两次“归一化—计算—加回”。看清残差流、LayerNorm/RMSNorm、FFN 和 RoPE 各做什么，再用同一套公式核对一张 7B 级配置的参数账。代码只用标准库，不训练模型。

## 4.1 一个 block 做两次加法

现代 decoder 的一个 block 通常写成 pre-norm 形式：

```text
h = Norm(x)
x = x + Attention(h)
h = Norm(x)
x = x + FFN(h)
```

先把输入归一化，再送进注意力或前馈层，算出一个“更新量”，加回原来的 `x`。`x` 这条贯穿所有层的主干叫残差流（residual stream）：每个 block 从里面读一份归一化副本，再往里加自己的更新。层与层之间没有把整个向量替换掉，原始信号有一条直通路径。

```ill
llm-ch04-transformer-block
```

也有 post-norm（先加回再归一化）和其他变体。[LayerNorm 论文](https://arxiv.org/abs/1607.06450) 之后的深堆叠实践里，pre-norm 更容易训练；[pre-LN 分析](https://arxiv.org/abs/2002.04745) 讨论了原因。具体模型用哪一种，要看实现，不能只看“Transformer”三个字。

## 4.2 Norm 在做什么

LayerNorm 对一个向量做去均值和缩放：

```text
LayerNorm(x) = (x - mean(x)) / sqrt(var(x) + eps) * gamma + beta
```

RMSNorm 省掉去均值，只用均方根缩放：

```text
RMSNorm(x) = x / sqrt(mean(x²) + eps) * gamma
```

`llm/examples/transformer_demo.py` 对 `x = [1.0, 2.0, 3.0]` 的输出：

| 操作 | 结果 | 中间量 |
| --- | --- | --- |
| 原向量 | `[1.000, 2.000, 3.000]` | 模长 3.742 |
| RMSNorm | `[0.463, 0.926, 1.389]` | 缩放因子 2.160 |
| LayerNorm | `[-1.225, 0.000, 1.225]` | 均值 2.000，缩放因子 0.816 |

这个示例把 `gamma` 设为 1、`beta` 设为 0，因此 RMSNorm 保留了三项的相对比例，LayerNorm 的输出均值为 0。真实模型还会应用学到的缩放或偏移，输出不必继续满足这两个性质。pre-norm 把归一化放在子层之前，残差流本身不在这一步被缩放。

## 4.3 FFN 与 SwiGLU

注意力负责混合位置，FFN 负责在每个位置上做非线性变换。普通 FFN 是两个矩阵：

```text
FFN(x) = W_down · activation(W_up · x)
```

`d_ff` 常取 `4 × d_model`。SwiGLU 用三个矩阵，多一个门控分支：

```text
FFN(x) = W_down · (Swish(W_gate · x) ⊙ (W_up · x))
```

门控让 `d_ff` 可以取小一些；常见做法是取到约 `8/3 × d_model`，使参数量与 `4d` 的两矩阵 FFN 接近。[GLU Variants](https://arxiv.org/abs/2002.05202) 给出了这类变体的对照。

<!-- block: llm-ch04.b-params -->
脚本按 `d_model = 4096`、32 层、32 个查询头与 32 个 KV 头、词表 32000 估算参数。这里用标准多头注意力，计入每层两个 Norm 的缩放参数，省略偏置与末尾 Norm；表中的整数是这份简化账目的精确和，不是某个真实 checkpoint 的逐项统计：

| 配置 | 每层参数 | 整模参数（tied） | 整模参数（untied） |
| --- | ---: | ---: | ---: |
| SwiGLU，`d_ff=11008` | 202 383 360 | 6 607 339 520 | 6 738 411 520 |
| ReLU，`d_ff=16384` | 201 334 784 | 6 573 785 088 | 6 704 857 088 |

同一配置下，注意力每层 67 108 864，FFN 每层 135 266 304，未共享的词嵌入 262 144 000。SwiGLU 的 FFN 比 ReLU 版略大，但两者整模规模接近；这解释了为什么“7B”可以对应不同的 `d_ff` 与激活函数，却仍然落在同一量级。

词嵌入是否与输出层共享（tied / untied）会差出一整张词表：32000 × 4096 = 131 072 000 个参数。共享时只算一张，不共享时输入嵌入与输出投影各算一张。模型卡若只写“7B”，这些细节都被四舍五入掉了。

## 4.4 RoPE：把位置变成旋转

注意力中的查询与键携带内容信息。因果遮罩规定当前位置能看哪些位置；要显式表示位置间的距离，还可以使用位置编码。RoPE 按位置旋转查询和键：

```text
q'_m = R(mθ) · q_m
k'_n = R(nθ) · k_n
```

`R` 是旋转矩阵，`θ` 是一组角频率。旋转后的点积可以写成：

```text
q'_m · k'_n = q_mᵀ R((n - m)θ) k_n
```

固定未旋转的 `q_m` 和 `k_n` 时，位置通过相对偏移进入这个式子；把两个位置同时平移相同距离，点积不变。内容向量仍参与计算，且在真实模型里会随上下文变化，因此不能说注意力分数“只由距离决定”。

也可以把每对坐标 `(x_{2i}, x_{2i+1})` 当成复平面上的一点：位置为 `m` 时，旋转就是乘以 `e^{imθ_i}`。不同坐标对使用不同的角频率。脚本先用固定的二维查询与键演示，只有一组频率：

| `m - n` | 点积 |
| ---: | ---: |
| 0 | +1.000 |
| 1 | +0.540 |
| 2 | -0.416 |
| 3 | -0.990 |

通常第 `i` 对坐标的角频率为 `θ_i = base^(-2i/d)`，其中 `i = 0, …, d/2 - 1`，`d` 是参与旋转的维度。高频随位置转得快，低频转得慢；这有助于理解不同距离尺度，但不能据此把语义任务固定分给某几维。调大 `base` 会降低 `i > 0` 的频率，`i = 0` 的频率仍为 1。只有两个维度时恰好只有这一对，改变 `base` 不会改变结果。

长上下文方法会调整这些位置关系，做法和训练条件各不相同：

| 方法 | 调整什么 |
| --- | --- |
| [位置插值（PI）](https://arxiv.org/abs/2306.15595) | 按比例缩小位置索引，将长序列映射进原有位置范围 |
| NTK-aware 缩放 | 调整 base，使不同频段的伸缩程度不同 |
| [YaRN](https://arxiv.org/abs/2309.00071) | 按频段混合插值与外推，并调整注意力缩放 |

PI 原论文的扩展结果包含微调，不能理解为任意模型改一个参数就能获得同样效果。NTK-aware 要区分具体变体，动态变体还会随序列长度调整频率；核对时需要原训练长度和缩放因子。YaRN 则还需确认频段参数、注意力缩放，以及 checkpoint 是否经过相应的长上下文训练。

[Transformers 的固定版本实现](https://github.com/huggingface/transformers/blob/47b0e478f324b54f177ea7998a0791870fdd0324/src/transformers/modeling_rope_utils.py)分别计算线性、动态 NTK 和 YaRN 的频率；YaRN 还返回注意力缩放因子。配置中能选择这些算法，只说明实现提供了计算路径，不能证明未经训练的 checkpoint 在更长输入上仍然可靠。

使用时应分别记录模型的训练长度、推理允许的长度和经过评测的有效长度。若扩展过程包含微调，模型权重也会更新；不能把这些方案统称为“只动位置、不动权重”。[RoFormer](https://arxiv.org/abs/2104.09864) 给出了 RoPE 的推导，[频段分析](https://arxiv.org/abs/2310.05209)可作进一步阅读；具体缩放和效果仍以所用模型及实现为准。

## 4.5 按模型卡算三笔账

拿到一张卡，至少按顺序算三笔：

1. **权重显存**：参数量 × 每个参数的字节数。fp16 是 2 字节，4-bit 约 0.5 字节（不含量化尺度与对齐开销）。
2. **KV cache**：按[第 3 章](ch03.md)的公式算每 token 字节数，再乘上下文长度与并发数；权重省了，cache 不一定省。
3. **计算量与延迟**：稠密投影与 FFN 的主要矩阵运算，可按每 token 约 `2 × 参与矩阵乘法的权重参数量` 估算 FLOPs。这个近似不包括随上下文长度变化的注意力计算，也不能直接换算成延迟；MoE 还要区分总参数与激活参数。

用上面的 untied 配置举例：6 738 411 520 个参数，fp16 权重约 12.6 GiB；4-bit 约 3.1 GiB，但还要加量化尺度、对齐和运行时缓冲。同一配置有 32 个 KV 头，每头 128 维；单条 128K（131 072）token 序列的 fp16 KV cache 为 `2 × 32 层 × 32 头 × 128 维 × 2 字节 × 131 072 = 64 GiB`。权重加 cache 约 76.6 GiB，尚未计入其他开销。

第 3 章的 GQA 示例只有 8 个 KV 头，在其余 cache 条件相同时占 16 GiB。但换成 GQA 也会改变 K、V 投影的参数量，不能继续把上表的多头注意力参数总数当作新模型的精确值。比较两张模型卡时，要连同头数一起重算。

这些是教学配置的预算值。真实部署还要检查缓存精度、分片、滑动窗口和实际保留的 token 数。对这里的全注意力缓存，层数、KV 头数、每头维度、长度、并发数与每元素字节数共同决定体积。量化权重也不会自动量化 KV cache；两者是不同的配置。

MoE 的“参数量（total / active）”需要另算。在常见的稀疏 MoE 层里，路由器为每个 token 选择 top-k 个专家 FFN，再合并它们的输出；不同 token 可以选中不同专家，所以一个批次可能用到很多专家。[稀疏门控 MoE 论文](https://arxiv.org/abs/1701.06538)介绍了这种结构，[Mixtral 的固定版本实现](https://github.com/huggingface/transformers/blob/47b0e478f324b54f177ea7998a0791870fdd0324/src/transformers/models/mixtral/modeling_mixtral.py)可以看到路由、选择与加权合并的步骤。

总参数用于估算完整权重的存储量。若全部权重以同一精度驻留 GPU，显存预算就要包含所有专家；也可以跨设备分片，或把部分权重卸载到 CPU、磁盘，代价是数据搬运和调度开销。[Accelerate 的大模型推理文档](https://huggingface.co/docs/accelerate/v1.11.0/en/concept_guides/big_model_inference)说明了这种卸载过程。总参数不等于每张卡必须常驻的参数量。

激活参数更适合估算单个 token 经过的主要权重计算，还需核对统计是否包含共享层与共享专家。假设模型总参为 600B、每 token 激活 6B，前者用于估算完整权重存储，后者用于近似主要矩阵计算量；不能据此保证它和 6B 稠密模型一样快。延迟还受显存带宽、专家间通信、批大小和负载分布影响。训练时若路由长期偏向少数专家，其他专家获得的训练样本会减少；负载均衡辅助损失是常见的缓解方法。

| 模型卡字段 | 影响 | 常见误读 |
| --- | --- | --- |
| 参数量（total / active） | 完整权重存储、每 token 主要计算量 | 把激活参数直接当延迟，或当全部权重体积 |
| 层数 × `d_model` | 深度、宽度、每层计算量 | 只看总参数，不看形状 |
| 头数 / KV 头数 | 注意力并行度、KV cache | 把 `d_model` 当每头维度 |
| `d_ff` / 激活函数 | FFN 参数与吞吐 | 假设所有模型都是 `4d` ReLU |
| 词表大小 / tied | 嵌入参数、输出层 | 漏掉第二张词表 |
| 上下文长度 | KV cache、prefill 成本 | 把“支持 128K”当“128K 免费” |
| 精度 / 量化 | 权重体积、质量、延迟 | 认为量化只省显存 |

## 4.6 Agent 工程落点

- 选模型先看任务和延迟预算，再看参数量。同一个 7B 级模型，GQA、量化、批处理和服务框架不同，吞吐可能有明显差异。
- 子 Agent 用更小的模型是常见做法：分类、路由、摘要、格式修复不需要主模型的全部分辨率；但要用评测确认质量没有掉到不可接受。
- 全注意力、固定缓存精度下，实际缓存 token 数翻倍，KV cache 也翻倍；并发序列再翻倍，缓存预算还要翻倍。权重体积不会因此翻倍。
- MoE 分开看总参数和激活参数：前者用于权重存储预算，后者辅助估算每 token 的主要计算量，延迟要在目标硬件上测。
- 模型卡只是起点：版本、量化方式、服务端实现都会改变数字；关键决策要用自己的请求压测。

## 4.7 常见翻车

| 常见翻车 | 后果 | 正确做法 |
| --- | --- | --- |
| 把“7B”当精确值 | 权重、显存、成本都算偏 | 用模型卡的确切配置重算 |
| 只算权重不算 KV cache | 长上下文一开就 OOM | 权重 + cache + 激活一起预算 |
| 把总参数当激活参数 | MoE 延迟和吞吐估错 | 区分 total 与 active |
| 以为量化只影响显存 | 质量或延迟出现回退 | 在自己的任务上做量化前后评测 |
| 忽略 tied / 词表 | 参数量少算一整张嵌入 | 核对 tied 与 vocab |
| 调大 RoPE 范围就当作质量保证 | 长输入能运行，却可能答错 | 核对训练长度、缩放方案与长输入评测 |

## 4.8 本章小实验

在仓库根目录运行：

```bash
python llm/examples/transformer_demo.py
```

然后试三组改动：

1. 把 `X0` 改成 `[0.1, 0.2, 0.3]`，观察 RMSNorm 与 LayerNorm 的缩放差异；再把 `ATTN` 和 `FFN` 都设成零向量，确认残差流原样穿过两个 block。
2. 把 `params` 里的 `d_ff` 从 11008 改成 16384、`swiglu` 改成 `False`，核对整模参数为什么仍然接近；再改 `vocab`，看词表对总数的影响。
3. 先看二维例子：它只有 `i=0` 这一对坐标，改 `base` 后结果应当不变。脚本接着使用 `[1.0, 0.0, 1.0, 0.0]`，在偏移 10 时比较 `base=10000` 与 `base=100`：第二对坐标的旋转角从 0.1 变为 1.0 弧度，点积分别约为 `+0.156` 和 `-0.299`。再把查询和键的位置同时加 7，检查同一 base 下的点积保持不变。这些算术检查不能证明真实模型的长上下文质量。

这一章只走前向算术，没有反向传播、损失函数和优化器。第 7 章补上预训练的算力账，第 8–9 章讲后训练。想先看采样怎样从模型输出里选 token，读[第 5 章](ch05.md)；想算上下文和 KV cache 的完整预算，读[第 6 章](ch06.md)。
