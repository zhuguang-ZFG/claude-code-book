> **白话先看懂**：Transformer 可以看成很多层重复的加工站。每层先汇总前文，再单独加工，然后把结果加回原信息。Norm 防止数值失控，RoPE 告诉模型词的位置，MoE 让每个 token 只调用少数专家。读模型卡时，先看层数、宽度、头数和显存，不必先背公式。

一张模型卡写着“7B、32 层、4096 隐藏维、32 头、32000 词表”。按“7B × 2 字节”只能粗估 fp16 权重为 14 GB（约 `13.0 GiB`；若按下文 6.74B 实际参数算是 `12.6 GiB`），还不能回答一张 24 GB 卡能否运行它。上下文长度、KV 头数、并发数、激活函数、是否共享词表和运行时缓冲也占显存。本章用一组教学配置把这些账分开算。

一个 block 可以拆成两次“归一化—计算—加回”。看清残差流、LayerNorm/RMSNorm、FFN/SwiGLU、RoPE 和 MoE 各做什么，再用同一套公式核对一张 7B 级配置的参数与显存账。代码只用标准库，不训练模型。

## 4.1 一个 block 做两次加法

可以把**残差流（residual stream）**想成一条从一楼直通顶楼的“主传送带”，token 的笔记一直摊在上面。每经过一栋楼里的一层（block），只顺手做两次“拿出来抄一份、贴回增补量”的操作：先集合前文线索（Attention），再独自消化加工（FFN），原本就在传送带上的信息原封不动往下传，因此不会越过层数越算丢。

现代 decoder 的一个 block 通常写成 pre-norm（Pre-LN）形式，下面以两行等价计算拆开每一步：

```text
h = Norm(x)
x = x + Attention(h)
h = Norm(x)
x = x + FFN(h)
```

先把输入归一化，再送进注意力或前馈层，算出一个“更新量”，加回原来的 `x`。`x` 这条贯穿所有层的主干叫残差流（residual stream）：每个 block 从里面读一份归一化副本，再往里加自己的更新。原始 `x` 始终保留，子层只叠加更新。

```ill

```

也有 post-norm（`x' = Norm(x + 子层(x))`）和其他变体。[LayerNorm 论文](https://arxiv.org/abs/1607.06450)之后的深堆叠实践里，pre-norm 在初始化阶段梯度尺度更平稳，不必强依赖精密的 warmup 调参；[pre-LN 分析](https://arxiv.org/abs/2002.04745)讨论了原因。正因为 pre-norm 的残差主干本身在 block 之间不做归一化，其范数会随层数累积（如后文小实验里的 `norm: 3.742 -> 3.850 -> 4.030`），真实模型在全部 `L` 个 block 堆叠之后、送入输出投影 `lm_head` 之前，必须再接一层**末尾 Norm（Final Norm）**，如 [Llama 实现](https://github.com/huggingface/transformers/blob/47b0e478f324b54f177ea7998a0791870fdd0324/src/transformers/models/llama/modeling_llama.py) 的 `self.norm` 和 [nanoGPT](https://github.com/karpathy/nanoGPT/blob/3adf61e154c3fe3fca428ad6bc3818b27a3b8291/model.py) 的 `ln_f`。

## 4.2 Norm 在做什么

信号连过几十层矩阵乘法，数值可能越传越大，也可能越传越小。**Norm（归一化）**把向量拉回稳定刻度，避免数值大的维度压过其他维度。`LayerNorm` 先减平均值再按标准差缩放；`RMSNorm` 省掉去均值，只按均方根缩放，许多现代开源 decoder 采用这种更简单的形式。

> **选读**：Norm 的公式可以跳过。先记住它把数值拉回稳定范围；LayerNorm 多一步去均值，RMSNorm 更简单。

LayerNorm 对单个样本的隐藏向量做去均值和按标准差缩放：

```text
LayerNorm(x) = (x - mean(x)) / sqrt(var(x) + eps) * gamma + beta
```

[RMSNorm 论文](https://arxiv.org/abs/1910.07467)指出，Transformer 里归一化真正关键的是尺度不变性而非均值重中心化，因此 RMSNorm 省掉去均值，只按均方根（RMS）缩放：

```text
RMSNorm(x) = x / sqrt(mean(x²) + eps) * gamma
```

`llm/examples/transformer_demo.py` 对 `x = [1.0, 2.0, 3.0]` 的输出（取 `gamma = 1`、`beta = 0`）：

| 操作 | 结果 | 中间量 |
| --- | --- | --- |
| 原向量 | `[1.000, 2.000, 3.000]` | 模长 3.742 |
| RMSNorm | `[0.463, 0.926, 1.389]` | 缩放因子 2.160 |
| LayerNorm | `[-1.225, 0.000, 1.225]` | 均值 2.000，缩放因子 0.816 |

RMSNorm 省掉均值统计并保留了三项的正比关系，LayerNorm 的输出均值严格为 0；式中的 `+ eps` 是实现时防全零除零的数值稳定项（原论文 Eq. (4) 略去该项，Llama 默认取 `eps = 1e-6`）。

把输入整体乘 0.1 时，因为 `eps` 很小，两条 Norm 的输出向量几乎不变，同比例缩小 10 倍的是缩放因子（`2.160 -> 0.216`）。真实模型还会乘上可学习的 `gamma`（以及 LayerNorm 的 `beta`），输出不必保持单位方差或零均值；半精度训练/推理中，主流实现（如 Llama/Qwen2）会先把隐藏向量转成 `float32` 计算平方均值并开方，乘上权重后再转回低精度，以免低精度下求平方和溢出或失真。

## 4.3 FFN 与 SwiGLU

如果说注意力是“全班同学互相交换笔记”，那 **FFN（前馈网络）** 就是“每个同学回到座位上独立消化笔记”：先把向量放大到一个更宽的草稿空间（`d_ff`），做一次非线性筛选，再压缩回原来的宽度。现代模型常用的 **SwiGLU** 增加一条门控分支：一边算内容，一边算每个维度该放行多少，两支逐维相乘。

注意力负责混合位置，FFN 负责在每个位置上做非线性变换。普通两矩阵 FFN 写成：

```text
FFN(x) = W_down · activation(W_up · x)
```

其中 `d_ff` 常取 `4 × d_model`。早期编码器与 GPT 系列模型卡（如 GPT-2、nanoGPT 与 [LLMs-from-scratch 第 4 章](https://github.com/rasbt/LLMs-from-scratch/blob/22c637fdf9aa2f5fdd39c2cc80c1d36b4ab7d8d8/ch04/01_main-chapter-code/ch04.ipynb)）在这个两矩阵结构里常使用 `ReLU` 或 `GELU`（`hidden_act` 为 `"gelu"` 或 `"gelu_new"`），两者不改变 `2 × d_model × d_ff` 的参数矩阵形状。现代主流开源 decoder 则多采用三矩阵 **SwiGLU**，增加一条门控分支：

```text
FFN(x) = W_down · (Swish(W_gate · x) ⊙ (W_up · x))
```

式子中 `Swish(W_gate · x)` 那一支就是门，`⊙` 表示逐维相乘：门算出的数决定对应维度放行多少。其中 `Swish(x) = x · σ(x)`（取系数 `β = 1`，即 PyTorch 与模型配置中的 `hidden_act: "silu"`）。门控引入了第三个投影矩阵，`d_ff` 常缩到约 `8/3 × d_model` 使参数总量与 `4d` 两矩阵接近；为对齐硬件分块（例如 `256` 的整数倍），`4096 × 8/3 ≈ 10 923` 常向上圆整到 `43 × 256 = 11 008`。[GLU Variants](https://arxiv.org/abs/2002.05202) 系统对比了不同门控变体。

| 配置 | 每层参数 | 整模参数（tied） | 整模参数（untied） |
| --- | ---: | ---: | ---: |
| SwiGLU，`d_ff=11008` | 202 383 360 | 6 607 339 520 | 6 738 411 520 |
| ReLU，`d_ff=16384` | 201 334 784 | 6 573 785 088 | 6 704 857 088 |

以第一行 **SwiGLU（`d_ff = 11008`）** 为例，每层注意力为 `4 × 4096² = 67 108 864`，FFN 为 `3 × 4096 × 11008 = 135 266 304`，两个 Norm 为 `8 192`；第二行 **ReLU / GELU（`d_ff = 16384`）** 的 FFN 为 `2 × 4096 × 16384 = 134 217 728`，两组配置整模规模几乎相等。对照 [Llama 配置](https://github.com/huggingface/transformers/blob/47b0e478f324b54f177ea7998a0791870fdd0324/src/transformers/models/llama/configuration_llama.py)的 7B 默认值，加上 `Final Norm` 的 `4 096` 个参数后，untied 总参数为 `6 738 415 616`；若再把 32 个 KV 头改为 GQA-8，每层注意力会从 `67 108 864` 降到 `41 943 040`（32 层共减少约 `0.81B`）。同为 RoPE + RMSNorm + SwiGLU，[Qwen2 实现](https://github.com/huggingface/transformers/blob/47b0e478f324b54f177ea7998a0791870fdd0324/src/transformers/models/qwen2/modeling_qwen2.py)还保留了 `q_proj`、`k_proj`、`v_proj` 的线性偏置及可选滑动窗口，核算真实权重前必须读对应配置文件。

词嵌入是否与输出层共享（tied / untied）会差出一整张词表：`32000 × 4096 = 131 072 000` 个参数（未共享两张合计 `262 144 000`）。可以用 `params()` 直接对照不同模型卡开关：

```python
from llm.examples.transformer_demo import params

base = params(4096, 32, 32, 11008, 32000, swiglu=True, tied=False, final_norm=True)
gqa = params(4096, 32, 32, 11008, 32000, swiglu=True, tied=False, kv_heads=8, final_norm=True)
print(base["total"], gqa["attention"], gqa["total"])
# 6738415616 41943040 5933109248
```

## 4.4 RoPE：把位置变成旋转

只靠第 3 章的注意力算点积，有一个隐藏麻烦：如果不做任何位置标记，“狗咬人”和“人咬狗”在注意力眼里只是同一袋词。要把“这两个词隔了多远”写进注意力，一种办法是按位置把查询和键各转过一个角度，位置越靠后转得越多；两个词一起往后挪相同距离时，它们之间的夹角不变。**RoPE（旋转位置编码）**用的就是这个办法：把每个词的查询、键向量当成表盘上的指针，第 1 个词转 1 格，第 2 个词转 2 格，第 `m` 个词转 `m` 格。两根指针做点积时，真正起作用的是它们之间的**夹角差 `n - m`**——不管“猫追老鼠”出现在文章第 5 行还是第 500 行，这两个词隔着的相对距离永远是一样的。

> **选读**：RoPE 的推导只在核对实现时读。先记住“它用旋转后的夹角差表示相对位置”。

因果遮罩规定当前位置能看哪些历史位置；要显式表示相对距离，现代模型普遍使用旋转位置编码（RoPE）。RoPE 在**每个注意力头内部**按位置索引旋转查询和键向量：

```text
q'_m = R(mθ) · q_m
k'_n = R(nθ) · k_n
```

由于旋转矩阵正交，`R(mθ)ᵀ = R(-mθ)`，且旋转叠加满足 `R(-mθ) R(nθ) = R((n - m)θ)`，因此旋转后的点积自动折叠为相对偏移：

```text
q'_m · k'_n = (R(mθ) q_m)ᵀ (R(nθ) k_n) = q_mᵀ R(mθ)ᵀ R(nθ) k_n = q_mᵀ R((n - m)θ) k_n
```

固定未旋转的 `q_m` 与 `k_n` 时，只同时把 `m` 和 `n` 平移 `+Δ`，差值 `n - m` 与点积都严格保持不变；当 `q_m = k_n`（如下表）时，点积只依赖绝对距离 `|m - n|`，而当 `q ≠ k` 时偏移正负会改变旋转方向。且内容向量自身参与点积并在真实网络里随前文变化，因此不能说注意力分数“只由距离决定”。

```ill
llm-ch04-rope-rotation
```

把头内维度两两配对成复平面上的点时，位置 `m` 的二维旋转等价于乘以 `e^{imθ_i}`。脚本先用固定二维向量 `[1.0, 0.0]` 演示单一频率下的点积变化：

| `m - n` | 点积 |
| :--- | ---: |
| 0 | +1.000 |
| 1 | +0.540 |
| 2 | -0.416 |
| 3 | -0.990 |

这里的 `d_rot` 是**单个注意力头的旋转宽度**（通常等于 `head_dim = d_model / heads`，如 7B 里为 `128` 维、共 `64` 对坐标；若配置 `partial_rotary_factor < 1`，则是其旋转子集），**不是**残差流总宽度 `d_model = 4096`。`i = 0` 的最高频率恒为 `base^0 = 1`，`i > 0` 频率随 `base` 增大而衰减，不同坐标对以不同转速编码位置尺度；但这不意味着可以把某几对坐标固定指派给某种语义角色。

工程核对还要留意**配对布局差异**：[RoFormer 原论文](https://arxiv.org/abs/2104.09864)与本脚本的 `rope()` 按相邻坐标 `(2i, 2i+1)` 旋转；而 [Llama 实现](https://github.com/huggingface/transformers/blob/47b0e478f324b54f177ea7998a0791870fdd0324/src/transformers/models/llama/modeling_llama.py) 与 Qwen2/Mixtral 的 `rotate_half` 把每个头拆成前半 `x[:d_rot/2]` 与后半 `x[d_rot/2:]` 配对 `(i, i + d_rot/2)`。两者在权重行同步重排后数学完全等价，但若对同一批未重排权重混用两种配对方式，分数会立即算错（脚本输出显示同组 4D 向量重排对齐为 `-1.082`，混用误得 `+0.193`）。

长上下文扩展方法会调整这些角频率，常见配置可分为三类（部分新模型如 Llama-3 / Qwen2 也会直接在训练阶段将 `rope_theta` 调高至 `500 000` 或 `1 000 000`）：

| 方法 | 调整什么 |
| --- | --- |
| [位置插值（PI）](https://arxiv.org/abs/2306.15595) | 按比例缩小位置索引（等价整体除以频率缩放因子），压缩进原位置范围 |
| [NTK-aware 缩放](https://arxiv.org/abs/2309.00071) | 按维度指数抬高 `base`（`b' = b · s^(d_rot/(d_rot-2))`），保留高频细节、主要压缩低频 |
| [YaRN](https://arxiv.org/abs/2309.00071) | 按频段阈值混合插值与外推，并调整注意力温度缩放因子 |

也就是说，配置里启用扩展算法或调大窗口，不代表未经微调的 checkpoint 在更长输入上仍有质量；读模型卡时要分开记预训练长度、扩展后配置上限和实测有效长度。

## 4.5 按模型卡算三笔账

> **先看三笔账**：权重装不装得下、KV cache 有多少、算一个 token 要多少计算。模型卡其他字段都围绕这三笔账。

拿到一张模型卡，至少按顺序算清三笔预算：

1. **权重显存**：参数量 × 每参数字节数。fp16/bf16 为 2 字节，4-bit 约 0.5 字节（尚未计入分组量化尺度、零点与内存对齐开销）。
2. **KV cache**：按[第 3 章](ch03.md)的公式算出每 token 字节数，再乘实际保留的上下文长度与并发序列数；权重压缩了，KV cache 不一定同步缩小。
3. **计算量与延迟**：稠密投影与 FFN 的主要矩阵乘法可按每 token 约 `2 × 参与矩阵乘法的参数量` 估算 FLOPs。注意：输入侧 `embed_tokens` 只是按编号抽屉拿一行出来，不算矩阵乘法，不计入该 `2×` 算术项；而输出侧 `lm_head` 在生成每个 token 时都要拿当前状态乘一遍整张大词表给几万个候选打分，无论词表权重是否 `tied` 都会贡献 `2 × d_model × vocab` FLOPs，一次也省不掉。该近似也不包含随序列长度平方增长的注意力分数计算，更不能直接等同于延迟。

沿用上面的 7B untied 配置（`6 738 411 520` 教学口径，与加 `Final Norm` 后几乎无异）：fp16 权重按二进制计算为 `12.55 GiB`（十进制约 `13.48 GB`），4-bit 约 `3.14 GiB` 再加量化元数据。若配备 32 个 KV 头、每头 128 维，单条 128K（`131 072` token）序列的 fp16 KV cache 就达 `2 × 32 × 32 × 128 × 2 × 131 072 = 64.00 GiB`——总计 `76.55 GiB`，远远超出 24 GB 单卡；而换成第 3 章的 GQA-8（且同样省略滑窗与量化），128K KV cache 降为 `16.00 GiB`，同时每层 K、V 投影也随之减重。部署评估仍须核查真实 KV 精度、张量并行分片、滑动窗口层与异步预留缓冲。

普通稠密模型每读一个字都要动用全脑参数；**MoE（混合专家）**则更像一家专科医院：院里养着很多位专科医生（**total 总参数**决定了医院要装多大房间、占多少显存），但每个词进来时分诊台只挂其中一两位对口专家的号（**active 激活参数**决定了算这一个词要花多少力气）。

稀疏混合专家（MoE）模型则必须在模型卡上拆开读 **total（总参数）** 与 **active（激活参数）**：路由器为每个 token 选出 `top-k` 个专家 FFN 加权合并，不同 token 可命中不同专家，一个大 batch 仍可能扫过全部专家。[稀疏门控 MoE](https://arxiv.org/abs/1701.06538) 早期论文采用加噪声门控（先向路由 logits 加可调高斯噪声、执行 `KeepTopK`，再做 `softmax`），而 [Mixtral 实现](https://github.com/huggingface/transformers/blob/47b0e478f324b54f177ea7998a0791870fdd0324/src/transformers/models/mixtral/modeling_mixtral.py) 先对全部本地专家做 `softmax` 再选 `topk` 并重新归一化权重，训练阶段辅以负载均衡损失防止路由器长期偏斜到少数专家；另有架构会在稀疏专家外额外常驻共享专家（shared experts）。

估算显存和吞吐时，总参数用于衡量全精度常驻权重或跨卡分片/卸载体积（参见 [Accelerate 大模型加载文档](https://huggingface.co/docs/accelerate/v1.11.0/en/concept_guides/big_model_inference)），激活参数更接近单个 token 的主流矩阵乘计算量；但一个 “600B total / 6B active” 的 MoE 并不保证和 6B 稠密模型同速，因为权重读取带宽、专家 all-to-all 通信、批大小和路由倾斜都可能成为瓶颈。

| 模型卡字段 | 影响 | 常见误读 |
| --- | --- | --- |
| 参数量（total / active） | 完整权重存储、每 token 主要计算量 | 把激活参数直接当延迟，或当全部权重体积 |
| 层数 × `d_model` | 深度、宽度、每层计算量 | 只看总参数，不看形状 |
| 头数 / KV 头数 | 并行度、KV cache 与 K/V 投影 | 把 `d_model` 当每头维度 |
| `d_ff` / 激活函数 | FFN 矩阵数、对齐宽度与吞吐 | 假设所有模型都是 `4d` ReLU |
| 词表大小 / tied | 嵌入存储与 `lm_head` 输出计算 | 漏掉第二张词表或混淆 `lm_head` FLOPs |
| 上下文长度 / `rope_theta` | KV cache、prefill 成本、频率基底 | 把“配置支持 128K”当“128K 免费且高准” |
| 精度 / 量化 | 权重体积、数值精度、访存延迟 | 认为权重量化会自动量化 KV cache |

## 4.6 Agent 工程落点

- 选模型先看任务和延迟预算，再看参数量。同一个 7B 级模型，GQA、量化、批处理和服务框架不同，吞吐可能有明显差异。
- 子 Agent 可先用更小的模型试分类、路由、摘要、格式修复；是否够用由任务评测决定，不能只按省钱切换。
- 全注意力、固定缓存精度下，实际缓存 token 数翻倍，KV cache 也翻倍；并发序列再翻倍，缓存预算还要翻倍。权重体积不会因此翻倍。
- MoE 分开看总参数和激活参数：前者用于权重存储与分片预算，后者辅助估算每 token 的主要计算量，延迟要在目标硬件上实测。
- 模型卡上的数字还会被版本、偏置开关、RoPE 配对方式和量化口径改变；关键决策用自己的请求压测。

## 4.7 常见翻车

| 常见翻车 | 后果 | 正确做法 |
| --- | --- | --- |
| 把“7B”当精确值 | 权重、显存、成本都算偏 | 按模型卡与 `config.json` 逐项重算 |
| 只算权重不算 KV cache | 长上下文一开就 OOM | 权重 + KV cache + 并发缓冲一起预算 |
| 把总参数当激活参数 | MoE 延迟和吞吐估错 | 区分 total 与 active，并在目标卡压测 |
| 以为量化只影响显存 | 质量或延迟出现回退 | 在自己的任务上做量化前后评测 |
| 忽略 tied / `Final Norm` | 参数总量对不上模型卡 | 核对 tied 词表、`bias` 与末尾 Norm |
| 调大 RoPE 范围就当质量保证 | 长输入能跑，但易答错 | 核对预训练长度、缩放方案与长输入评测 |

## 4.8 本章小实验

在仓库根目录运行：

```bash
python llm/examples/transformer_demo.py
```

然后试四组核对与改动：

1. 把 `X0` 改成 `[0.1, 0.2, 0.3]`，验证因尺度不变性两条 Norm 的输出向量几乎不变（仍为 `[0.463, 0.926, 1.389]` 与 `[-1.225, 0.000, 1.225]`），真正缩小 10 倍的是 `scale`（`2.160 -> 0.216`、`0.816 -> 0.082`）；再把代理函数 `block()` 的 `ATTN`、`FFN` 设成零向量，确认残差流原样穿透，并观察演示中真实多 token 模块 `forward_block()` 的输出与 2 层后经 `Final Norm` 的模长。
2. 对照 `params(..., final_norm=True)`、`kv_heads=8` 和 `moe_experts=8, moe_active=2` 的输出，理解 GQA 如何省掉每层 25 165 824 个注意力参数、MoE 为何需要分别看 `total` 与 `active_total`；也把 `d_ff` 改成 16384、`swiglu=False`，确认两矩阵与三矩阵版本总规模为何接近。
3. 先看 2D 例子（只有 `i=0` 一对坐标，改 `base` 结果不变），再看 4D `[1.0, 0.0, 1.0, 0.0]` 在偏移 10 下 `base=10000`（`+0.156`）与 `base=100`（`-0.299`）的差异及同加 7 后的点积不变性；同时核对同组 4D 向量的相邻配对 `rope()` 与重排后的 `rotate_half_rope()` 严格相等（`-1.082`），而未重排混用会得到错误的 `+0.193`。
4. 观察末尾 `sparse_moe_forward()` 的 top-2 路由与重新归一化输出，手动把 `router` 第一行权重改大，确认被选专家与加权结果如何变化。
