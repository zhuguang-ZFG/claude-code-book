# 第 8 章：SFT 与 LoRA：把通用模型改成你的助手

<!-- block: llm-ch08.b-opening -->
假设客服 Agent 要稳定输出固定的 JSON 结构，并按约定调用三个内部工具。微调前，需要先把问题分清：模型是选错工具、填错参数，还是输出格式不合法？这些错误需要不同的训练样本和评测指标。仅收集“最后答对了”的对话，会漏掉中间的错误与恢复过程。

本章用一组手设概率说明 SFT 的损失掩码，再用小矩阵比较 LoRA 合并前后的计算。示例用于核对训练目标与参数形状，不包含真实模型的微调效果。

## 8.1 SFT 在改什么

SFT 用标注示范继续训练模型。本节讨论对话 SFT：模型根据前面的 system、user、assistant 消息和工具回执，预测目标回答的下一个 token。单个目标 token 的交叉熵损失是：

```text
loss = -log p(正确 token | 前面的上下文)
```

先确定哪些目标位置计入损失。若训练目标是助手回答，可以屏蔽 system 和 user 对应的目标损失，把直接监督集中在 assistant 上。也有训练方案计算完整序列的损失；包含 prompt 不等于模型必然只会续写用户问题，效果要结合数据、模板和评测判断。`llm/examples/sft_demo.py` 用五个抽象位置演示两种平均口径；表中的文字是位置标签，并非某个 tokenizer 的实际切词结果：

| 位置 | 目标概率 | 损失 | 计入损失 |
| --- | ---: | ---: | ---: |
| system | 0.95 | 0.051 | 0 |
| user | 0.80 | 0.223 | 0 |
| assistant | 0.70 | 0.357 | 1 |
| 已退款 | 0.60 | 0.511 | 1 |
| 请查收 | 0.50 | 0.693 | 1 |

全部 token 平均是 0.367，只算 assistant 是 0.520。后者更大，只说明平均时选取的位置不同。只算 assistant 时，三个目标损失各占 `1/3` 权重；算全部 token 时，五个目标损失各占 `1/5`。

损失掩码不等于注意力遮罩，也不等于切断输入侧的梯度。prompt 仍然参与回答的计算，回答损失的梯度仍可经过输入的上下文表示传回可训练参数；被去掉的是预测 prompt token 的直接损失项。

实现时要检查模板与标签。[TRL v0.25.0 的 SFT 文档](https://github.com/huggingface/trl/blob/55f5433e15cc6203d3c731f9de5247b00878bebd/docs/source/sft_trainer.md)区分 `assistant_only_loss` 和 `completion_only_loss`：前者选择对话中的助手消息，后者选择 prompt-completion 样本的 completion 部分。助手掩码还要求聊天模板提供相应的生成区域标记。抽取一条分词后的样本，逐个核对输入 token、训练标签和被忽略的位置，比只看配置名称可靠。

这也解释了为什么“损失降到多少”不能跨数据口径比较。两个实验的 mask 不同、token 数不同、任务难度不同，损失值没有可比性；要比就固定评测集和评测指标。

```ill

```

SFT 常用于训练回答方式、格式和工具调用，也可能让模型学到或记住事实。但对需要频繁更新、可追溯出处的知识，把事实留在可更新的检索库里通常更容易维护。行为变化与事实正确率应分别评测，不能仅凭训练损失下降判断知识已可靠写入。SFT 作为对齐流程的一部分，可参考 [InstructGPT](https://arxiv.org/abs/2203.02155)。

数据侧至少检查五件事：去重、覆盖失败与恢复轨迹、授权与隐私、训练/评测按任务或时间切分、以及是否混入通用数据以减轻遗忘。只收集顺利完成的轨迹，就缺少工具报错后如何恢复的示范；训练集和评测集重叠，则可能高估泛化能力。

## 8.2 LoRA：冻结主干，训练低秩增量

全量微调要更新所有权重。LoRA 冻结原矩阵 `W`，只训练两个小矩阵：

```text
W' = W + (alpha / r) · B · A
```

`A` 的形状是 `r × d_in`，`B` 是 `d_out × r`，`r` 远小于 `d_in` 和 `d_out`。常见实现把 `A` 随机初始化、把 `B` 初始化为 0，于是训练开始时 `W' = W`，模型从原状态出发。`alpha / r` 控制更新幅度；改 `r` 时通常也要重调 `alpha` 或学习率。

<!-- block: llm-ch08.b-lora -->
示例用一个 4×4 的 `W` 和 rank 2 的 `A`、`B`，`alpha=4`，缩放因子是 2。对输入 `[1,1,1,1]`：

| 权重 | 输出 |
| --- | --- |
| 原始 `W` | `[0.300, 0.400, 0.300, 0.500]` |
| `W + (alpha/r)·B·A` | `[0.300, 0.500, 0.300, 0.540]` |

对这个输入，第二、四维发生了变化，第一、三维没变；换一个输入，未必还是这两维不变。对固定的适配器，更新量 `B·A·x` 落在 `B` 的列空间里，`B·A` 的秩最多为 `r`。训练也会改变 `A`、`B`，这个子空间不是预先固定的。

```ill
llm-ch08-sft-lora
```

对一个 `4096 × 4096` 的矩阵，LoRA 的可训练参数是 `2 × 4096 × r`：

| 秩 | 可训练参数 | 占全量比例 | fp16 适配器权重 |
| ---: | ---: | ---: | ---: |
| 1 | 8 192 | 0.049% | 16.0 KiB |
| 8 | 65 536 | 0.391% | 128.0 KiB |
| 16 | 131 072 | 0.781% | 256.0 KiB |
| 64 | 524 288 | 3.125% | 1.0 MiB |
| 4096 | 33 554 432 | 200.0% | 64.0 MiB |

最后一行说明 LoRA 不是“秩越大越省”：`r = d` 时 `A`、`B` 合起来是两个满矩阵，参数量反而是原矩阵的两倍。LoRA 的节省来自 `r << d`。r=8 的适配器在一个矩阵上是 128 KiB；如果 32 层每层只挂一个矩阵，约 4 MiB，但真实模型通常会在多个投影上挂适配器，要按实际配置乘。

训练完有两种部署方式：

- **保留适配器**：基座不变，按请求加载不同 LoRA，可做多租户、多任务切换；推理图里多两次小矩阵乘。
- **合并进基座**：把 `(alpha/r)·B·A` 加进 `W`，用合并后的权重运行，省去独立的适配器分支。

是否还能切换适配器取决于合并接口和服务实现。[PEFT v0.17.1](https://github.com/huggingface/peft/blob/53c25fe4fdd7c6aa4b40db0560815ea570d32303/docs/source/developer_guides/lora.md)区分可撤销的 `merge_adapter()` / `unmerge_adapter()` 与 `merge_and_unload()`：后者返回不再保留 PEFT 适配器功能的模型。不能把一次合并概括成整个进程都无法切换。

本章脚本分别计算 `W·x + (alpha/r)·B·(A·x)` 和 `(W + (alpha/r)·B·A)·x`，在浮点容差内比较结果。这个线性等价检查假定推理时关闭 dropout；量化合并的舍入误差、真实吞吐和任务质量还要单独验证。

## 8.3 QLoRA 与显存

QLoRA 把冻结的基座以 4-bit 形式存储，并训练 LoRA 适配器。[原论文](https://arxiv.org/abs/2305.14314)还使用 NF4、双重量化和分页优化器。4-bit 是权重存储方式，不表示前向与反向的所有运算都使用 4-bit；适配器、激活值、梯度和优化器状态仍要占空间。量化引入数值近似，但任务质量会下降多少、是否下降，都要实测，不能只凭位宽下结论。

## 8.4 微调、提示词与 RAG 的分工

| 需求 | 优先手段 | 原因 |
| --- | --- | --- |
| 固定输出格式、工具调用约定 | 提示词、约束解码与校验；必要时 SFT / LoRA | 先验证接口约束，再用示范补足行为 |
| 注入最新事实、文档知识 | RAG | 检索可更新，不必重训 |
| 调整角色、规则、语气 | 提示词 | 最快、最便宜、可回滚 |
| 领域术语与写法 | SFT + RAG | 行为靠示范，事实靠检索 |
| 降低延迟与成本 | 蒸馏 / 小模型 + LoRA | 用小模型承接窄任务 |
| 多租户风格适配 | 多 LoRA | 可共享基座；数据权限仍由服务端隔离 |

三者不是互斥的。一个客服 Agent 可以先用提示词定规则，用 RAG 取订单和政策，再用 LoRA 固定工具调用格式和回复风格。每一层都要有独立的评测，否则出了问题分不清是哪一层造成的。

**分类微调**把文本映到固定标签，可用于意图识别、工单分类和[第 10 章](ch10.md)的模型路由。它通常先取一个序列表示，再由分类头输出各类别的分数，但取哪个位置要看架构：[BERT](https://arxiv.org/abs/1810.04805) 的常见序列分类实现使用首个 `[CLS]` 位置，经 pooler 后送入分类头；因果 decoder 则常用最后一个有效 token，或采用指定的池化方式。可对照同一版本的 [BERT 实现](https://github.com/huggingface/transformers/blob/47b0e478f324b54f177ea7998a0791870fdd0324/src/transformers/models/bert/modeling_bert.py)与[序列分类公共实现](https://github.com/huggingface/transformers/blob/47b0e478f324b54f177ea7998a0791870fdd0324/src/transformers/modeling_layers.py)：padding 位置不能不加区分地当成句末。

分类损失在分类头的输出处计算，但梯度更新哪些参数由冻结配置决定：可以只训练分类头，也可以更新部分主干、LoRA 或整个模型。Raschka 的[第 6 章配套代码](https://github.com/rasbt/LLMs-from-scratch/blob/22c637fdf9aa2f5fdd39c2cc80c1d36b4ab7d8d8/ch06/01_main-chapter-code/ch06.ipynb)就同时训练分类头、最后一个 Transformer block 与末尾 LayerNorm。

所需样本量和成本优势取决于标签难度、数据分布、模型大小及部署方式，不预设固定倍数。约束解码（见[第 12 章](ch12.md)）可以限制生成模型输出合法标签，但标签是否合法与选得是否正确仍是两项检查。

## 8.5 Agent 工程落点

- 训练数据来自真实轨迹：assistant 的工具调用、参数、最终回答是监督信号；工具回执是观察，不要把回执当成助手要模仿的输出。
- 格式要有校验器：JSON Schema、工具参数类型、必填字段、失败重试；SFT 降低漂移，不替代校验。
- 评测按任务切分：留出未见过的时间段、租户或工具版本；随机切分容易把同一会话的相邻轮次泄漏到测试集。
- 记录版本四元组：基座模型、适配器、训练数据摘要、评测报告；缺一项就无法复现线上行为。
- 部署要有回退：适配器热加载失败、输出分布漂移或工具报错率上升时，能切回基座或上一版。
- 隐私与授权：训练轨迹里可能有用户地址、订单号和内部日志；脱敏、保留期限和访问控制要在训练前处理。

## 8.6 常见翻车

| 常见翻车 | 后果 | 正确做法 |
| --- | --- | --- |
| 损失掩码与任务不匹配 | 监督落在错误位置或遗漏目标回答 | 按训练目标核对模板、标签与掩码 |
| 只收集顺利完成的轨迹 | 缺少报错后的恢复示范 | 加入失败、恢复和拒绝样本 |
| 训练集与评测集重叠 | 指标虚高，上线翻车 | 按会话/时间/租户切分 |
| 学习率过大或步数过多 | 通用能力遗忘、输出变窄 | 混通用数据，早停，做回归评测 |
| 只测格式不测事实 | JSON 正确但内容错误 | 格式、事实、工具执行三层评测 |
| 把 LoRA 合并后不回归 | 静默改变线上行为 | 合并前后跑同一套评测 |
| 量化后直接上线 | 质量或工具调用退化 | 量化前后对比，保留 fp16 回退 |
| 多适配器版本混用 | 请求打到错误的任务适配器 | 适配器注册表 + 请求级版本固定 |

## 8.7 本章小实验

在仓库根目录运行：

```bash
python llm/examples/sft_demo.py
```

然后试四组改动：

1. 把 `MASK` 改成全 1，观察 all-token 与 assistant-only 两个均值怎样变化；再把 mask 改成只保留最后一个 token，理解“权重集中在哪”。
2. 把 `B` 全部设成 0，确认输出回到基座；恢复原来的 `B`，再把 `ALPHA` 从 4 改成 8，观察更新幅度翻倍。
3. 在参数表的 `for rank in (1, 8, 16, 64)` 中加入 4，先手算 `2 × 4096 × r` 再运行核对。这里不必改四维示例的 `RANK`；若要改变该示例的秩，必须同时调整 `A` 的行数和 `B` 的列数，只改缩放分母不算改变秩。
4. 把 `X` 改成 `[1,0,0,0]`，观察第一、三维是否仍不变；再把 `W` 换成单位矩阵，比较独立适配器分支与合并权重的输出。用单个输入无法判断适配器在真实任务上是否有足够容量。

这些概率和矩阵是手设的，不包含反向传播和优化器；它们说明损失掩码与参数形状，不代表真实微调效果。想复习模型卡上的参数和显存账，读[第 4 章](ch04.md)；想理解采样波动对评测的影响，读[第 5 章](ch05.md)；RAG 的切块与重排会在第 11 章展开。
