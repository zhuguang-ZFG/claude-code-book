# 第 9 章：对齐：模型为什么“听话”

<!-- block: llm-ch09.b-opening -->
一个代码审查 Agent 被要求“直接指出问题，不要客气”。上线后它确实少说客套话了，但也开始把正确的写法说成错误，只因为用户先表达了相反意见。团队用偏好数据做了一轮对齐，模型变得更“让人满意”，却更不敢坚持事实。

对齐优化的是一组偏好，不是真理。两组手设分数，就够把奖励模型的 Bradley-Terry 损失和 DPO 损失算一遍。算完再讨论 RLHF、DPO 在 Agent 系统里能做什么、不能做什么。

## 9.1 从模仿到比较

[第 8 章](ch08.md)的 SFT 最大化示范回答的似然：给一个输入，让模型更像人写的答案。对齐换了一个信号：给同一个输入的两个回答，标注哪个更好。相比让标注员打绝对分，成对比较更容易保持一致。

Bradley-Terry 模型把“更好”变成概率：

```text
P(y_w 优于 y_l) = sigmoid(r_w - r_l)
loss = -log sigmoid(r_w - r_l)
```

`r_w` 和 `r_l` 是两个回答的奖励分数。差值越大，模型越确信 `y_w` 更好；差值小于 0 时，损失会大于 `log(2) ≈ 0.693`。这套偏好学习框架的早期工作见 [Christiano 等](https://arxiv.org/abs/1706.03741)。

## 9.2 奖励模型

奖励模型通常从 SFT 模型出发，把输出词表的语言模型头换成一个标量头，输入是整段回答，输出一个分数。训练数据是成对比较，损失就是上面的 Bradley-Terry 损失。`llm/examples/alignment_demo.py` 用四组分数演示：

| 比较 | 胜者分数 | 败者分数 | 差值 | 损失 | 判对 |
| --- | ---: | ---: | ---: | ---: | --- |
| 更有帮助 | 2.00 | 1.00 | 1.00 | 0.313 | 是 |
| 更安全 | 0.50 | 0.60 | -0.10 | 0.744 | 否 |
| 更诚实 | -1.00 | -0.50 | -0.50 | 0.974 | 否 |
| 格式正确 | 1.20 | 1.20 | 0.00 | 0.693 | 否 |

平均损失 0.681，成对准确率 1/4。差值 1.0 的样本损失只有 0.313；差值 -0.5 的样本损失 0.974；打平不是胜利，损失仍是 0.693。

奖励模型是一个代理指标：它学的是标注员的偏好，不是“正确”本身。把策略过度优化到奖励模型上，分数会继续涨，真实质量却可能下降，这叫奖励黑客（reward hacking）。[Reward Model Overoptimization](https://arxiv.org/abs/2210.10760) 讨论了这种过优化的 scaling 现象。Agent 系统里，奖励模型同样可能奖励“看起来礼貌”“格式完整”而忽略事实和工具执行结果。

## 9.3 RLHF：奖励、策略与 KL

RLHF 的常见结构至少有三个模型：

- **策略**（policy）：要训练的语言模型；
- **参考策略**（reference）：SFT 后的冻结副本，用来约束漂移；
- **奖励模型**（reward）：给回答打分。

PPO 训练通常还带一个价值网络（critic），显存和调度成本要按四个模型量级估算。

目标可以写成：

```text
maximize  E[r(x, y)] - β · KL(π(·|x) || π_ref(·|x))
```

第一项让回答拿高分，第二项惩罚策略偏离参考模型太远。`β` 控制“讨好奖励”与“保持原样”的权衡。PPO 是常见的优化算法，但训练不稳定、对超参敏感，工程上还要处理 rollout、批处理和奖励归一化。SFT、奖励模型与 PPO 的组合在 [InstructGPT](https://arxiv.org/abs/2203.02155) 中有完整描述。

三个模型意味着显存和调度成本都不低；如果奖励模型和策略一起放大，训练集群的账要先算清楚。

## 9.4 DPO：把偏好直接写进策略

DPO 跳过显式奖励模型，直接用偏好对优化策略。对一对回答 `(y_w, y_l)`，定义策略相对参考模型的对数概率差：

```text
gap = [log π(y_w|x) - log π_ref(y_w|x)]
    - [log π(y_l|x) - log π_ref(y_l|x)]
loss = -log sigmoid(β · gap)
```

`β` 放大或缩小同一个 gap。脚本中的两组案例：

| 案例 | β | 胜者 log 比 | 败者 log 比 | 边际 | 损失 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 偏好正确 | 0.1 | 0.30 | -0.20 | 0.05 | 0.668 |
| 偏好正确 | 1.0 | 0.30 | -0.20 | 0.50 | 0.474 |
| 偏好反转 | 0.1 | 0.10 | 0.40 | -0.03 | 0.708 |
| 偏好反转 | 1.0 | 0.10 | 0.40 | -0.30 | 0.854 |

训练开始时策略通常等于参考模型，两个 log 比都是 0，gap 为 0，损失是 `log(2) = 0.693`。偏好正确时，策略提高胜者的相对概率、降低败者的相对概率，gap 变正，损失下降；偏好反转时方向相反，损失上升。`β` 越大，同一个 gap 产生的边际越大；在未饱和区梯度也更强，但策略更容易偏离参考模型，损失也会更快贴近 0。

```ill

```

DPO 不需要在训练时跑奖励模型和 PPO，但仍需要：

- 一份高质量的偏好对数据；
- 一个冻结的参考模型（通常就是 SFT 模型）；
- 对 `β`、学习率和训练步数的调参；
- 对策略漂移、模式坍塌和过拟合的评测。

“不需要奖励模型”不等于“不需要偏好数据”，也不等于“不会奖励黑客”。方法细节见 [DPO](https://arxiv.org/abs/2305.18290)。

## 9.5 对齐不是什么

- **它不校验事实**：偏好数据里说错的事，模型会学得更像；事实要靠检索、工具和测试。
- **它不替代安全边界**：对齐降低了一部分有害输出，但权限、沙箱、输入过滤和人工审批仍要做；提示注入仍可能绕过。
- **顺从不是目标**：如果标注员偏好“同意用户”，模型会学会拍马屁（sycophancy）；对代码审查、风险判断这类任务，这是负资产。
- **它不是一次性动作**：数据分布、工具版本和用户群体变化后，偏好会漂移，要重新评测。
- **它不消除标注分歧**：标注员之间也会分歧；把分歧压成一个分数，会丢掉“在什么条件下更好”。

Agent 场景尤其要区分“礼貌”和“正确”。一个回答可以语气很差但结论正确，也可以语气完美但调用了错误工具；偏好模型如果只学到语气，就会奖励后者。

## 9.6 Agent 工程落点

| 目标 | 手段 | 注意 |
| --- | --- | --- |
| 固定工具调用格式 | SFT / LoRA | 对齐不替代 schema 校验 |
| 安全拒绝与升级 | 偏好数据 + DPO/RLHF | 同时测误拒与漏拒 |
| 减少拍马屁 | 偏好对里加入“坚持正确结论”的样本 | 评测要覆盖用户施压场景 |
| 事实更新 | RAG / 工具 | 对齐不能可靠注入新知识 |
| 多租户风格 | 多 LoRA / 提示词 | 版本与权限隔离 |
| 线上回归 | 成对评测 + 任务指标 | 胜率上涨不代表任务成功 |

偏好数据最好来自真实轨迹：工具调用失败后的恢复、应该拒绝的请求、用户施压时的正确坚持。只收集“用户满意”的回答，会把顺从学进模型。评测至少分三层：成对偏好胜率、任务成功率、安全/误拒率；三层都过，才算对齐没有把系统改坏。

RLHF 至少同时装策略、参考和奖励三个模型，PPO 还常带价值网络；DPO 训练时省掉奖励模型，但推理仍要部署策略，评测仍要参考模型或基线。LoRA 能减少可训练参数，不减少基座权重的显存；这些账要按[第 4 章](ch04.md)的方法单独算。

## 9.7 常见翻车

| 常见翻车 | 后果 | 正确做法 |
| --- | --- | --- |
| 拿 SFT 数据直接做 DPO | 没有偏好对，目标函数对不上 | 构造 chosen/rejected 对 |
| 偏好数据只来自一个标注员 | 把个人偏好当全局标准 | 多标注、记录分歧、抽检 |
| 只优化奖励模型分数 | 奖励黑客，真实质量下降 | 保留任务指标与人工抽检 |
| `β` 过大 | 策略偏离参考，输出模式坍塌 | 从小值扫起，监控 KL/长度 |
| `β` 过小 | 偏好学不动 | 调学习率与步数，检查 gap |
| 只测胜率不测任务 | 拍马屁赢评测，任务失败 | 胜率 + 成功率 + 安全率 |
| 把对齐当安全边界 | 提示注入仍可绕过 | 权限、沙箱、审批另做 |
| 训练/评测同分布 | 指标虚高 | 按时间、租户、攻击类型切分 |

## 9.8 本章小实验

在仓库根目录运行：

```bash
python llm/examples/alignment_demo.py
```

然后试四组改动：

1. 把“格式正确”的胜者分数改成 1.3，观察损失从 0.693 降到多少；再把两者设成相等，确认损失回到 `log(2)`。
2. 把“更安全”的分数对调，观察成对准确率与平均损失的变化。
3. 把 DPO 的 `BETAS` 改成 `(0.01, 0.1, 1.0, 10.0)`，观察同一个 gap 下边际和损失怎样变化；正 gap 的损失会更快贴近 0，负 gap 的损失会继续变大。
4. 把“偏好反转”的四个 log 概率改成“策略已经偏好正确”，观察 gap 与损失；再思考为什么初始化时通常是 0.693。

这些分数和 log 概率是手设的，不包含奖励模型或策略训练；它们说明损失形状和 `β` 的作用，不代表真实模型的对齐效果。SFT 与 LoRA 的基础见[第 8 章](ch08.md)；采样波动会干扰评测，见[第 5 章](ch05.md)；完整评测会在第 14 章展开。
