# 第 11 章：RAG：切块、检索与重排

<!-- block: llm-ch11.b-opening -->
用户问“退款多久到账”，知识库里有退款政策、退货流程、物流时效和发票说明。把整个知识库塞进窗口，费用高、干扰多，模型还可能引用旧版政策。检索增强生成（RAG）要做的，是在提问之后只取回几段真正相关的材料，并让模型带着来源回答。

这一章用一个小客服语料走一遍切块、BM25、向量召回、RRF 融合和重排，最后把检索指标算一遍。语料和向量都是手设的，代码只用标准库。

## 11.1 RAG 解决的是“事实的新鲜度”

预训练和后续微调都可能改变参数中的知识，但要花训练成本，也不容易逐条核对来源与生效时间。RAG 把外部材料放进当前请求，便于更新、授权和引用。文档改完后，还需要完成入库、索引更新与旧缓存失效，后续请求才可能读到新版本。SFT 则常用于学习回答和引用方式；它也能学习事实，只是不能替代知识库的版本管理。相关训练方法见[第 8 章](ch08.md)与[第 9 章](ch09.md)。

一条完整的检索链路：

```text
切块/记录元数据 → 编码/建索引
查询 → 确定权限与生效版本 → 受限召回
     → 校验/去重 → 重排
     → 注入上下文 → 带来源回答
```

```ill
llm-ch11-rag-pipeline
```

RAG 的原始论文见 [Lewis 等](https://arxiv.org/abs/2005.11401)。它把检索器和生成器一起训练；工程上的 RAG 往往更简单：固定检索器，只把片段拼进提示词。简单不等于省事，切块、召回和重排每一步都会决定最终答案。

## 11.2 切块：先把答案留在同一块里

`llm/examples/rag_demo.py` 先演示一个最小问题：把“退款审核通过后原路退回”按固定长度切开。

| 块大小 | 切块结果 | 答案完整 |
| ---: | --- | --- |
| 10 | `退款审核通过后原路退` / `回` | 否 |
| 20 | `退款审核通过后原路退回` | 是 |

块太小，答案被切成两半，任何一块单独看都不完整；块过大时，一个向量可能混入多个主题，降低对局部问题的区分能力；合适的大小仍取决于语料和编码器。常见做法是按标题和句子切，保留少量重叠，并在块前拼上文档标题。示例给每个块加了 `退款政策：` 前缀，这样块离开原文后仍知道自己属于哪份文档。

```ill
llm-ch11-chunking
```

切块还要带元数据：来源、版本、更新时间、权限、章节路径。没有这些字段，后面无法过滤旧版本，也无法给答案标注出处。

## 11.3 召回：关键词和向量各管一段

BM25 按词频和逆文档频率打分，擅长精确词、编号、错误码；向量召回按语义相似度，擅长“钱还没退”和“退款未到账”这类字面不重合的表达。两者都只解决“召回”，不保证“相关”。

示例用字符二元组做中文分词（没有分词器依赖），对 12 个块算 BM25；向量是手设的三维主题权重（退款、物流、发票），查询向量偏退款。两个排序的前三名：

| 排名 | BM25 | 向量 |
| ---: | --- | --- |
| 1 | `refund-faq@v2#0` | `refund-policy@v2#0` |
| 2 | `refund-policy@v2#2` | `refund-policy@v2#1` |
| 3 | `refund-policy@v2#0` | `refund-policy@v2#2` |

BM25 的第一名是“退款到账时间受银行处理速度影响”，查询词命中得最准；向量第一名是“未发货订单可以申请退款”，因为整个文档的主题向量和查询最接近。这里同一文档的块共享一个向量，因此三个政策块的余弦分数完全相同，按输入顺序打破平局。这个排序展示了手设文档向量的局限，不是编码器理解句意后的结果。

融合排序用 Reciprocal Rank Fusion（RRF）：

```text
RRF(d) = Σ_i 1 / (c + rank_i(d))
```

只对包含 d 的列表求和，`rank_i` 从 1 开始。这里用 c 表示平滑常数，避免与截断位置 top-k 混淆；示例采用 [RRF 原论文](https://doi.org/10.1145/1571941.1572114)实验使用的 60，它不是所有数据集的最优保证。RRF 按名次累加，不直接比较不同检索器的原始分数。示例的 RRF 前三名是 `refund-policy@v2#0`、`refund-faq@v2#0`、`refund-policy@v2#2`，把两边的结果拉到一起。稠密检索的经典做法见 [DPR](https://arxiv.org/abs/2004.04906)；工程上不必从零训练，先用现成编码器加 BM25 往往就能跑起来。

## 11.4 过滤、去重与重排

权限与版本规则应参与召回。若检索后再检查，也必须在可信的检索边界内完成；未授权文本不能先发给外部重排服务或生成模型，再靠提示词要求忽略。示例按下面的顺序处理候选：

- **过滤**：示例先丢掉 `version < 2` 的块，再计算召回，留下 12 个块，不包含“7 天内退回”。统一阈值只是演示；真实文档的版本号不能跨文档比较，应按文档身份、状态和生效时间选择版本。块 ID 带版本，例如 `refund-policy@v2#0`，防止新旧内容在融合时被当作同一块。
- **去重**：示例删除去空白后全文相同的块，默认已启用。它不识别翻译或改写，也不自动判断哪个政策版本有效。真实系统合并重复内容时还应保留来源和权限信息。
- **重排**：用交叉编码器或一个小模型，把查询和每个候选块一起打分。示例的重排是玩具：`0.6 × 向量余弦 + 0.1 × 词重叠 + 0.2 × 标题命中`，它把“到账时间通常为 1–3 个工作日”排到第一，而向量召回只把它排第三。

重排之后才注入上下文。注入时带来源和片段 ID，回答里能回链；同时按[第 6 章](ch06.md)的预算留出输出余量，不要把 top-k 全部塞满。k 不是越大越好：多取一段无关材料，就多一分干扰和费用。

## 11.5 检索质量怎么量

11.1–11.4 的每一步都能改坏结果。要知道改动有没有用，得把**检索**和**生成**分开评。

### 检索层

先准备带标注的查询集，每条列出候选文档和相关性等级（2 = 能回答问题，1 = 相关但不完整，0 = 无关）。可以从几十条真实问法开始排查，但样本量应按业务覆盖、错误稀有程度和所需估计精度扩大。示例把 `grade > 0` 都视为二值相关，分级指标则保留 2/1/0：

| 指标 | 问的问题 | 惩罚什么 |
| --- | --- | --- |
| `recall@k` | 所有相关文档里，有多少进了前 k | 漏检 |
| MRR | 第一条相关文档排第几 | 首个命中太靠后 |
| `NDCG@k` | 分级相关性按位置打折后，离理想排序差多少 | 最佳答案没排前面 |
| `MAP@k` | 先算每条查询的截断 AP，再跨查询平均 | 多个相关文档的覆盖与排序 |

NDCG 的归一化折扣累计增益思想见 [Järvelin 与 Kekäläinen，2002](https://doi.org/10.1145/582415.582418)。本例采用指数增益版本 `2^rel - 1`，位置从 1 开始，折扣为 `1 / log2(i + 1)`：

```text
gain_i = 2^rel_i - 1
DCG@k = Σ_{i=1..k} gain_i / log2(i + 1)
NDCG@k = DCG@k / IDCG@k
```

`IDCG@k` 是把同一查询的全部标注按等级降序排列后，取前 k 项计算的 DCG。本例在没有相关文档时返回 0，汇总时也保留这类查询。

其余指标使用二值相关性：R 是该查询全部标注文档中 `grade > 0` 的数量；`rel_i` 表示第 i 位是否相关，是为 1，否则为 0。

```text
P@i = 前 i 位相关文档数 / i
recall@k = 前 k 位相关文档数 / R
AP@k = Σ_{i=1..k}(P@i × rel_i)
       / min(R, k)
MAP@k = 各查询 AP@k 的平均
RR = 1 / 首个相关结果的位置
MRR = 各查询 RR 的平均
```

找不到相关结果时，RR 记为 0。

本例的 AP@k 用 `min(R,k)` 作分母；也有实现始终除以 R，比较时须写明约定。R=0 时 recall 和 AP 返回 0。RR 检查传入的完整排序，不受 K 截断；若只想看前 k 位，应另报 MRR@k。排名列表中的文档 ID 应唯一，未知文档在这个脚本中按不相关处理。

`llm/examples/retrieval_metrics.py` 用 5 条查询、两套排序算了一遍：

| 排序器 | `recall@3` | MRR | `NDCG@3` | `MAP@3` |
| --- | ---: | ---: | ---: | ---: |
| 关键词优先 | 1.00 | 0.90 | 0.77 | 0.92 |
| 向量优先 | 0.93 | 1.00 | 0.97 | 0.90 |

平均看，关键词排序把相关文档找得更全（`recall@3` 1.00 对 0.93），但常把只算相关的文档放在前面：以“退款多久到账”为例，最佳答案被排到第二，单条 `NDCG@3` 只有 0.81。向量排序覆盖率略低，但五条都把最佳答案放在第一，平均 `NDCG@3` 0.97。四个指标互有胜负——不是数据出错，而是每个指标惩罚的失败不同。

这条退款查询的两套排序 RR 都是 1，因为第一条的 grade 都大于 0。RR 无法区分“相关但不完整”和“能回答问题”。查漏检看 `recall@k`，查首个二值命中的位置看 MRR，查完整答案是否靠前看保留分级信息的 NDCG。它们回答不同的问题。

### 生成层

检索对了，生成仍可能答错。RAG 评测常拆成两个轴（[Ragas](https://arxiv.org/abs/2309.15217) 的命名）：

- **faithfulness**：答案里的每个断言能否被检索到的片段支持；
- **answer relevance**：答案是否真的回答了问题，而不是答了旁边那个问题。

faithfulness 衡量是否得到材料支持，不保证材料本身真实或仍然有效。这两项可以用 LLM-as-judge 辅助打分，偏差与校准见[第 14 章](ch14.md)。人工抽检应覆盖不同分数段及高风险问题，既核对引用支持关系，也核对来源版本；抽多少条取决于希望发现的错误频率，固定每段 20 条并非通用验收标准。

### 一套能复用的流程

1. 从日志采样查询，人工标 2/1/0；
2. 先跑检索指标，定位是“没找到”还是“没排好”；
3. 再跑生成指标，定位是“没读到”还是“读到了答错”；
4. 每次只改一个旋钮（切块、embedding、`nprobe`、重排），同一份标注重跑；
5. 报指标时带上标注集大小与置信区间（[第 14 章](ch14.md)）。

一个常见误判：换了重排器，最终答案准确率没动，就认为重排没用。可能生成器本来就能从 top-5 里挑出对的片段，重排只是改了顺序；这时该看 NDCG 与注入的上下文精度，而不是只看端到端准确率。

## 11.6 Agent 工程落点

| 场景 | 检索策略 | 注意 |
| --- | --- | --- |
| 产品文档问答 | 标题切块 + BM25/向量 + 重排 | 版本与生效日期 |
| 工单排查 | 错误码/日志关键词 + 时间过滤 | 旧工单不能压过新工单 |
| 工具选择 | 工具描述 + 名称/参数关键词 | schema 结构化，不只看语义 |
| 长期记忆 | 向量 + 时间/权限过滤 | 过期记忆要淘汰 |
| 多租户知识库 | 元数据过滤 + 租户隔离 | 检索层就要隔离，不能只靠提示词 |

检索评测见 11.5：先看 `recall@k` 判断漏没漏，再看 `NDCG@k` 判断排得好不好，最后才看端到端答案。

## 11.7 常见翻车

| 常见翻车 | 后果 | 正确做法 |
| --- | --- | --- |
| 固定长度硬切 | 答案被切断、指代丢失 | 按标题/句子切，保留重叠与标题 |
| 只做向量召回 | 编号、错误码、专有名词漏召 | BM25 + 向量混合 |
| 直接比较 BM25 与余弦分数 | 融合权重不可解释 | 用 RRF 或归一化后再融合 |
| 不按版本/时间过滤 | 旧政策压过新政策 | 元数据过滤 + 生效时间 |
| top-k 取很大 | 上下文被无关片段挤满 | 召回后重排，控制注入数量 |
| 不带来源 | 无法核对、无法回链 | 片段 ID、文档标题、更新时间 |
| 训练集与评测集重叠 | 指标虚高 | 按文档/时间/租户切分 |

## 11.8 本章小实验

在仓库根目录运行：

```bash
python llm/examples/rag_demo.py
python llm/examples/retrieval_metrics.py
```

然后试四组改动：

1. 把 `chunk_fixed` 的块大小从 10 改成 6、12、30，观察“原路退回”在哪些大小下被切断；再想想要不要加重叠。
2. 把 `QUERY_VEC` 改成 `[0.1, 0.9, 0.0]`（物流），观察向量排序怎样变化，BM25 是否还稳定；再试一个只含错误码的查询。
3. 在 `main()` 中把过滤调用改成 `filter_stale(chunks, min_version=1)`，确认旧政策重新进入候选，并检查 `@v1` 与 `@v2` 的 ID 不同。另建一个实验：在 `build_chunks(DOCS)` 后复制一块并给它换一个 ID，再调用 `dedupe`，比较数量。默认语料没有这种全文重复，旧版与新版文字不同也不会被去重。
4. 把 `retrieval_metrics.py` 中一条文档的 grade 从 0 改成 2，观察相关总数和理想排序怎样改变。再把 K 从 3 改成 1，重算截断指标；解释为什么完整排序上的 MRR 不变。

示例只演示检索链路，不调用生成模型；它给的是候选排序和过滤形状。下一章进入工具调用与 MCP，看 Agent 怎样把“查知识库”变成一次可校验的工具调用；想复习 embedding，回[第 2 章](ch02.md)，想算上下文预算，读[第 6 章](ch06.md)。
