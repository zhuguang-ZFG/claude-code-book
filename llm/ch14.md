# 第 14 章：幻觉、评测与蒸馏：怎样判断它真的变好

<!-- block: llm-ch14.b-opening -->
两个系统在同一套 200 道题上分别答对 164 道和 172 道。B 多答对 8 道，但只看这两个总数，还不知道它修正了哪些错误，又引入了哪些新错误。要判断是否值得切换，需要逐题结果、测试集来源，以及错答和弃权的计分规则。

这一章用手设数据计算置信区间、配对差异、污染、弃权和蒸馏成本。每个数都对应一项具体问题：估计有多不确定，改进发生在哪些题上，以及取得这些正确答案付出了多少成本。

## 14.1 幻觉不是单一故障

排查生成错误时，可以先按下面五类记录。它们是本章的工程检查表；格式、计算和工具执行错误不都属于研究文献中狭义的“幻觉”：

- **事实错误**：模型不知道或记错了，编出一个像真的答案；
- **引用错误**：文档、链接、页码不存在，或引用了旧版本；
- **工具错误**：参数传错、调用了不存在的工具、把失败当成功；
- **计算错误**：步骤看起来合理，算术结果错了；
- **格式错误**：JSON 少括号、字段类型不对，导致下游解析失败。

预训练模型按概率生成下一个 token，流畅和正确不是同一件事。检索和工具能减少事实与工具错误，但不能保证模型正确使用返回结果；[幻觉综述](https://arxiv.org/abs/2202.03629) 按来源与表现做过分类。

| 类型 | 优先手段 |
| --- | --- |
| 事实/时效 | 检索、工具查询、显示更新时间 |
| 引用 | 片段 ID、可点击来源、回链核对 |
| 工具/格式 | schema 校验、执行回执、失败重试 |
| 计算 | 代码执行、单元测试、逐步核对 |
| 过度自信 | 弃权、置信度、人工升级 |

## 14.2 一个准确率不够

`llm/examples/eval_demo.py` 先算 200 道题上的两个系统：

| 系统 | 正确数 | 准确率 | 95% Wilson 区间 |
| --- | ---: | ---: | --- |
| A | 164 | 82.0% | [76.1%, 86.7%] |
| B | 172 | 86.0% | [80.5%, 90.1%] |

Wilson 区间描述各自准确率估计的不确定性，计算方法见 [NIST 手册](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。这里的二项模型把每题看作独立的对错观察；同一会话拆成多题、重复模板或近重复样本会削弱这个假设，不能机械地把题目条数当成独立样本量。

两个区间重叠，不能直接推出两系统没有显著差异。它们回答的是各自准确率的范围，而比较同一批题还要利用配对信息。以下两组逐题结果，都能得到 A 为 164/200、B 为 172/200：

| 配对结果 | 情形一 | 情形二 |
| --- | ---: | ---: |
| 两者都对 | 164 | 144 |
| 只有 A 对 | 0 | 20 |
| 只有 B 对 | 8 | 28 |
| 两者都错 | 28 | 8 |
| 双侧精确 McNemar p 值 | 0.0078 | 0.3123 |

McNemar 检验只使用判断不一致的两类题。在两系统边际准确率相等的原假设下，一道不一致的题偏向 A 或 B 的概率各为一半；[statsmodels 文档](https://www.statsmodels.org/stable/generated/statsmodels.stats.contingency_tables.mcnemar.html)说明了精确检验使用二项分布。第一组的 8 次差异全部有利于 B，第二组则是 B 修正 28 道、同时新错 20 道。按事先约定的 0.05 阈值，前者提供差异证据，后者未达到该阈值，尽管两组的 Wilson 区间完全一样。

p 值不是“B 更好的概率”，未达到阈值也不证明二者相同。上线还要检查效应大小、错误严重程度与任务覆盖；反复试很多模型或挑选有利分组后再检验，也会改变误报风险。先保存逐题输出和评分，再讨论增加样本或如何分层。

第二笔账是污染。200 条测试里，20 条在训练时见过；模型在这 20 条上全对，在剩余 180 条上对 144 条：

| 口径 | 准确率 |
| --- | ---: |
| 干净测试集 | 80.0% |
| 混入见过的题 | 82.0% |
| 虚高 | +2.0 个百分点 |

污染不一定来自故意；网页、代码镜像、翻译对和旧版本都可能把测试题带进训练。评测要按时间、租户、文档版本切分，并做近重复检测。[HELM](https://arxiv.org/abs/2211.09110) 一类整体评测框架强调多场景、多指标，而不是一个总分。

**LLM-as-judge** 用另一个模型给回答评分：可以成对比较，也可以按预先写好的评分规则逐项打分。这能辅助评估开放回答和多轮对话，但评分模型也会出错。[MT-Bench 研究](https://arxiv.org/abs/2306.05685)讨论了位置、长度等偏差，[自偏好研究](https://arxiv.org/abs/2403.18841)则检查了模型对自身输出的偏好。

成对比较时，可把答案顺序交换后再评一次，并记录不一致率；不能只留下两次一致的结果，把冲突样本悄悄丢掉。评分规则应明确到可检查的条件，关键样本可交给其他模型或人工复核。换一个模型家族也不保证判断独立，仍需用人工标注检查评分者本身。

把零散的基准放进一张地图更好导航。评测体系通常分三支：**知识与能力**（理解、问答、生成、推理、代码）、**伦理与安全**（毒性、偏见、越狱、红线测试）、**垂直领域**（法律、医疗、金融等按场景另算）。知识与能力一支再分两路：以任务为中心，[HELM](https://arxiv.org/abs/2211.09110) 用“任务 × 领域 × 语言”三个维度把场景摊开成几十类，避免一个总分掩盖短板；以人为中心，[AGIEval](https://arxiv.org/abs/2304.06364) 直接拿人类标准化考试——高考、SAT、法考——当题库。给 Agent 选模型时按这张地图选支：做客服先看安全与拒答，做代码 Agent 看推理与代码，别拿通用总分替代你的场景。

## 14.3 弃权与覆盖

模型可以选择不答。示例的 100 道题里，模型回答 80 道，其中 72 道正确，20 道弃权：

| 指标 | 值 |
| --- | ---: |
| 覆盖率 | 80.0% |
| 回答内准确率 | 90.0% |
| 整体准确率 | 72.0% |
| 错答率 | 8.0% |

这里“错答率”的分母是全部 100 道题，所以为 8%；若只看已回答的 80 道，则错误比例为 10%。整体准确率 72% 已把弃权按未答对计入；20 道弃权仍须单独记录，不能与 8 道实际错答混为一谈。

弃权后的动作和成本取决于任务：可以转人工、补检索或请求更多信息。评测要覆盖这些后续步骤，才能比较弃权与执行错误答案的代价。

报告评测时至少同时给覆盖率、回答内准确率和错答率。只看其中一个，系统可以通过“多弃权”把准确率做高，也可以通过“全都答”把覆盖率做高。

## 14.4 蒸馏：小模型承接窄任务

蒸馏让一个学生模型学习教师模型的输出、概率分布或推理轨迹。示例的成本账：

| 模型 | 准确率 | 每请求价格 | 每道正确题成本 |
| --- | ---: | ---: | ---: |
| 教师 | 85.0% | $0.0060 | $0.0071 |
| 学生 | 78.0% | $0.0012 | $0.0015 |

按未四舍五入的数值算，学生的平均“每道正确题成本”约为教师的 `1/4.6`，准确率低 7 个百分点。这个指标是总请求费用除以答对的题数，不表示不断重试同一道题就能按这个价格得到正确答案。表中也未计入蒸馏训练、错误处理、转人工和重试成本。即使是分类或路由任务，是否接受质量下降，也应由错误类型和业务成本决定。

蒸馏也会继承教师的错误和偏差。用教师生成训练数据、再用同一族模型评测，容易得到漂亮的闭环分数。学生要在独立测试集上评，最好包含教师失败过的样本。[Hinton 等](https://arxiv.org/abs/1503.02531) 的经典蒸馏用软标签传递类别间的相似性；语言模型蒸馏还会用理由、答案和偏好数据，具体配方要看任务。

## 14.5 Agent 工程落点

| 场景 | 评测重点 | 做法 |
| --- | --- | --- |
| 客服问答 | 事实、引用、弃权 | 干净测试集 + 来源核对 |
| 工具调用 | 选对工具、参数、恢复 | 执行回执 + 失败注入 |
| 代码修复 | 测试通过、回归 | 单元测试 + 隐藏用例 |
| 长上下文 | 位置效应、遗漏 | 分段评测 + 关键事实 |
| 蒸馏学生 | 窄任务准确率、成本 | 独立测试集 + 教师失败样本 |
| 上线回归 | 分位数、错误率 | 灰度 + 监控 + 回退 |

评测集要版本化，和模型、提示词、工具 schema 一起记录。改了一条提示词就换一套题，前后分数不可比；同一套题反复调参，又会过拟合评测集。留一份不常看的 holdout，只在发布前用。

## 14.6 常见翻车

| 常见翻车 | 后果 | 正确做法 |
| --- | --- | --- |
| 只报一个准确率 | 看不出样本量与波动 | 给置信区间和样本数 |
| 训练/测试污染 | 指标虚高，上线翻车 | 按时间/租户切分，查近重复 |
| 把弃权算成答对 | 覆盖率与准确率混淆 | 分开报覆盖率、回答内准确率、错答率 |
| 只测最终答案 | 分不清检索、推理、格式哪步错 | 分层评测中间环节 |
| 用同一族模型评蒸馏 | 共同偏差可能使评分高估实际质量 | 独立测试集 + 人工抽检 |
| 调参调到测试集上 | 过拟合评测，发布即跌 | 保留 holdout，限制查看次数 |
| 忽略成本与延迟 | 准确率略升，账单翻倍 | 每道正确题成本 + p95 |

## 14.7 本章小实验

在仓库根目录运行：

```bash
python llm/examples/eval_demo.py
```

然后试三组改动：

1. 比较 `wilson(164, 200)`、`wilson(150, 200)` 和 `wilson(1640, 2000)`，把准确率变化与样本量变化分开观察。再运行两组 McNemar 对照，确认同样的准确率总数可以对应不同的配对证据。
2. 固定总题数为 200、干净准确率为 80%、见过的题全部答对，比较 `contamination(156, 195, 5, 5)` 与 `contamination(120, 150, 50, 50)`。观察变化时不要同时改变干净部分的准确率。
3. 核对 72 道正确、8 道错答、20 道弃权是否合计为 100。先按“正确才得分”计算 72% 的整体准确率，再设定转人工的价格和解决率，单独计算后续服务的成本与成功率；不要修改原模型的覆盖率冒充模型改进。

示例只算统计与成本，不调用模型。下一章讨论[多模态输入](ch15.md)，术语速查见[第 16 章](ch16.md)；想复习采样波动，回[第 5 章](ch05.md)，想复习工具回执，读[第 12 章](ch12.md)。
