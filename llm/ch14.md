# 第 14 章：幻觉、评测与蒸馏：怎样判断它真的变好

<!-- block: llm-ch14.b-opening -->
两个系统在同一套题上跑出 82% 和 86%。团队准备把 86% 的那个上线，直到有人问：样本只有 200 条，差距是不是噪声？测试集里有没有训练时见过的题？模型答不出的那部分，是被算成错，还是被悄悄跳过？

评测不是给模型打一个总分，而是回答“在什么数据上、用什么指标、差距有多大、错了会怎样”。这一章用一组手设计算，展示置信区间、污染、弃权和蒸馏成本怎样改变结论。

## 14.1 幻觉不是单一故障

“幻觉”常被当成一个词，实际至少有五类：

- **事实错误**：模型不知道或记错了，编出一个像真的答案；
- **引用错误**：文档、链接、页码不存在，或引用了旧版本；
- **工具错误**：参数传错、调用了不存在的工具、把失败当成功；
- **计算错误**：步骤看起来合理，算术结果错了；
- **格式错误**：JSON 少括号、字段类型不对，导致下游解析失败。

预训练模型按概率生成下一个 token，流畅和正确不是同一件事。检索和工具能减少事实与工具错误，但不能保证模型正确使用返回结果；[幻觉综述](https://arxiv.org/abs/2202.03629) 按来源与表现做过分类。

| 类型 | 优先手段 |
| --- | --- |
| 事实/时效 | 检索、工具查询、显示更新时间 |
| 引用 | 片段 ID、可点击来源、回链核对 |
| 工具/格式 | schema 校验、执行回执、失败重试 |
| 计算 | 代码执行、单元测试、逐步核对 |
| 过度自信 | 弃权、置信度、人工升级 |

## 14.2 一个准确率不够

`llm/examples/eval_demo.py` 先算 200 道题上的两个系统：

| 系统 | 正确数 | 准确率 | 95% Wilson 区间 |
| --- | ---: | ---: | --- |
| A | 164 | 82.0% | [76.1%, 86.7%] |
| B | 172 | 86.0% | [80.5%, 90.1%] |

区间重叠。82% 与 86% 的差距在 200 条样本上还不足以宣布胜者；要缩小区间，需要更多样本，或做配对比较、按任务分层。只报一个点估计，读者无法判断差距是不是噪声。

第二笔账是污染。200 条测试里，20 条在训练时见过；模型在这 20 条上全对，在剩余 180 条上对 144 条：

| 口径 | 准确率 |
| --- | ---: |
| 干净测试集 | 80.0% |
| 混入见过的题 | 82.0% |
| 虚高 | +2.0 个百分点 |

污染不一定来自故意；网页、代码镜像、翻译对和旧版本都可能把测试题带进训练。评测要按时间、租户、文档版本切分，并做近重复检测。[HELM](https://arxiv.org/abs/2211.09110) 一类整体评测框架强调多场景、多指标，而不是一个总分。

## 14.3 弃权与覆盖

模型可以选择不答。示例的 100 道题里，模型回答 80 道，其中 72 道正确，20 道弃权：

| 指标 | 值 |
| --- | ---: |
| 覆盖率 | 80.0% |
| 回答内准确率 | 90.0% |
| 整体准确率 | 72.0% |
| 错答率 | 8.0% |

“回答内准确率 90%”听起来很好，但它把 20% 的弃权排除在外。对 Agent 来说，弃权可能比错答便宜：转人工、再检索、让用户补充信息，都是可接受的动作；编一个错误答案再执行，代价更大。

报告评测时至少同时给覆盖率、回答内准确率和错答率。只看其中一个，系统可以通过“多弃权”把准确率做高，也可以通过“全都答”把覆盖率做高。

## 14.4 蒸馏：小模型承接窄任务

蒸馏让一个学生模型学习教师模型的输出、概率分布或推理轨迹。示例的成本账：

| 模型 | 准确率 | 每请求价格 | 每道正确题成本 |
| --- | ---: | ---: | ---: |
| 教师 | 85.0% | $0.0060 | $0.0071 |
| 学生 | 78.0% | $0.0012 | $0.0015 |

学生每道正确题便宜约 4.6 倍，但准确率低 7 个百分点。这个交换是否值得，取决于任务：分类、路由、格式修复这类窄任务可以接受；高风险决策不能只看平均准确率。

蒸馏也会继承教师的错误和偏差。用教师生成训练数据、再用同一族模型评测，容易得到漂亮的闭环分数。学生要在独立测试集上评，最好包含教师失败过的样本。[Hinton 等](https://arxiv.org/abs/1503.02531) 的经典蒸馏用软标签传递类别间的相似性；语言模型蒸馏还会用理由、答案和偏好数据，具体配方要看任务。

## 14.5 Agent 工程落点

| 场景 | 评测重点 | 做法 |
| --- | --- | --- |
| 客服问答 | 事实、引用、弃权 | 干净测试集 + 来源核对 |
| 工具调用 | 选对工具、参数、恢复 | 执行回执 + 失败注入 |
| 代码修复 | 测试通过、回归 | 单元测试 + 隐藏用例 |
| 长上下文 | 位置效应、遗漏 | 分段评测 + 关键事实 |
| 蒸馏学生 | 窄任务准确率、成本 | 独立测试集 + 教师失败样本 |
| 上线回归 | 分位数、错误率 | 灰度 + 监控 + 回退 |

评测集要版本化，和模型、提示词、工具 schema 一起记录。改了一条提示词就换一套题，前后分数不可比；同一套题反复调参，又会过拟合评测集。留一份不常看的 holdout，只在发布前用。

## 14.6 常见翻车

| 常见翻车 | 后果 | 正确做法 |
| --- | --- | --- |
| 只报一个准确率 | 看不出样本量与波动 | 给置信区间和样本数 |
| 训练/测试污染 | 指标虚高，上线翻车 | 按时间/租户切分，查近重复 |
| 把弃权算成答对 | 覆盖率与准确率混淆 | 分开报覆盖、精度、错答率 |
| 只测最终答案 | 分不清检索、推理、格式哪步错 | 分层评测中间环节 |
| 用同一族模型评蒸馏 | 闭环分数漂亮，实际退化 | 独立测试集 + 人工抽检 |
| 调参调到测试集上 | 过拟合评测，发布即跌 | 保留 holdout，限制查看次数 |
| 忽略成本与延迟 | 准确率略升，账单翻倍 | 每道正确题成本 + p95 |

## 14.7 本章小实验

在仓库根目录运行：

```bash
python llm/examples/eval_demo.py
```

然后试三组改动：

1. 把系统 A 的正确数从 164 改成 150，观察 Wilson 区间怎样变宽；再把样本量从 200 改成 2000，看同样的准确率区间缩小多少。
2. 把污染比例从 20/200 改成 5/200 和 50/200，观察虚高幅度；再想想为什么“干净准确率”要用未见的题单独算。
3. 把弃权的 20 道题全部算成错答，重算覆盖率和整体准确率；再把这 20 道转人工，估算人工成本与错答成本的取舍。

示例只算统计与成本，不调用模型；它给的是评测口径。下一章把全书术语收成一张速查表；想复习采样波动，回[第 5 章](ch05.md)，想复习工具回执，读[第 12 章](ch12.md)。
