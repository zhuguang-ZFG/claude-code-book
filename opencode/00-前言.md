# 前言

<!-- block: opencode-front.b-opening -->
OpenCode 回答问题时，背后有一段可以追踪的执行过程：读取配置，把工具交给模型，询问权限，执行操作，再把结果送回模型。本书沿着这段过程读源码，也观察失败时程序停在哪里、留下什么。

你不必先会 Effect，也不必先写过插件。前五章从安装、配置、服务端和会话讲起；第六到十章把工具、权限、插件和 MCP 接起来；后面再讨论代码上下文、子任务、撤销和自动化。想直接改插件，可以从第八章开始，再回到第七章确认它实际拥有什么权限。

如果想先动手，按手头的环境选择入口：只有 Node 时，从第 8.6 节运行观察器测试；准备好固定 Windows 程序和依赖后，再跟第 1.6 节读取文件。这两项都不用模型账号。第十七章的金额计算练习则只需 Python 就能比较错误版与参考版；让 OpenCode 自行修复是另一步，需要你配置真实模型。

## 为什么固定一个版本

本书以 v1.19.5、提交 `810c0eba1a7348036f8bdf61e6632d0c36c6876c` 为基线。这个提交中 V1 与 V2 同时存在，模块名、公共接口和生命周期各有差别。示例会注明使用哪一套接口，源码链接也固定到这个提交，方便逐处对照。

运行实验使用官方 Windows x64 发布程序。源码分析可能涉及其他平台的分支；没有在那些平台运行过的地方，会明确说是源码观察。官网会继续更新，读者升级时应先看第十六章，而不是只把安装命令里的版本号改掉。

## 本书实际运行了什么

第八章的处理器实验可以用 Node 直接运行，SDK 客户端是替身。第九章把原创插件装进真实宿主，验证发现、调用顺序、初始化失败、实例清理和模块缓存。第六、七章再运行真实自定义工具，检查允许、拒绝、询问以及 `once`、`always` 的有效范围。

这些宿主实验用本地模型协议替身发出确定的工具调用。插件、内置 read、自定义工具、权限服务、会话 HTTP API 和日志服务都是真实实现；模型并没有推理任务。这种设计让你能稳定地观察“请求进入后发生了什么”，却不能据此比较模型质量或给出费用结论。

## 怎样跟着做

示例放在 `opencode/examples/`，命令从书仓根目录执行。先读示例说明，下载并核对固定二进制，再准备隔离依赖。实验会创建自己的项目、用户配置、数据库和日志；原始证据放在忽略的 `.scratch`，不会混入日常工程。

这里的“书仓根目录”是能看到 opencode 和 yuyu-book 的目录。驱动创建的临时项目是 OpenCode 实际读取的目标，启动驱动时不必进入它。第十七章会改为在金额练习副本中操作；切换位置处会单独说明。

你自己的项目可能配置了其他插件、模型和指令文件，运行结果会与隔离实验不同。排查时可以先比较版本、项目目录和生效配置，再检查工具事件，逐步缩小差异来源。

书末的来源导航可用于查找实现，命令速查和实验记录可用于复现；忘记某个术语时，可以从索引回到相应章节。
