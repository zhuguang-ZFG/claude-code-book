# 前言

<!-- block: pi-front.b-5adf2cbd -->
> **开门一句话：**Pi 保持较小的内置功能集，通过扩展适应不同任务。本书说明核心与扩展各自负责什么，以及怎样修改和验证它们。

本册在十二卷合集中列为卷四。《御舆》分析 Claude Code 的架构，卷三介绍开源命令 `omp`。本册回到 Omp 的上游项目 Pi，讨论它如何划分核心功能与扩展。

Pi 的作者是 Mario Zechner，仓库在 [earendil-works/pi](https://github.com/earendil-works/pi)，
官网 [pi.dev](https://pi.dev)，MIT 许可。它在 README 里给自己下的定义很短：

> Pi is a minimal, extensible agent harness that you can make your own.

Pi 将一部分功能留给扩展。本册会逐项说明哪些能力内置、哪些需要另装或自行编写，以及扩展与核心怎样配合。

## 为什么值得单独写一册

对照 Claude Code 与 Omp，可以看出 Pi 在功能范围上的取舍：

- **Claude Code** 是成品：权限管线、记忆、子智能体、钩子，默认就给全。
- **Omp** 在 Pi 的基础上往"开箱即用"走：LSP、调试器、子代理、浏览器，装好就能干。
- **Pi** 选择相反的方向：内置工具少，子代理和 plan mode 明确不做，其余交给扩展、技能、提示模板、
  主题和包。它把"装配权"交回给你。

使用 Pi 前，需要先回答两个问题：

1. **"这个功能在哪？"**——答案常常是"没有，需要装或写"。
2. **"它怎么保证安全？"**——答案不是审批弹窗，而是"它不保证；要用容器或操作系统边界"。

本册先说明这些功能与安全边界，再介绍怎样通过扩展完成自己的任务。

## 这本册子现在写到哪

本册已有前言、25 章和附录 A–E。`PIN.md` 保存固定版本，`outline.md` 列出章节与证据入口，`VERIFY.md` 和 `facts/` 保留实验记录，`BUILD-PLAN.md` 说明构建方式。正文继续维护中文版本。

通俗层和手绘插图已接入，`make book-pi`、`make book-pi-pdf`、`make book-pi-epub` 分别构建 HTML、PDF 和 EPUB。旧构建记录的图版数、页数与体积只对应当时的文件，当前输出以本次构建为准。

想先看一组完整的失败与恢复，可以从第 12.8 节开始。驱动在临时目录里续跑会话、注入坏文件头、恢复备份，再检查新记录的父子关系；扩展加载实验则先制造错误导出，再恢复为可注册的工具。第 15 章继续核对工具输出、错误与中止。两组实验都不调用模型。

## 本书不做什么

- **不是官方文档的翻译。**与 Earendil Inc.、Pi 维护者及贡献者无隶属关系。
- **不把"没验证"写成"我试过"。**涉及本机运行的结论，证据放在 `VERIFY.md` 或各章的证据文件里；
  没条件跑的就写"未验证"。
- **不拿名称相近推断行为相同。**Pi 与 Omp 有血缘关系，但默认值、权限模型、扩展接口都不同；
  对照只搬问题清单，不搬数字。
- **不做"全书完成"的承诺。**写到哪，目录和 README 就更新到哪。

准备好了，从第 1 章开始：先看 Pi 砍掉了什么，以及为什么砍掉反而是它的卖点。
