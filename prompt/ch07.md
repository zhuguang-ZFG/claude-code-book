# 第 7 章：材料很多时，怎样选、排和缩短

<!-- block: prompt-ch07.b-opening -->
青禾工作坊收到一份正式时间修订，志愿者群里又出现了扩容的讨论。有人找出去年活动的房间号，还翻到一段答复草稿。如果把这些文字全部塞进对话，再加一句“请综合判断”，模型需要同时完成找资料、辨版本、处理冲突和组织回答。

这次仍只整理现行时间、容量、报名截止时间和房间状态，并简述满额后的处理办法。把输入分别保存为完整材料、所选材料和摘要，比较各自保留了什么，就能看出哪些答案还有依据。

这里的“上下文”指一次请求中模型实际能使用的内容，通常包括当前指令、当前材料，以及产品实际带入的历史消息或工具结果。某个文件放在电脑里，不代表它已经进入这次请求。我们用保存下来的输入确认这件事。

## 六份文字，六种作用

完整练习 D02 提供以下材料。没有读过第 1 章也可以从这一表开始。

| 材料 | 这次任务中的作用 | 需要防止的混用 |
| --- | --- | --- |
| [N01-v1 活动通知](materials/notice-v1.md) | 最初时间、12 人容量、截止时间、免费与房间未定 | 原时间已被修订，其他信息仍有效 |
| [R01-v1 名额规则](materials/rules-v1.md) | 满额候补、取消递补、重复申请的处理 | 不能把程序演示参数当成实际容量 |
| [U01-v2 正式修订](materials/update-v2.md) | 明确改为 13:30—15:30 | 只替换点名的时间字段 |
| [C01-v1 聊天摘录](materials/chat-v1.md) | 有人提出可能扩容至 15 人 | 建议尚无批准，不能替换正式容量 |
| [A01-v1 去年回顾](materials/archive-v1.md) | 解释旧房间号从哪里来 | 去年的 201 室不是今年安排 |
| [D01-v1 旧答复样稿](materials/demo-v1.md) | 可以观察答复语气及错误来源 | 示例中的事实仍需核对 |

单看日期会选错。聊天摘录比正式修订更新，却只是未核实意见；旧答复虽然已经写成完整句子，也没有经过组织者确认。两份材料都不能直接替换正式安排。

U01-v2 的作用更加具体：它明确修订 N01-v1 的活动时间，并说其他规定继续生效。因此，你不能只保留最新文件，删除旧通知。旧通知里仍有任务需要的截止时间和活动安排。版本判断要细到字段：哪个值被替换，哪些值沿用，谁有权修改。

## 先列出回答所需的证据

选择材料前，给任务做一次反向核对。假设最终答案有五个部分，各自依靠什么？

| 答案部分 | 至少需要的材料 | 缺少后的影响 |
| --- | --- | --- |
| 当前起止时间 | U01-v2，结合其修订关系 | 可能继续使用原来的 14:00—16:00 |
| 容量 | N01-v1 或 U01-v2 的明确保留说明 | 可能把聊天中的 15 人当成安排 |
| 报名截止时间 | N01-v1 或 U01-v2 的明确保留说明 | 只说“提前报名”，无法完成任务 |
| 房间状态 | N01-v1、U01-v2 的未确认说明 | 可能沿用去年或样稿中的 201 室 |
| 候补与递补 | R01-v1 | 只说“先到先得”，漏掉取消后的办法 |

按这张表回查材料，就能看出删掉某份文件会影响哪个答案，以及哪些句子必须保留。

对当前任务，C01-v1、A01-v1 和 D01-v1 可以不送入：正式安排与规则已足够支撑答案。它们并非永远无用。如果问题改成“居民为什么误以为在 201 室”，旧回顾和旧答复就成为调查材料，应该重新选入。相关性依赖问题，不能只给文件贴一个永久的“有用”或“无用”标签。

## 把三份输入真正存下来

你可以手工操作：把六份材料全文复制成一份文本，再复制一份只保留 U01-v2、N01-v1、R01-v1 的文本，最后另外写一份摘要。每份文本使用相同任务和相同输出约定，保存后再交给模型。

如果愿意运行脚本，在仓库根目录执行：

```bash
python prompt/examples/lab.py context D02 --mode full --out .scratch/prompt-context-full
python prompt/examples/lab.py context D02 --mode selected --out .scratch/prompt-context-selected
python prompt/examples/lab.py context D02 --mode summary --out .scratch/prompt-context-summary
```

每个目录都会出现 `request.txt` 和 `context.json`。`request.txt` 是完整的待发送文字，已经包含任务、提示和材料。`context.json` 是检查用的记录，包含选入材料、未选材料、字符数和 SHA-256 指纹。指纹是一段由文件内容算出的标记，内容变化通常会得到不同标记，用于核对版本；它不判断事实是否正确。

本书工具按 UTF-8 读写文字。实际发送时只发送 `request.txt`，不要把整个目录连同检查文件交给模型。特别是在摘要模式，检查记录里会提到原文 ID 和指纹，但原文并没有因此出现在请求里。

2026-11-10 对当前材料包运行导出，得到以下结果。数字包含提示、任务、输出约定、材料标记和材料正文，详细记录在[输入测量文件](evidence/context-measurements.json)。

| 输入方式 | 字符数 | UTF-8 字节数 | 选入内容 |
| --- | ---: | ---: | --- |
| full | 2076 | 4872 | 六份材料全文 |
| selected | 1526 | 3602 | U01-v2、N01-v1、R01-v1 全文 |
| summary | 485 | 1065 | 一段人工编写的 S01-v1 摘要 |

这只是输入大小的实测，没有运行模型。`selected` 这一次选择了整份文件，没有自动检索或按段切片；如果需要只选片段，应另外保存截取范围，并检查前后的适用条件有没有丢失。

字符数也不是 token 数。模型按自己的分词方式处理文本，中文、英文、标点和代码之间不能用一个固定比例精确换算。这里使用字符数便于在没有模型服务时比较文本长度；正式估算容量和费用，要记录所用模型及实际接口提供的计数方式。

## 摘要为什么可能短到不能用了

练习中的摘要故意写成这样：

> 人工教学摘要 S01-v1：活动在 2026 年 12 月 5 日下午举行，免费，12 人，满额后候补。房间未定。摘要依据 N01-v1、R01-v1、U01-v2，但省略了具体起止时间、报名截止时间和取消递补规则。摘要不替代原文。

它没有捏造信息，却删掉了当前任务必需的内容。读完摘要后，你能知道活动在下午，无法知道究竟几点开始；能知道满额候补，无法完整解释取消后的递补。

如果模型只看到这段摘要，正确做法是指出缺少具体时间、截止时间和递补细则，要求补充对应原文。它承认不足是合理的，但当前交付仍未完成。评估时应分别记录这两件事：是否诚实处理不足，是否交出了所需信息。

假如摘要模式回答出了 13:30，你也不能立即宣布“摘要足够”。先查会话里是否还留着完整材料、模型是否读到了其他文件、是否只是碰巧猜中。没有进入本次输入的证据，不能在核对时补贴成模型依据。

因此，本章的机械引文检查只接受当前输入里确实出现的来源。摘要模式可以引用 S01-v1，不能直接引用 N01-v1 的原句。写一句“摘要来源于 N01-v1”没有把那份原文交给模型。

如果要自己改写摘要，可以先保留一份未删减版本，再压缩那些与目标无关的文字。活动起止、截止时间、12 人容量、房间未定以及取消递补应作为必留内容；去年桌布的颜色则可以去掉。这个取舍来自任务，不来自“摘要通常要多少字”。

## 排序也是一次改动

所选材料按 U01-v2、N01-v1、R01-v1 排列：先看到当前修订，再看到仍有作用的原通知，最后看到业务规则。这样的顺序便于人核对，但本章没有证据证明它对任意模型都更好。

如果你同时删掉三份文件、改变顺序、改写摘要，又把提示换成长版，最后回答改善了，也很难说明是哪一项起了作用。做工程选择时可以把它们合在一起试，但结论只能是“这套组合在当前任务中表现如何”。想研究排序本身，就固定材料内容、提示和其他条件，仅改变排列次序。

正式通知已经指明替换关系时，可以直接据此整理；无关的旧照片说明也可以删去。若要进一步声称“这种排序提升了模型正确率”，就需要对照和重复记录，操作见[第 16 章](ch16.md)。

## 留预算，也留追查原文的路

材料规模变大后，可以给自己设一个输入预算。但总预算还要容纳任务说明、产品加入的消息、工具定义、历史内容和输出空间。不能把所有额度都按可粘贴的资料计算。

在本章的小任务里，你可以先设一个手工练习限制：请求正文不超过 1600 个字符。这个数只是练习约束，不是任何模型的上下文上限。当前所选版本为 1526 字符，满足该约束；摘要更短，却丢掉必要信息。达到大小限制和完成任务，要分别检查。

真正面对成百份资料时，通常需要先检索候选片段。检索返回的内容还要经过版本、权限、时间范围与问题相关性判断。关键词相同只意味着可能相关：去年活动的“201 室”能匹配“房间”，并不能回答今年去哪一间。

保留原文位置也很重要。你可以在摘录旁记下文档 ID、版本、章节或段落，以及为什么选它。若摘要遗漏了取消条件，之后就能回到 R01-v1，而不必让模型根据已经压缩的摘要再猜一次。检索系统怎样切块、建立索引，属于模型与应用工程课程的主题；本章关注的是被送入任务的材料能否支持交付。

## 没有模型也能完成的检查

先不运行生成，对三份 `request.txt` 做一次人工核对：当前时间能否直接找到，截止时间是否仍在，房间是否仍写未确认，候补和递补是否保留。把每个答案对应到具体来源。找不到时登记缺口，不从另外一个输入文件补答案。

如果使用模型，再分别开新会话发送三份请求。每次保存原始响应、会话中实际带入的其他内容，以及工具是否能够访问文件。不要在同一个会话先发 full、再发 summary，却把后一次称为只使用摘要的实验。

本轮已经完成导出和长度测量，模型回答对照仍待真实运行。你可以把尚未发生的观察留空，写“未运行”；不能把对输入的人工分析记成模型已经失败或已经成功。

完成后留下一份取舍说明，例如：“D02 保留正式修订、原通知和规则；省略聊天建议、去年回顾和旧答复，因为当前任务只整理现行安排；如果任务变成追查误传，需重新选择。”这份说明让接手的人知道你的选择为什么成立，也知道什么时候需要推翻它。
