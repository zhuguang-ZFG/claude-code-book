# 第 2 章：装好、连上、跑第一个线程
<!-- block: t3code-ch02.b-opening -->

上一章把控制平面和模型分开了，这一章把它落到你自己的机器上。安装路径、服务器启动方式、provider 登录、第一个线程的创建顺序，官方文档都写得很具体；这一章按这条顺序走一遍，并把桌面、网页、手机三种客户端的入口差别列清楚。读完之后，你应该能在不查第二份资料的情况下把环境跑起来。

命令会以表格和代码块出现，方便照抄。要特别注意两个容易踩的点：provider 的安装和登录发生在**运行服务器的那台机器**上，而不是你手里这块屏幕；`t3` 命令如果指向已经存在的服务器，正确做法是配对而不是再起一个。最后给出一份首次运行检查清单，每一项都能按官方文档自己核对。

## 2.1 下载与安装

命令行安装只要一条命令。macOS、Linux 用 `curl -fsSL https://t3.codes/install.sh | sh`，Windows 在 PowerShell 里用 `irm https://t3.codes/install.ps1 | iex`。安装器把 `t3` 放到 `~/.local/bin`；如果它不在 `PATH` 里，安装器会提示，并对 zsh、Linux 上的 bash 和 fish 打印添加命令。Windows 上同一窗口立即可用，新窗口需要把目录加进 `PATH`。若已存在一个并非安装器或桌面应用创建的 `t3`，它会保留该文件并停止。想装 nightly 用 `T3CODE_CHANNEL=nightly`，钉版本用 `T3CODE_VERSION`。不想安装可先跑 `npx t3@latest`（需要 Node.js）。

```powershell
irm https://t3.codes/install.ps1 | iex
```

桌面应用可从 GitHub Releases 下载，也能走包管理器：

| 平台 | 安装命令 |
|---|---|
| Windows | `winget install T3Tools.T3Code` |
| Windows / Scoop | `scoop install extras/t3code` |
| macOS | `brew install --cask t3-code` |
| Debian / Ubuntu | `sudo apt install ./T3-Code-*.deb` |
| Arch | `yay -S t3code-bin` |
| Nix | `nix profile add github:NixOS/nixpkgs/nixos-unstable#t3code` |

`npx t3@latest` 会先问要不要安装 `t3`；拒绝的话下一个小版本会再问一次，之后也能用 `npx t3 install` 补装。注意 `npx t3` 永远跑 npm 选中的版本，即使本机已装 `t3`；在 nightly 通道上要用装好的 `t3`（如 `t3 connect`），别用 `npx t3`，那是最新 stable。

Intel Mac 没有 `t3` 可执行文件，只有桌面应用；要在那种机器上跑服务器得用 `vp` 从源码构建：`git clone` 仓库后执行 `vp i && vp run build:desktop`，再 `node apps/server/dist/bin.mjs`。这样跑起来的服务器不适用 `t3 update` 和后台服务，更新靠 `git pull` 加重新构建。Linux 的 AppImage 要先 `chmod +x` 再执行；`.deb` 会自更新但每次要密码，没有密码提示的环境会更新失败，只能重新下载安装。AUR 包用 `yay -Syu` 更新，Nix 包用 `nix profile upgrade t3code`，都不要走应用内更新器。

## 2.2 启动本地服务器

裸跑 `t3` 会启动服务器并打开网页应用；`t3 serve` 只启动服务器、不开浏览器。要在新工作目录启动，用显式路径如 `t3 ./my-project`；裸目录名只有在目录已存在时才被接受。若 `t3` 或 `t3 start` 报告已有服务器在跑，照它提示执行 `t3 pair` 并打开配对 URL 连接那个服务器；要另起独立服务器，先停掉旧的，或换一个 `--base-dir`。

在 WSL 里，先在 **Settings → Sharing & access** 选发行版，agent 和项目就运行其中；provider CLI 要装进那个发行版，T3 Code 会自动在其中安装自己的服务器运行时，应用更新后首次启动可能慢一些。若 provider 在 CLI 里能用、T3 Code 却报超时，可以给探测加时间：

```sh
T3CODE_CODEX_PROBE_TIMEOUT_MS=60000 T3CODE_CLAUDE_PROBE_TIMEOUT_MS=60000 t3 serve
```

变量值是整毫秒且不超过 2147483647；非法或缺失值保持默认。远程环境要把变量设在跑服务器的机器上，并写进启动器或服务配置，systemd 可在 `[Service]` 下加 `Environment=`。它只放宽 readiness 与发现探测，不影响 turn 执行、安装、更新检查或关闭超时。

## 2.3 provider 登录

打开 **Settings → Providers**，选中环境，再启用想要的 provider。安装、登录和配置都属于环境所在机器，即使你从手机或另一台电脑连进来也一样。官方文档给出的登录动作各不相同：Codex 可用 Connect with ChatGPT 或 `codex login`，Claude 用 `claude auth login`，Cursor CLI 用 `agent login`，Grok Build 用 `grok login`，Kiro 用 `kiro-cli login`，OpenCode 用 `opencode auth login`，Pi 先运行 `pi` 再 `/login`。

```sh
claude auth login
codex login
opencode auth login
```

provider CLI 必须在服务器的 `PATH` 上；版本管理器装的 CLI 找不到时，在 provider 设置里填 **Binary path**。Cursor 的可执行文件叫 `cursor-agent`，登录命令却是 `agent login`。通过 ChatGPT 连接的 Codex 和 Antigravity 可以用托管运行时，不必进 `PATH`。每个 provider 实例可以有自己的环境变量，例如 API key 或自定义 base URL；标记为 sensitive 的值保存后不再显示原文。要给另一个账号用，就再加一个 provider 实例，而不是复用同一个实例的凭据。

版本也要看一眼：provider 版本与当前 T3 Code 有已知兼容问题时，**Settings → Providers** 会警告并给出推荐版本或范围；包管理器能指定版本就在那里装，否则到那台机器上用 provider 自己的安装器，未列出的版本属于未验证。provider 卡片落后于最新版时会显示可用版本，**Update now** 会调用拥有该 CLI 的安装器（Homebrew、mise，或全局 npm / pnpm / Yarn / Bun / Volta / Vite+ 安装），识别不出来才用 CLI 自己的更新命令。Claude、Codex、OpenCode 中 T3 Code 认不出的安装方式保持手动；Nix 装的走 Nix，Cursor 和 Antigravity 随 T3 Code 一起更新。Antigravity 与 ChatGPT 连接的 Codex 首次装的是已测版本，发现更新的兼容版本时会在设置里提供更新。

## 2.4 第一个线程

在网页或桌面上点 **New thread**：默认侧栏里有多个打开的项目时会弹出项目选择器（归档项目不算）；Shift-click 可直接在当前项目里开始，也可以用项目自己的新建动作。新线程继承你选的模型和模式，除非目标项目有自己的模型默认值；分支与工作区模式来自你配置的默认值。想在既有 worktree 里继续，用分支工具栏的 **New thread in this worktree**。侧栏被筛到单个项目时，**New thread** 直接在那个项目里建，不再询问。

线程可以没有项目：点新线程标题下的 **or start without a project**、项目菜单里的 **No project**，命令面板里的 **New thread in...**，或按 `mod+alt+n`。这类线程各自占用 `~/.t3/scratch` 下的一个文件夹，名字由日期、首条消息的前几个词和短 id 组成，例如 `2026-09-25-convert-these-pngs-to-webp-a1b2c3d4`。删线程不删文件夹；因为不是 Git 仓库，分支、worktree 和 diff 控件会隐藏。工作变成正经项目时，从线程菜单选 **Turn into project**，再用 **Initialize Git** 获得分支与 diff 能力。

要在后台并行开工，网页和桌面端按 `Cmd+Enter`（macOS）或 `Ctrl+Enter`（Windows / Linux）：新线程立刻跑起来，同时给你一个新的草稿；下一次提交沿用刚选的工作区模式和基准分支。

## 2.5 桌面、网页与手机

桌面应用由服务器加界面组成；网页客户端连接某个环境；手机端从 App Store 或 Google Play 安装，它连的是另一台机器上的服务器，按 remote access 文档用 T3 Connect 或配对 URL 链接。网页和桌面端的 **Settings → About → Mobile app** 也放有商店链接和二维码。商店应用兼容 stable 与 nightly 服务器；TestFlight 需要邀请，Android 测试版可从 beta releases 下 APK。若应用启动即崩，下一次成功启动后到 **Settings → Diagnostics**，那里列出最近 7 天的启动崩溃及组件栈。

从终端打开项目也能进入这套界面：桌面应用已在同机运行时，`t3 app` 会为当前目录开新线程，必要时顺手把项目加进来；`t3 app ../my-project` 指向别的目录。它依赖桌面应用，独立服务器或 SSH 会话不够用。还可以把文件夹从 Finder、Explorer 拖到侧栏，行为等同 `t3 app`；浏览器不共享本机文件夹路径，网页端要用 **Add project**。手机端 **New thread** 依次取当前线程的项目、线程列表筛选的项目、本机上次打开的项目；关掉 **Settings → General → Use last project** 可每次都选。

外部 agent 是另一类入口：在 **Settings → Environments** 里打开环境的菜单选 **Copy MCP URL**，得到形如 `https://<环境地址>/mcp` 的地址，第 13 章再展开它的鉴权流程。

## 2.6 t3 命令族速览

`t3 help` 或 `t3 --help` 给完整参考，下面这些是安装与日常最常用的：

| 命令 | 作用 |
|---|---|
| `t3` | 启动服务器并打开网页应用 |
| `t3 serve` | 只启动服务器，不开浏览器 |
| `t3 ./my-project` | 在指定目录启动 |
| `t3 up` | 让其他设备访问 |
| `t3 service install` | 作为后台服务常驻 |
| `t3 pair` | 连接已经运行的服务器 |
| `t3 app` | 在桌面应用里为当前目录开线程 |
| `t3 update` / `t3 doctor` / `t3 uninstall` | 升级、回收数据库空间、卸载 |
| `t3 thread start . "…"` | 在主机上直接开线程（无需登录） |
| `t3 auth pairing create` | 生成配对码，供外部 agent 签入 |

`t3 thread` 一族在**运行环境的机器**上免签使用，`.` 指包含当前目录的项目或其 Git worktree。新线程用项目默认模型和权限模式，除非传 `--worktree <base-branch>`；`send` 从不打断忙线程，消息会排到下一 turn。需要指定模型时传 `--provider <instance-id> --model <slug>`，模型选项用 `--option` 加选项 id、等号和值，推理强度在 Codex 上是 `--option reasoningEffort=high`、Claude 上是 `--option effort=high`。选项 id 和允许值取决于 provider 与模型，以 `orchestrator_capabilities` 报告的为准，`true` / `false` 用于开关型选项。`--wait` 会打印 agent 的回复：run 失败或停止时退出码 1，agent 等你在应用里回答时退出码 2；加 `--json` 可让结果总带 thread id。传 `-` 作为消息会从 stdin 读取内容。想给线程改名可用 `--title`，想让它像应用里那样从消息生成标题则加 `--generate-title`；标题默认是消息第一行。

## 2.7 首次运行检查清单

按顺序核对下面几项，能排除绝大多数「装好了但不动」的情况：

```text
1. provider 在该环境的 Settings → Providers 中已启用
2. provider CLI 位于服务器机器的 PATH，或已填 Binary path
3. 已在该机器上完成登录（claude auth login / codex login 等）
4. 启动方式明确：t3（带网页）或 t3 serve（不带浏览器）
5. 若有旧服务器提示，用 t3 pair 连接，或更换 --base-dir
6. 手机/网页访问先用 T3 Connect 或配对 URL，不靠猜端口
7. 探测超时需加长时，写进启动器或服务配置并重启服务器
```

这里有个边界值得记住：provider 的探测超时发生在服务器侧，把变量设在你手上的浏览器进程里没有用；对远程环境，要设到跑服务器的那台机器上。另一个边界是安装位置：同一机器已有别的 `t3` 时，安装器不会覆盖它，所以「命令能跑」不等于「跑的是刚装的那个」。手机端若崩溃，靠 **Settings → Diagnostics** 的 7 天记录取证，而不是反复重装。

## 2.8 本章要点与来源

安装分两条路：`t3` 命令行通过 `install.sh` / `install.ps1` 进入 `~/.local/bin`，桌面应用走各平台包管理器；nightly 与钉版本分别用 `T3CODE_CHANNEL` 和 `T3CODE_VERSION`。服务器启动区分为 `t3` 与 `t3 serve`，已有服务器时用 `t3 pair` 配对，`--base-dir` 可开独立实例。provider 的启用在 **Settings → Providers**，登录、PATH 与 Binary path 都属于环境机器；同一 driver 的不同账号要用不同 provider 实例。线程可在当前项目、既有 worktree 或无项目模式下创建，`mod+alt+n` 是无项目快捷键，无项目线程落在 `~/.t3/scratch` 下且不带 Git 控件。三端入口不同但连的是同一个环境；`t3 app` 需要桌面应用存在，浏览器不能代替本机文件夹路径。主机上的 `t3 thread` 系列免签，`.` 解析为当前目录所属项目或其 Git worktree，`send` 不打断忙线程，`--wait` 用退出码区分失败与等待回答。探测加长用 `T3CODE_<PROVIDER>_PROBE_TIMEOUT_MS`，必须在跑服务器的机器上设置并写进启动器。无项目线程落在 `~/.t3/scratch`，不是 Git 仓库，所以没有分支与 diff 控件；手机启动崩溃看 **Settings → Diagnostics** 的 7 天记录。按官方文档 `user/install.md`、`user/thread-sidebar.md` 与 `user/outside-agents.md` 的条目，可以自己核对每条命令、字段名和菜单路径。
