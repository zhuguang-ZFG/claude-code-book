# 第 5 章：一条消息怎样变成上下文
<!-- block: t3code-ch05.b-opening -->

composer（消息输入框）看起来只是一个文本框，实际上是上下文的装配台：你在这里决定 agent 看到什么——正文、附件、引用、终端片段、skill、目标，以及这条消息以什么方式插进正在运行的 turn。这一章按「输入面—字符与粘贴—附件—chip—命令—队列—历史」的顺序走一遍，把官方文档里的数值和快捷键一次列清。

读这一章时请留意两类边界。一类是资源上限：字符数、文件大小、上传完成时机，这些数字来自 `user/composer.md`，不是估计值。另一类是并发边界：排队和 steer 是两种截然不同的投递方式，斜杠命令为什么要等当前 turn 结束、goal 命令为什么例外，都能在这套边界里找到解释。

## 5.1 composer 的输入面

composer 写的是 Markdown，并且边写边渲染。光标落在带样式的文字上时显示其 Markdown 标记，例如 `**bold**`；标记可以像普通字符一样删除或改写，把 `**` 改成 `*` 就变斜体，离开光标后样式更新。想写纯 Markdown 就关掉 **Settings → Chat → Rich text composer**。以 `- `、`1. `、`- [ ] `、`> `、`# ` 或 `---` 开头的行会变成列表、任务列表、引用、标题和分隔线，三个反引号加 Enter 打开代码块；代码块里 Enter 保持缩进，Tab / Shift+Tab 缩进选中行，结尾再输入 ``` 加 Enter 或末行两个空行退出。agent 收到的是你键入的原样文本，标记和编号都算。

回车默认发送；在列表或引用里 Shift+Enter 续行，空行上按一次退出一层，再按一次离开；Tab 把列表项嵌到上一项下面。发送键的行为在 **Settings → Chat → Send shortcut** 里配置，快捷键本身在 **Settings → Keybindings** 里改，配置文件默认位于环境的 `~/.t3/userdata/keybindings.json`，是规则数组：

```json
[
  { "key": "mod+g", "command": "terminal.toggle" },
  { "key": "mod+shift+g", "command": "terminal.new", "when": "terminalFocus" }
]
```

每条规则必须有 `key` 和 `command`，可选的 `when` 用 `terminalFocus`、`composerFocus`、`composerEmpty`、`turnRunning` 等上下文键；`!` 表示非，`&&` 和 `||` 组合，最后一条匹配的规则生效。文件无法解析时 T3 Code 使用默认设置。

## 5.2 字符上限与大粘贴

单条消息最多 120,000 字符。超长的草稿会留在 composer 里，让你自己缩短或拆成几条——系统不会替你截断。粘贴 32 KiB 或以上的文本时，这段内容会自动变成文本附件，这样 agent 能查看全文而不占满模型上下文；较短的粘贴若插入后会突破消息上限，同样变成附件。在硬件键盘上用 `Cmd+Shift+V`（Apple 设备）或 `Ctrl+Shift+V`（其他平台）可以让大段粘贴保持为可编辑文本，而不是附件。

引用（citation）也有成本：引用文本和你写的注释都计入消息上限。因此「把一整段回答引用进来再写两句」看似省事，实际和粘贴正文一样吃额度；差别在于引用保留了指向源消息的链接，源不可用时保存的引用仍然可读。

可以这么理解：这套规则把「模型上下文」和「环境里的文件」分成两种容器。超过阈值的文本不进正文而进附件，agent 依旧能读，但上下文窗口不必为它付整份代价。要注意 provider 和模型自己的限制仍然适用，包括对话里已经有的图片；T3 Code 的字符上限只是第一道闸。草稿里的上传附件、引用和其他附加内容在 Recall 时不会恢复，只有你键入的文本回来——所以长消息最好在发送前用 prompt stash 存一份完整快照。

## 5.3 附件、图片与视频

每条消息最多挂 100 个文件。单张图片上限 10 MiB，一条消息里的图片合计不超过 80 MiB；其他文件（包括视频）单个上限 50 MiB，还要看环境的上传支持与限制。附件在加入时就开始上传，全部完成才能发送；失败的可以重试或删除，网页和桌面端在上传完成前刷新页面需要重新挂一次。provider 与模型的限制（含对话中已有图片）依然叠加在其上。

| 资源 | 上限 / 行为 |
|---|---|
| 消息字符 | 120,000 |
| 文件数 | 每条消息 100 |
| 单张图片 | 10 MiB；单消息合计 80 MiB |
| 其他文件与视频 | 单个 50 MiB |
| ZIP | 最大 50 MB，可作为文件夹列表打开 |
| 大粘贴 | 32 KiB 起自动转文本附件 |
| stash 中的上传文件 | 保留 24 小时 |

网页和桌面端可以把图片拖进或粘贴进 composer，HEIC / HEIF 会被转成 JPEG，超限照片会缩小；移动端支持系统分享菜单传入文件，Android 还能在分屏里从另一个应用拖图进来。视频附件给 agent 的是一个文件路径；只有 Antigravity 会把支持的视频当视频发给 Gemini 模型。超出工作区的文件链接以只读打开，工作区外的 HTML 不能加载邻近的脚本、样式或图片。选择文件 chip 可预览：代码和 JSON 有高亮，Markdown / HTML / CSV / TSV 有渲染与原始两种视图，音频有播放控件，大文本文件只给有限预览，保存后才能读全文。

## 5.4 上下文 chip 与引用

附加的上下文落在光标处，成为正文里的 chip（上下文块）：终端片段、diff 或文件的审阅意见、预览标注、文件都算。chip 可以像字符一样在前后输入、剪切粘贴、删除；悬停看简要信息，选中终端片段看完整输出，选中审阅意见或标注看详情。读屏软件会念出类似「Terminal excerpt, Terminal 1 lines 3-4」的内容。

PR 以图标加号码出现，颜色反映附加时它是 open、draft、merged 还是 closed。输入 `#` 可浏览当前项目仓库里最新的 PR，链接到线程的 PR 会排在最前；继续输入数字按号码筛选，完整号码即使很旧也能直接解析，输入一个词则按文本搜索。另一个线程也能当上下文：输入 `@` 加标题片段，从同一服务器或（在 Linked environments beta 下）链接的机器里选；也可以把线程从侧栏拖到 composer。附带线程只传引用，agent 按需读历史，所以挂一个很长的线程本身不占上下文；它也不会改变那个线程，除非你明确要求。链接到别的环境的线程保持为链接，拖进来则变成保存的 transcript 文件。

图片既有缩略图架也有光标处的 chip，方便说明「我说的是哪张」；删 chip 不动缩略图，删缩略图时若正文仍提到它，会先询问。输入 `@` 加模型名（如 `@opus`）可以点名模型供委派使用，但不会改线程模型。引用用 **Cite in composer**：网页和桌面端选中某条 assistant 回复的文字后执行，可加注释；移动端长按回复、调整选区后选 **Cite**。复制含 chip 的文本再粘贴，chip 及指向会一起走，图片和文件重新从原环境抓取。

## 5.5 skill、命令与 goal

输入 `/` 打开命令菜单，输入 `$` 从所选环境与 provider 添加 skill；移动端在创建线程前的 **New task** 上也有这两个入口。skill 也会出现在斜杠菜单里，除非关掉 **Settings → Chat → Show skills in slash menu**（在 Advanced 下）；只列对该 provider 启用的 skill。增删 skill、插件或 MCP server 之后，在网页和桌面端的命令面板里执行 **Restart agent session**：对话继续，下一条消息会用新配置重新启动 agent。

provider 的命令必须出现在消息开头才生效；T3 Code 自己的命令如 `/model` 和 skill 提及可以出现在任意行。`/compact` 在 provider 支持时减少上下文占用；`/clear` 单独发送（或从斜杠菜单选）会在同一线程开新 session，下一条消息进入看不到旧消息的新 provider session，线程用 **New session** 标记分界，旧消息和 diff 仍保留。上下文用量可在 **Settings → Appearance → Thread details** 打开 Context window 后查看。

`/goal` 后面写清「完成」的标准，例如 `/goal all tests in packages/api pass`，agent 会跨多个 turn 持续工作直到它判断目标达成；线程显示 **Goal** 并在末尾给出进度。它要求 Codex、Claude 或 OpenCode 2.2.5 以上。`/goal` 单用显示当前目标，`/goal clear` 清除；Codex 与 OpenCode 还支持 `/goal pause`、`/goal resume`。Stop 对 Codex / OpenCode 会暂停目标，对 Claude 只结束当前 turn，目标仍在，下一次你发消息时再检查。发送新目标或在 agent 工作时 `/goal resume` 会停掉当前 turn（排队则不会）。composer 里的 `mod+shift+a` 改权限、`mod+shift+x` 改工作区、`mod+shift+g` 改分支、`mod+shift+e` 改推理强度、`mod+shift+l` 直接复用上一个 worktree。

## 5.6 排队、steer 与离线

agent 正在工作时，新消息有两种去处。**Settings → Chat → Follow-up behavior** 在 Queue（排到后续 turn）与 Steer（立即插入当前 turn）之间选择；设置属于当前客户端，已排队的消息保持原位。排队消息保存在服务器上，发送前可编辑或删除。Enter 发送时，`Cmd+Enter`（macOS）/ `Ctrl+Enter`（Windows、Linux）执行相反动作；若你的发送快捷键本来就需要修饰键，则加 Shift 取反。斜杠命令如 `/compact`、`/context` 会等当前 turn 结束，因为把命令 steer 进 turn 会替换 agent 的任务；goal 命令是例外，部分会停止当前 turn。

```json
{
  "key": "mod+enter",
  "command": "thread.steerQueuedMessage",
  "when": "composerFocus && turnRunning && composerEmpty"
}
```

上面这条规则让空 composer 里的 `mod+enter` 把最早一条排队消息变成 steer；更通用的是 `Cmd/Ctrl+Shift+Enter`，它不影响当前草稿，但要求有支持 steer 的活动 turn。`Option+Up`（macOS）/ `Alt+Up`（其他平台）在光标位于 composer 开头时编辑最近排队的消息。移动端在 **Settings → Chat** 里有同样的选择，发送按钮在 turn 运行时显示将执行的动作，长按可单次改用另一个；按钮只在运行中的 agent 支持 steer 时提供 Steer。

离线时手机保留草稿附件的本地副本，可预览、可排队，上传在重连后继续；草稿和排队消息跨应用重启仍存在，退出 T3 Connect 登录后仍留在设备上，重新登录同一账号才取回。若停止 agent 或服务器重启，排队消息保持顺序并被挂起，空 composer 里按 **Resume** 继续；provider 支持原生续跑时不发新提示，不支持时就得发一条消息。发送新消息通常也会恢复队列，但 steer 正在运行的 turn 除外。

## 5.7 编辑历史与 prompt stash

空 composer 里按 `ArrowUp` 找回本线程上次发送的文本，再按继续往前，`ArrowDown` 往回；越过最新一条则清空。只恢复文本，附件、终端上下文和其他附加内容不回来；一旦编辑，这条内容就变成普通草稿。composer 里有附件或已挑元素时不算「空」，方向键照常移动光标。网页和桌面端开启 Settings > Labs 的 **Suggest next prompt** 后，Claude 或 Codex turn 结束时可能给出下一条建议，`Tab` 填入、`Escape` 忽略；每次建议都是一次额外请求并复用该 turn 的 prompt cache，因此会消耗少量额度。

要重写历史，在已发送消息下选 **Edit from here**：`Revert and keep changes` 保留工作区文件，`Revert files too` 恢复到该消息前的检查点（还会撤销你自己改的文件，且只在工作树线程里提供，细节见第 7 章）。被选中的消息及其附件回到 composer 供编辑重发，未发送草稿留在它上方。这会把该消息及之后的对话从活动线程和 provider 历史里移除，但不撤销外部动作或独立的 provider 记忆。

prompt stash 用 `Cmd+S`（macOS）/ `Ctrl+S`（其他平台）保存当前提示与附件，空 composer 时同一快捷键恢复单个 stash 或打开菜单。含上传文件的 stash 必须在原环境恢复，文件保留 24 小时；过期后先恢复文本，再用 **Attach again** 重挂或删掉缺失文件。语音输入用 composer 的麦克风或 `mod+shift+d`，文本转写发生在你在 **Settings → Voice** 选的环境上。撤销侧栏动作则是 `mod+z`：取消固定、结算、snooze、归档和丢弃草稿都会显示 5 秒通知。

## 5.8 本章要点与来源

composer 是上下文装配台：Markdown 边写边渲染，关闭 **Settings → Chat → Rich text composer** 可写纯标记；快捷键放在 `~/.t3/userdata/keybindings.json`，规则含 `key`、`command`、可选 `when`，最后匹配者生效。硬上限是 120,000 字符、每条消息 100 个文件、图片单张 10 MiB 合计 80 MiB、其他文件与视频 50 MiB；32 KiB 以上的粘贴自动转附件。上下文以 chip 形式落在光标处，PR 用 `#`、线程与模型用 `@` 检索，引用文本和注释都计入上限。`/` 是命令、`$` 是 skill，`/compact`、`/clear`、`/goal` 各有明确语义，goal 依赖 Codex、Claude 或 OpenCode 2.2.5 以上。Follow-up behavior 决定 Queue 还是 Steer，斜杠命令等当前 turn 结束，手机离线可排队并续传。Recall 只回文本，prompt stash 连附件一起存但上传件 24 小时失效，且必须在原环境恢复；过期可用 **Attach again** 重挂。编辑历史上，**Edit from here** 的两种恢复方式分别是保留文件和回到该消息前的检查点，后者只在工作树线程提供，且不撤销外部动作。移动端离线排队会在重连后续传，草稿跨重启保留；停止 agent 或服务器重启后按 **Resume** 继续，provider 支持原生续跑时不发新提示。上下文 chip 的复制粘贴会带指向一起走，图片和文件重新从原环境抓取；工作区外文件链接只读。按官方文档 `user/composer.md` 与 `user/keybindings.md` 的条目，可以自己核对数值、字段名与快捷键。
