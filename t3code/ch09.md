# 第 9 章：终端、快照与工作痕迹
<!-- block: t3code-ch09.b-opening -->

agent 的工作不只在 diff 里。命令在终端留下滚动输出，SnapShot 把当前窗口连同可访问性数据贴进草稿，可视化回复生成可交互的 HTML 页面，Usage 则把 token 与额度汇成一张账。本章讨论这些痕迹怎样产生、能保留多久、哪些内容会离开本机。

阅读顺序按“现场—记录—账本—清理”展开：9.1—9.2 是终端与快照，9.3 讨论痕迹如何串起来，9.4—9.6 是可视化回复、文本生成与用量，9.7 讲保留与脱敏，9.8 收束。所有字段名、快捷键与路径均来自钉版文档，按官方文档给出的路径可以自己核对。

## 9.1 终端历史

终端归属环境服务器，而不是客户端。新终端使用哪个可执行文件，由启动 T3 Code 服务器环境中的 `T3CODE_TERMINAL_SHELL` 决定：写名称或完整路径，不要加引号和命令行参数；留空则用平台默认；可执行文件起不来时回退到常规 shell。它不改变 provider 执行的命令，也不改变自动项目初始化与 settle 脚本用的 shell。Windows 上若要用 Git for Windows 自带的 Git Bash，可在 PowerShell 里这样设置：

```powershell
[Environment]::SetEnvironmentVariable('T3CODE_TERMINAL_SHELL', 'C:\Program Files\Git\bin\bash.exe', 'User')
```

完全退出 T3 Code 再重开；若仍继承旧环境，需注销并重新登录 Windows。要用的是 `bin\bash.exe`，不是会另开窗口的 `git-bash.exe`。历史方面，每个终端在环境服务器上保留最多 5,000 行和 8 MiB 滚动内容，先到上限先删最旧输出，长行可能被从开头截短，新输出不截断。网页和桌面用 Shift+PageUp/PageDown 翻阅，Ctrl+Shift+Home/End 跳到开头或最新（macOS 用 Cmd）；终端上下文菜单的 **Select all** 可复制全部保留内容，复制后用 **Jump to latest** 回到最新输出。

## 9.2 快照是什么

SnapShot（快照）捕获你正在看的窗口，并把它附到当前草稿。附件带有应用名与窗口标题，可用时还有应用图标和窗口的可访问性数据（控件、文本及其在图中的位置），agent 可以据此理解截图。功能默认关闭，只在 macOS、Windows 和 Wayland 下的 Linux 桌面应用可用，X11 不支持。开启路径是 **Settings > SnapShots**，分两步：允许捕获、选择快捷键；每一步只显示当前桌面需要的内容，**Finish later** 会关掉捕获但保留已安装组件。

默认快捷键在 macOS 与 Windows 上是两个 Shift 同时按下；T3 Code 在前台时按下，截到的就是它自己。若没有打开的线程，会先在当前项目建一份草稿。待处理的捕获存在磁盘上，附件写入草稿前关掉应用也不会丢，下次启动再附；因图片过大被拒绝的捕获会被丢弃。**Include app text** 决定附件是否包含可访问性数据，关掉后只附截图，在 macOS 上也就不必申请 Accessibility 权限；某些应用只暴露窗口控件而不给正文，响应慢时 T3 Code 会只附截图而不等待。

## 9.3 可追溯的工作痕迹

把三处痕迹放在一起看，就能重建“这一轮到底发生了什么”。终端给出命令与输出的原文，按 9.1 的规则在服务端留 5,000 行/8 MiB；SnapShot 给出窗口画面及可选的控件文本，让 agent 不必靠猜；diff 与线程消息给出改动与决策的顺序。架构上，这些信息的所有者是服务器：provider 进程、终端、Git、检查点和持久状态都在环境一侧，客户端只渲染投影。因此换一台设备连接，看到的不是“本机补出来的记录”，而是同一份已提交状态。Usage 页再把模型侧的工作量补进来：它汇总已连接环境中 Codex、Claude Code、Grok Build、OpenCode、Antigravity、Pi、Muse Code 与 Cursor 的历史，给出 token、缓存节省、模型细分和估算的 API 等价成本；这些估算不是订阅账单。可以这么理解：痕迹的可追溯性来自“状态在服务器、客户端只读”，而不是来自每台设备各自的缓存。

## 9.4 可视化回复与 HTML

agent 可以不用纯文本回答，而是生成一个自包含的 HTML 页面：图表、表格、示意图、拼图或模型稿。只要提出要求（如“show this as a chart”），它就会出现在线上回复的上方，所有 provider、网页、桌面和手机都支持。页面使用当前主题（含自定义主题），并随明暗模式切换；脚本在页面内运行，但与 T3 Code 及你的会话隔离，页面里的链接在浏览器中打开，展开按钮可全屏查看。agent 可以用文件路径把本地图片放进页面，发布时由 T3 Code 内嵌，原文件移动或删除后页面仍可用；删除线程会一并删除它的页面。

发布前，agent 用 T3 Code 自带的无头浏览器截图自查，不使用你安装的浏览器；某台机器第一次预览会下载约 120 MB 到 T3 数据目录，所以可能要等一分钟。预览可以加载 CDN 等公共资源，但不能访问本地网络：运行环境的机器解析域名，私有或保留地址会被拦截。Clash/Mihomo 的 fake-IP 模式可能返回这类地址，导致外链失败，可内联资源、加 `fake-ip-filter` 或改用 redir-host。MCP 应用也会出现在工具调用下方，Claude 需要 2.1.301 及以上版本。

## 9.5 文本生成模型设置

T3 Code 里除了 coding agent，还有只做文本生成的调用：线程标题、commit 消息、PR 文本、分支名和审查指南。Usage 文档指出，对 Codex 与 Claude Code 2.0.63 及以上版本，这类运行不再保存会话历史，因此不计入用量总数。审查指南的撰写模型在 **Settings → Source control & issues** 指定；没有指定时，退回到 source control writer model。视觉回复文档也说明了同一处设置：重写指南时模型会读取临时 checkout 里的改动，不改变其中任何文件，大 PR 需要几分钟。统计口径可以再调：在服务器 `<T3 home>/userdata/settings.json` 里加 `usageModelFilter`，用 `include` 与 `exclude` 按 `provider` 和 `model` 筛选；过滤发生在 **Map to** 之前，所以被排除的模型不会以映射后的名字重新出现。设置无效时 Usage 忽略它并显示所有模型，下一次保存其他设置还会把它从 settings.json 里移除。同理，价格表里的 **Map to** 只改变统计口径，并不改变 agent 实际调用的 provider。每个环境会逐条报告价格是否保存成功，离线环境标记为 **Not saved**，重连后用 **Retry failed saves** 补齐，已保存的环境不会被重复写入。

```json
{
  "usageModelFilter": {
    "include": [{ "provider": "claude", "model": "orbit-1" }],
    "exclude": [{ "model": "drift-9" }]
  }
}
```

## 9.6 用量与额度

Usage 从侧栏或命令面板打开；网页和桌面在终端未聚焦时按 `mod+u`，可在 **Settings → Keybindings** 里改 `usage.open`。它按 token 类型和速度拆分，显示缓存节省与按百万 token 计的细分成本；无法拆分的成本（例如模型没有公开费率、由 provider 直接报数）显示为 **Other**，Fast 与 Ultrafast 高出标准费率的部分记为 **Premium**。服务器默认扫描并保留 92 天历史；Claude Code 30 天后会删自己的 transcript，因此更早的用量只剩这份记录。想延长，在 `<T3 home>/userdata/settings.json` 设 `usageHistoryRetentionDays`（如 `365` 或 `"unlimited"`），但视图最多仍只显示 90 天；调低后下次刷新会裁剪，调回不会恢复。服务器把首个 hostname 存进 `<T3 home>/usage-host-id`，可用 `T3CODE_HOST_ID` 显式指定，容器重建后仍保持用量身份。**Usage → Limits** 按 provider 汇总订阅账号；自动检查同一环境至少间隔五分钟，也可用 `/usage-limits` 在对话里读同一份快照，它既不跑 agent 也不刷新数据。移动端在工作区导航里打开 **Usage** 也能看到同一份汇总。

| 字段或入口 | 位置 | 作用 |
| --- | --- | --- |
| `usageHistoryRetentionDays` | `<T3 home>/userdata/settings.json` | 扫描历史保留天数，可为 `"unlimited"` |
| `T3CODE_HOST_ID` | 服务器环境 | 固定用量身份 |
| `usageModelFilter` | 同上 settings.json | 按 provider/model 纳入或排除 |
| `/usage-limits` | composer 命令 | 读取同一份 Limits 快照 |

## 9.7 保留、清理与脱敏

清理与脱敏分散在几处设置里。终端侧是硬上限：5,000 行与 8 MiB，到达上限删最旧输出，客户端可以显示得更少；`T3CODE_TERMINAL_SHELL` 属于托管服务器那台机器，与远程连接无关。快照侧是可选项：**Include app text** 关掉就只留截图，声音、闪光与飞入动画可分别关闭，系统的“减少动态效果”也会禁用动画；关闭捕获只释放快捷键，不会卸载已安装的 helper。HTML 侧的隔离是结构性的：页面脚本看不到 T3 Code 会话，预览解析到私有或保留地址的名字会被拦截，本地图片在发布时内嵌，因此页面不依赖原路径。可以这么理解：这里的“脱敏”不是把内容改写，而是减少附带上传的字段、限制可访问的网络范围，并让过期痕迹自然消失。按官方文档列出的路径，可以逐项核对哪些内容留在环境、哪些留在设备。

## 9.8 本章要点与来源

要点有四。第一，终端是环境侧资源：`T3CODE_TERMINAL_SHELL` 在启动服务器的机器设置，滚动历史在服务器上限 5,000 行/8 MiB，客户端可以少显示但不能多存。第二，SnapShot 默认关闭，只在桌面端支持，附件是否带可访问性数据由 **Include app text** 控制，未写入草稿的捕获先落盘。第三，可追溯性来自服务器拥有状态：终端、检查点、diff 与用量都归环境，客户端只渲染；HTML 页面可交互但与会话隔离，本地图片在发布时内嵌。第四，Usage 的估算不是账单，历史默认 92 天、视图最多 90 天，`usageModelFilter` 与 `usageHistoryRetentionDays` 分别控制口径与保留期。按上述字段和菜单逐项核对，就能说清每一条痕迹从哪里来、到哪里去。需要追溯时，优先看服务端保存的投影，而不是设备上的缓存；口径有争议时，到 Usage 的 **Breakdown** 里看单个模型的趋势与缓存命中率。
