# 第 10 章：项目、多仓库与设置边界
<!-- block: t3code-ch10.b-opening -->

修改设置前，先确认目标是当前客户端、某个环境，还是某个项目。T3 Code 将偏好分成客户端本地、环境默认和项目覆盖三层；同名设置不一定作用于所有连接。

本章从项目边界和设置归属讲起，再看多仓库工作树、主题、快捷键和语音输入。阅读每项设置时，都要核对它保存在哪一层、影响哪些客户端或项目。

## 10.1 项目是组织边界

项目（project）在 T3 Code 里是组织单位，不是把文件关起来的沙箱。多仓库文档说得很直接：项目覆盖其文件夹内的每一个仓库，没有需要维护的清单；T3 Code 只看下一层，以及本身不是仓库的文件夹（如 `src`、`packages`）再下一层，每次都重新读磁盘，所以新克隆的仓库立刻属于项目，删掉的立刻消失，其他仓库的 worktree 不算进来。项目文件夹本身不必是 Git 仓库。**Settings → Projects → Repositories** 显示它在每台机器上的覆盖范围。项目外的仓库必须显式添加，因为添加才意味着 agent 能到达此前够不着的位置：网页和桌面用 **Add folder**，项目文件夹有 `.code-workspace` 时其中列出的外部文件夹会出现 **Add**（移动端也有），脚本里用 `t3 project add <path> --track <folder>`。**Remove** 只移出项目，不删文件；一个项目最多覆盖 128 个文件夹。架构文档同时规定：设置目标不可用时不能回退到另一个环境。

## 10.2 客户端偏好与环境默认

网页和桌面的设置页顶部有一句 “Applying settings for …”，它指出当前改动作用于哪个项目和哪个环境；只有设备偏好的页面（如 Appearance）不显示这句，并始终停在 **All projects** 与 **All environments**。外观、确认提示、浏览器配置等保存在当前设备或浏览器，忽略环境选择；其余设置存在某台服务器上。选择一个环境就是改它的设置，留在 **All environments** 则一次改所有已连接环境：离线环境保持原值，这是批量编辑，不是全局默认或同步承诺。架构文档用同一句话界定：*All environments* 是对当前已连接服务器的显式批量编辑。Providers 与 diagnostics 是按机器的，一次只显示一个环境（默认是主环境）；其余设置才会向所选目标扇出。多个环境取值不一致时，控件显示 **Mixed**，分层图标变成琥珀色，选一个值就应用到所有目标。

## 10.3 项目覆盖

选中项目即为它在所选环境上写覆盖值。每个服务器行标题旁的分层图标说明当前值来自内置默认、环境还是项目覆盖；点击可展开这条链，覆盖可重置为继续继承。改环境值不会碰项目自己的覆盖：若有项目覆盖了正在编辑的设置，分层图标会计数并逐条列出，点击可跳到该项目，或用 **Reset all** 让它们回到继承状态。不能覆盖项目的设置在项目选中时只读；Providers 的开关则相反——选中项目后可以只为该开关打开或关闭某个 provider，包括“机器上关着、某项目打开”和“机器上开着、某项目关掉”，该项目里的新 turn、排队消息与委派任务的后续都不会用被关掉的 provider，正在跑的 turn 会跑完。解析顺序是：项目覆盖 → 环境设置 → `t3.json` → 内置默认，留 **Inherit** 即交给下一层。仓库级 `t3.json` 还能排除仓库：`ignoreRepositories` 写相对路径，因文件随仓库提交，所有机器一致。

## 10.4 多仓库项目

多仓库项目的 worktree 线程会得到一个按项目布局排列的独立文件夹，所选的每个仓库在其中各自建 worktree，且都落在线程分支上。发送前用 workspace picker 旁的 repositories 控件选仓库：项目覆盖八个及以下仓库时默认全选，更多则一个都不选，直到手动挑；没有任何 commit 的仓库被排除。每个仓库从它拥有同名分支时以线程基线分支起步，否则用自己的默认分支；纯文件夹没有分支选择器，网页和桌面在控件底部填写基线分支。纯文件夹中不属于任何仓库的文件是共享链接而非副本，改一处所有线程都看得见。自定义布局用项目根 `t3.json` 的 `worktreeLayout`：

```json
{
  "worktreeLayout": {
    "create": "./scripts/new-workspace.sh",
    "remove": "./scripts/remove-workspace.sh"
  }
}
```

`create` 在项目文件夹运行并接收下列变量；每次检出必须留在 `T3_WORKTREE_PROJECT_PATH` 上，且必须是 `T3_WORKTREE_BRANCH` 上的 linked worktree。

| 变量 | 含义 |
| --- | --- |
| `T3_PROJECT_ROOT` | 项目文件夹 |
| `T3_WORKTREE_ROOT` | 待填充的空文件夹 |
| `T3_WORKTREE_PROJECT_PATH` | 项目副本在其中的位置 |
| `T3_WORKTREE_BRANCH` | 线程分支名 |
| `T3_WORKTREE_BASE` | 基线分支，无则为空 |
| `T3_WORKTREE_REPOSITORIES` | 所选仓库，每行一个路径 |

`create` 可能因线程文件夹丢失而再次运行，那时分支已存在；`remove` 可能在文件夹部分缺失时运行，并应删掉 `create` 生成的文件。失败的 `create` 会回滚已建检出；每个项目同时只跑一个布局命令，每条命令十分钟超时。

## 10.5 外观与主题

网页和桌面在 **Settings → Appearance** 选主题，可跟随系统、固定明暗，或为明暗分别指定预览；这些偏好按设备或浏览器分别保存。不离开对话也能用命令面板的 **Change theme**，或直接按 `Cmd+Option+A`（macOS）/ `Ctrl+Alt+A`（Windows、Linux）；**Change appearance** 与 `Cmd+Option+Shift+A` / `Ctrl+Alt+Shift+A` 则只切系统、亮、暗。移动端有自己的主题与文本、代码、终端偏好，不跟随环境；Android 12+ 可选 **Material You** 取壁纸颜色，默认还启用 **Material You Layout**。服务端可发布主题：`t3 theme set nightfall` 设定默认并切换已连接客户端，`t3 theme clear` 清除默认，`t3 theme show` 列出默认与已发布主题；主题文件放在 `~/.t3/userdata/themes/`，文件名即主题 ID。自定义 CSS 随主题保存，但不能加载外部文件：导入、图片集与外部地址形式的引用会被忽略，这是为了防止导入的主题把屏幕内容发到外部站点；选择器应优先用 `data-slot` 等稳定的 `data-` 属性，因为类名会随版本变化。服务端停止发布所选主题时，客户端会退回标准主题。

## 10.6 快捷键

快捷键规则保存在环境机器上、默认位于 `~/.t3/userdata/keybindings.json`，可直接编辑。文件是 JSON 数组，每条规则必须有 `key` 和 `command`，可选的 `when` 限定生效上下文；`mod` 在 macOS 是 Command，在其他平台是 Control。可用上下文键包括 `terminalFocus`、`composerFocus`、`composerEmpty`、`turnRunning`、`isWeb`、`isDesktop` 等，未知键求值为 false。冲突时最后一条匹配的规则胜出，所以更具体的规则要写在通用规则之后；无效规则被忽略，文件解析失败则用默认集。

```json
[
  { "key": "mod+g", "command": "terminal.toggle" },
  { "key": "mod+j", "command": "terminal.toggle", "when": "terminalOpen && !terminalFocus" }
]
```

常用组合里，`mod+shift+x` 选工作区、`mod+shift+g` 选 Git 分支、`mod+shift+l` 直接复用上一个 worktree、`mod+shift+m` 选模型、`mod+shift+h` 选主机。桌面端 `mod+w` 关闭聚焦的终端或右栏标签而非窗口，`mod+shift+t` 重开最近关闭的标签；许多默认规则带 `!terminalFocus`，改绑时保留它才能让 tmux 的 `Ctrl+B` 前缀到达终端。要释放某个默认快捷键，先从该行动作菜单选 **Unassign**，之后可用 **Reset to default** 恢复；若自定义桌面占用了同一组键，就在 **Settings → Keybindings** 里另选。`chat.find` 在非终端、非预览区默认是 `mod+f`，它要求服务器支持线程搜索。

## 10.7 语音输入

语音输入把听写文本放进草稿，只有发送消息才会把任何东西交给 agent；它也能用于引用评论、diff 注释、PR 回复与审查总结。网页和桌面必须先选好去处：在 **Settings → Voice** 把 **Transcribe with** 设成某个环境，录音经已鉴权连接送到该环境转写后丢弃；选择只保存在本设备，每台电脑和浏览器都要选一次，设回 **Off** 会丢弃正在进行的录音。选中环境离线时语音输入会等待，T3 Code 不会换一台。macOS 26+ 的桌面应用可选 **Apple Speech**，音频留在 Mac 上。云端路径包括 OpenAI、Grok Voice Transcribe 与 OpenRouter，需要密钥时可用 secret 引用；移除密钥会停掉该 provider 在环境中的使用。移动端默认本机转写，也可在 **Settings → Voice → Transcribe on** 选一个配对环境，录音只发给它，断开即停止，选 **This device** 会撤销访问并丢弃待处理音频。录音最长五分钟，`mod+shift+d` 开始/结束，`Esc` 丢弃；词典与项目词典随录音送到所选环境，项目词典优先，每次最多 100 条；文字清理默认关闭，开启后会把成稿及选区前后各至多 1,024 字符发给草稿所在环境的清理模型，音频不会发送。

## 10.8 本章要点与来源

一句话总结所有权：项目负责把仓库与人在组织上归到一起，环境负责持有设置与文件，客户端只保存本地偏好。设置解析按项目覆盖 → 环境 → `t3.json` → 内置默认，**All environments** 是当前已连接环境的批量编辑而非同步承诺；取值冲突显示 **Mixed**。多仓库项目每次读磁盘决定覆盖范围，Git 动作和布局命令都有明确边界：一个项目同时只跑一个布局命令、每条十分钟、worktree 必须是线程分支上的 linked worktree。外观按设备保存但可由服务端 `t3 theme set` 推送；快捷键文件在环境上，最后匹配的规则胜出；语音输入先选转写环境，离线就等待而不改主机。
