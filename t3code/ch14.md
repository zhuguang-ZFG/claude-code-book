# 第 14 章：设备与移动界面
<!-- block: t3code-ch14.b-opening -->

桌面和手机可以同时查看一个线程，agent 也可能在同一环境里操作模拟器。断网后，草稿、线程状态和设备运行情况分别由不同部分保存，恢复方式也不同。

<!-- block: t3code-ch14.b-client-runtime -->

本章从连接管理和设备发现开始，说明设备画面、移动端交互、离线草稿、语音输入与文件查看，再检查 client-runtime 的重试、缓存和授权规则。尤其要分清哪些数据离线仍可读，哪些操作不会自动重放。

## 14.1 一个服务器与多端同线程

官方文档把边界写得很清楚：web、desktop、mobile 在 `packages/client-runtime` 里对每个环境共享一个连接所有者；平台代码提供存储、凭据、网络信号和生命周期事件，React 视图只消费 runtime。把重试和会话所有权放在同一处，是为了避免出现互相竞争的多个重连循环。

设备也是这套模型的一部分。Device 面板在线程右侧打开一台实时 iOS Simulator 或 Android Emulator，你可以看 agent 如何验证移动端工作，也可以自己点屏；agent 通过 `device_*` 工具和 T3 Code 为它装好的 `agent-device` 命令行拿到同一台设备。模拟器跑在托管环境服务器的那台机器上，视频流经由环境服务器，所以局域网、Tailscale、T3 Connect 都能用。

实时视频要求安全页面（HTTPS 或 localhost）。在明文 HTTP 的远端 origin 上，iOS 退化成较慢的静态图流，Android 除 Expo Simulator 外无法显示视频。这条限制解释了为什么「手机能连上」和「手机能看到设备画面」是两件事。

## 14.2 设备发现与配对

在项目线程里打开右侧面板并选择 **Device**。首次使用会走三步：启动 device hub、检查 iOS 与 Android 支持、选择是否允许 agent 控制设备。只是打开面板不会下载或启动任何东西；hub 已安装时，设置页会说明并复用它。选一台正在运行的设备观看，或对已停止的设备点 **Start** 启动；每台设备一个标签页，只有可见标签页推流，切换标签不会关掉另一台。

自己的设备来源可在 **Settings → Devices** 里添加：**Add source → Machine over SSH**，填 SSH 别名或 `user@host`，可选身份文件和端口，它们在环境服务器上解析，所以用那里的 SSH 配置与密钥。菜单里的 **Test connection** 只检查 SSH、Node、npm 与平台工具，不安装任何东西；首次列出设备时才安装固定版本的工具。SSH 设备主机目前需要 macOS 或 Linux，且非交互式 SSH 命令要能找到 Node 22.12+ 与 npm。

```text
Add source → Machine over SSH
  host: user@host（或 SSH 别名）
  identity file / port: 可选
  Test connection → SSH / Node / npm / 平台工具逐项结果
```

Simlock 主机是 alpha：打开 **Settings → Labs → Simlock device hosts (alpha)** 与 **Use devices**，再用 **Add source → Simlock pool** 填 agent token（`simlock --gateway token create --role agent`）。每台 T3 服务器应有自己的 token。

## 14.3 移动端的线程视图

在手机 app 里打开 agent 所在线程，点 composer 上方的设备按钮即可观看实时画面并操作。在带 inspector 的 iOS 布局里，设备出现在线程旁边，可最大化到全屏；关闭全屏视图回到 inspector。线程开着多台设备时，在查看器里选一台；关闭查看器只是停止推流，设备仍留给 agent 使用。设备活动也会出现在线程时间线上。

桌面与 web 上，agent 打开设备时会像浏览器预览一样浮在聊天之上；在 **Settings → Browser** 关掉 **Auto-show floating preview**，就改为在右侧面板开标签页。工具栏的 **Tools** 抽屉显示前台 app，可切浅色/深色、改字号、翻转无障碍设置、叠加无障碍元素框、设置假位置和授予或撤销权限；iOS 还有 Liquid Glass、色彩滤镜、VoiceOver 与测试推送，Android 增加方向与网络开关。

支持 3D 视图的设备可在实时画面可交互的同时查看机身姿态：iPhone Duo 可用折叠与站立控件，或在机身上捏合调铰链；把模型转到另一块屏，实时显示和触控会切到那块屏。**Restore 3D view** 回到正对屏幕的位置；Android 折叠机有 **Fold device** / **Unfold device**。

## 14.4 离线草稿与队列

手机会在本地保留草稿附件的副本，因此断网时也能预览附件、把消息排进队列；恢复连接后上传继续。草稿和已排队的消息能挺过 app 重启；退出 T3 Connect 登录也不会删掉，重新登录同一账号后还在。web 与桌面则在 **Settings → Chat → Follow-up behavior** 里选 Queue 或 Steer：新消息进后续 turn，或立即 steer 正在跑的 turn。

发送按钮会显示当前动作，长按可只对这一条改用另一个动作；硬件键盘上 macOS 用 `Cmd+Return`、Android 用 `Ctrl+Return` 取反。macOS 的 `Cmd+Shift+Enter`（Windows/Linux 为 `Ctrl+Shift+Enter`）把最旧的一条队列消息作为 steer 发出，且保留当前草稿。agent 被停止或服务器重启后，队列顺序不变并处于保持状态，空 composer 里按 **Resume** 继续。

连接层也区分「暂时断开」和「被移除」。非自愿断开会保留注册与缓存投影；显式移除才关闭该环境作用域并清除凭据、缓存和草稿。缓存投影在离线时仍可读，但绝不能暗示连接还活着，也不能在重连时覆盖更新的实时数据；重连不会自动重放 mutation，重试与幂等归每个操作自己负责。

## 14.5 移动语音输入

手机 composer 的麦克风先录音，确认后才转写，文本插到开始录音时的选区，发送前可以修改。默认音频留在手机上：本地转写需要 iOS 26+ 的受支持 iPhone，或 Android 12+ 配兼容的 Google 语音服务。若要改用配对环境，到 **Settings → Voice → Transcribe on** 选环境并确认；录完的音频只发给那个环境，即使草稿属于别处。

选中的环境断开时听写会停止，绝不切换到别的主机；选 **This device** 则撤销访问并丢弃待处理音频。云听写在 **Settings → Voice** 的环境条目下打开 **Cloud providers** 并确认哪个 provider 可以收到录音。Android 录音与转写期间要让 app 保持在前台；单条录音最长 5 分钟。转写或取消后，手机上的临时录音会被删除，文本留在草稿里直到你发出消息。

麦克风优先级在 **Settings → Voice** 里排序：列表混合内置、有线、蓝牙与 CarPlay，以及你用过的具名设备；拖动即可调整，例如把 **Other Bluetooth** 放在 AirPods 上面，让新耳机优先。web 与桌面的 composer 用麦克风或 `mod+shift+d` 听写，转写环境同样在 **Settings → Voice** 选择。

## 14.6 文件与媒体查看

每条消息最多附 100 个文件；单张图片 10 MiB、单消息图片合计 80 MiB，其他文件（含视频）单个 50 MiB，还要受环境上传能力与 provider 限制。粘贴 32 KiB 以上文本会自动变成文本附件，不占模型上下文。web 与桌面可拖拽或粘贴图片，HEIC/HEIF 会转成 JPEG，超限图片会缩放；手机可从系统分享表发送文件，Android 还能在分屏里从别的 app 拖图进来。

| 类型 | 文档给出的上限或行为 |
|---|---|
| 每消息文件数 | 100 个 |
| 图片 | 单张 10 MiB，合计 80 MiB |
| 其他文件与视频 | 单个 50 MiB |
| ZIP | 50 MB 以内按文件夹列表打开 |

选中附件即可预览：代码与 JSON 有语法高亮，Markdown/HTML/CSV/TSV 有渲染与原始两种视图，音频有播放控件，大文本文件只显示有限预览。HTML 和 PDF 在 web/桌面按渲染页打开，HTML 可切源码视图，但预览无法访问你的 T3 Code session。文件链接始终指向环境的机器，即使是远程连接；工作区之外的文件只读打开，那里的 HTML 不能加载相邻文件的脚本、样式或图片。

## 14.7 跨设备的一致性来源

`packages/client-runtime` 的 supervisor 是传输重试的唯一所有者；端点解析与打开 RPC session 都只尝试一次。瞬时失败用带抖动、有上限的指数退避，且只有在连接稳定后才重置；离线与鉴权失败则等待显式唤醒。回到前台、网络变化、显式重试和离线报告都只是探测已建立的 session，而不是盲目重连——操作系统的离线报告常常是错的，尤其对 loopback；只有探测失败才替换 socket。

registry 按环境划分连接。云账号变更只作用于 relay 注册，绝不能丢掉直接配对的环境。socket 在升级时鉴权，HTTP 请求则从 authorization service 取当前凭据；HTTP 刷新失败不能拆掉一个健康的 socket，快过期的活 socket 会在同一会话上就地续期。

```text
supervisor = 唯一的传输重试所有者
endpoint resolve / RPC open = 单次尝试
前台 / 网络变化 / 显式重试 / 离线报告 → 探测已有 session
非自愿断开 → 保留注册与缓存投影
显式移除 → 清除凭据、缓存与草稿
```


连接活着也不代表环境可用：RPC session 要等服务端初始配置，shell 与线程订阅各自维护同步状态。缓存投影离线可读，但不能冒充实时连接；shell 快照有意是部分的，服务端会省略空闲 subagent 与较老的已结算线程，缺失的行通过 thread-family、shelf 和 search 查询补上——所以少了一行不等于线程被删了。

## 14.8 本章要点与来源

多端共用一个环境连接所有者；设备只是环境里的一台模拟器，画面经环境服务器推给各端。离线能力来自本地草稿、缓存投影和队列，而不是「假装还连着」。

- 设备：首次打开走三步设置；SSH 主机用 `user@host` 与 **Test connection**，Node 22.12+；iOS/Android 视频对 HTTPS 的要求不同。
- 移动：设备按钮在 composer 上方；听写默认留在本机，`Transcribe on` 指定环境后录音只去那里。
- 文件：100 个 / 10 MiB / 80 MiB / 50 MiB 四道上限，工作区外文件只读。
- 一致性：supervisor 独占重试，探测优先于重连；显式移除才清凭据与草稿；重连不自动重放 mutation。

排查多端问题时，先分清三处状态：草稿留在手机，线程状态来自服务器上的持久投影，设备跑在环境主机上。三者恢复方式不同，不能互相替代；各端只是同一个连接作用域的观察者。
