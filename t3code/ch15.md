# 第 15 章：秘密、隔离与遥测
<!-- block: t3code-ch15.b-opening -->

凭据、上传附件、签名资产 URL 和遥测数据走的是不同路径。核对一项功能的数据访问范围，需要知道数据存在哪台机器、由哪个进程读取，以及链接或凭据何时失效。

下面先看 secret provider 与线程内的凭据请求，再看附件和只读 URL 的隔离规则，随后说明遥测内容、关闭方式及开发期凭据。章末清单可用于逐项核对。

## 15.1 secrets 如何进入线程

T3 Code 可以从 secret provider 读凭据：凭据留在你的密码管理器里，T3 Code 只保存一个引用。目前支持的 provider 是 1Password，通过 1Password CLI（`op`）读取，因此运行 T3 Code 服务器的那台机器上必须装好 `op` 并已登录——你用手机或另一台电脑访问时，指的是远端那台机器，不是手里的设备。远程或无头服务器上应该用 service account 或 Connect server 登录，桌面交互登录 remote 用户无法批准。

添加入口是 **Settings → Secrets → Add provider**，填一个名字和 1Password 账号：shorthand、登录地址（不带 `https://`），或 `op account list` 显示的 ID。secret provider 属于你连接的环境，每个环境各有自己的列表；Secrets 设置页处于 preview，并非每个构建都有，但 agent 的 secret 请求在所有版本都能用。

凭据字段（provider 环境变量、源码控制 token、用量限额 key、设备主机 token 等）旁边有来源选择器：选 **Value** 直接保存凭据，或选一个 secret provider 并填引用，例如：

```text
op://vault/item/field
```

引用可用 1Password 的 **Copy Secret Reference** 复制；点引用旁的勾选按钮会立刻读一次。T3 Code 在真正需要时读取，例如 provider 启动时；在 1Password 里改掉凭据后刷新即可生效，文档也说明可以在 **Settings → Providers** 里刷新。

## 15.2 信任边界与泄露面

agent 需要 token 或密码时，线程里出现的是 secret 请求卡，而不是让你把值粘进聊天。你输入或粘贴后选 **Save securely**，或选 **Decline**；web、桌面、手机都能回答。如果环境配了 secret provider，卡片也允许选它并填引用而非明文。T3 Code 在你回答时读一次；1Password 锁着时卡片会说明，请求保持打开，解锁后重试或直接填值。

值不进入对话。多数请求连 agent 也不给值：T3 Code 把它交给真正需要用的工具。少数情况 agent 必须拿值去跑命令，卡片会明确说明——此时值被写进一个私有文件，agent 的命令可在约 24 小时内读到它。这是「不进聊天记录」与「agent 确实要用」之间的折中，值得在审查线程时留意。

另一条边界是可恢复秘密不进读模型：只有创建响应返回原始的配对凭据，访问列表只暴露元数据。也就是说，列一下已有的配对或分享，不会把可用的 token 再吐出来。

| 场景 | 值的去向 |
|---|---|
| 普通 secret 请求 | 交给需要的工具，不进对话 |
| agent 必须用值跑命令 | 写入私有文件，约 24 小时可读 |
| 请求卡回答时填引用 | 当时读取一次，原值留在 1Password |
| 列出已有凭据或分享 | 只见元数据，不见原始凭据 |

## 15.3 附件不进项目树

provider 文档把这条写成硬性约束：附件必须留在项目工作区之外，绝不能为了绕过 provider 的沙箱或批准规则，把上传文件拷进项目树。换句话说，附件是环境里的另一个文件位置，agent 拿到路径去读，而不是工作区里多出一个新文件。

composer 一侧配合这条边界：粘贴 32 KiB 以上的文本会自动成为文本附件，让 agent 去检查，不必塞满模型上下文；每条消息最多 100 个文件，图片单张 10 MiB、合计 80 MiB，其他文件单个 50 MiB。上传在你添加附件时就开始了，全部完成才能发送；失败要重试或移除。web 与桌面在上传完成前刷新，需要重新附一次文件。

文件链接始终指向环境的机器，远程连接时也一样；预览用的是原文件，包括工作区之外的文件，移动或删除它会让预览失效。工作区之外的文件以只读方式打开，那里的 HTML 不能加载相邻文件的脚本、样式或图片——附件预览因此不是「在项目里开了一个网页」。

## 15.4 只读文件与签名资产 URL

环境鉴权文档提醒：项目是组织边界，不是文件系统沙箱。拥有 `filesystem:read` 意味着可以读服务器 OS 用户能读的任何文件，比如 agent 写在临时目录里的产物；相对路径与写入仍受 `WorkspaceFileSystem.ts` 约束。所以文件能否被读，取决于服务器进程身份，而不是 UI 上选了哪个项目。

签名资产 URL 是另一种凭据：它只对应一个规范文件的 bearer credential，服务时会按 device/inode 身份再次核对（`AssetAccess.ts`），不会授予相邻文件访问权。但要注意一个时间差——`filesystem:read` 只在铸造 URL 时检查，因此已发出的 URL 在到期前一直有效，即便会话或授权已经被撤销。需要「立即失效」的场合，不能把签名 URL 当成撤销手段。

HTML 预览也无法访问你的 T3 Code session，且在 web/桌面可切源码视图查看标记。这几条合起来的意思是：只读预览、签名 URL 和会话鉴权是三套独立机制，各有自己的有效期和范围。

## 15.5 产品使用数据

T3 Code 服务器会向自己的 `ingest.t3.codes` 端点发送产品使用事件，关联哈希后的账号或安装标识；为统计一个人用了多少安装，还会发送哈希后的 T3 Connect 账号、已登录时的 OpenAI 与 Claude 账号，以及每个连接设备的随机标识。端点保留事件副本并转发到 PostHog。事件包含 provider、model、reasoning effort、permission mode、turn 与 request 结果、时长、release channel、可用时的 token 计数（子 agent 与主 agent 分开计），以及 provider 实际用的 model ID，包括自定义模型和自定义端点提供的模型。

文档明确不含提示词、回复、文件内容、鉴权 token、会话 ID、原始 provider 事件和子 agent 输出，唯一例外是 agent feedback。该功能的模式在 **Settings > Labs → Agent feedback** 选：默认 **Off** 时 agent 看不到反馈工具；**When I ask** 只在你要它报告时发；**Automatic** 会主动报告它遇到的 T3 问题。请求报告时线程中会出现写明将发出什么的卡片，按 **Send** 才发送；单个报告可含至多 300 字符的描述，经你批准的还带 turn 大纲（谁说话、消息长度、跑了哪些工具），不含文本。

要停掉产品事件：在启动服务器前设置 `T3CODE_TELEMETRY_ENABLED=false`。反馈报告先存本机，`t3 feedback list --json` 可核对每条报告究竟含什么。

```sh
t3 feedback list
t3 feedback list --json
```

## 15.6 开发凭据的隔离

开发场景有一个特殊凭据：`T3CODE_DEV_AUTH_TOKEN`。文档限定它只能用在「你信任该主机名上每个服务」的场合，因为浏览器在同一主机名的不同端口间共享 cookie；它在一个主机名上跨 worktree、跨端口可复用，并授予管理访问权限。桌面版和非开发服务器会忽略它，正常凭据始终优先：一个正常凭据被拒绝时，绝不回退到开发凭据。

隔离是按环境做的。每个环境把这个值哈希进自己的数据库记录，各自维护独立的 SQLite 状态、签名密钥和撤销状态。也就是说，即使两个开发实例共用同一段 token 文本，它们也不是同一个会话体系。

可以这么理解：它解决的是 dev server 反复重启、端口漂移带来的登录摩擦，代价是那个主机名上的所有开发服务共享一个高权限入口。因此它与生产环境的配对、OAuth 登录不共用信任假设，也不要把开发用的主机名和端口当成安全边界。

## 15.7 安全清单

下面这些点都能按官方文档逐条核对，适合在把环境开放给外部 agent 或远程设备前过一遍：

1. 配对只收窄作用域：用 bootstrap 凭据交换只能缩小 grant，client label 与设备元数据没有授权作用。
2. DPoP 失败必须失败：无效证明不能退化成 bearer；WebSocket 票据短期有效，长期 token 不进 socket URL。
3. 每个 RPC 单独查 scope，握手成功不增加权限；MCP 工具静态声明访问级别，线程专属工具在 handler 里再次拒绝外部调用方。
4. guest link 不是 session：它是绑定到一次分享的 HMAC token，任何 RPC、WebSocket 或 MCP 路由都不接受。
5. scope 演化向后兼容：交换时取请求 scope 与配对 grant 的交集，丢弃已退役名称；存储 grant 在 scope 拆分时不扩大，响应同时保留旧 `scopes` 与精确的 `permissions`。
6. 签名资产 URL 只在铸造时查 `filesystem:read`，撤销会话不会让已发出的 URL 立即失效。

```text
检查顺序：作用域 → DPoP/socket 票据 → 每 RPC scope → MCP 访问级别
        → guest link 类型 → 已发资产 URL 的有效期
```

## 15.8 本章要点与来源

秘密以引用形式留在 1Password，T3 Code 只存 `op://vault/item/field`；agent 索取时用线程内的卡片，明文尽量不进对话。隔离的关键不是 UI，而是服务器进程身份、签名 URL 的有效期与每 RPC 的 scope 检查。

- 秘密：provider 属于环境；普通请求把值交给工具，必须用值时落入约 24 小时的私有文件。
- 附件：上传不进项目树，链接指向环境机器；工作区外文件只读，HTML 预览无 session。
- 遥测：事件不含提示词与回复；`T3CODE_TELEMETRY_ENABLED=false` 在启动前设置，agent feedback 默认 Off。
- 开发凭据：`T3CODE_DEV_AUTH_TOKEN` 只在受信任主机名跨 worktree 复用，正常凭据优先，各环境独立哈希与撤销。

还有一条贯穿本章的判断标准：看一段数据是否安全，要问它在哪台机器上、以谁的进程身份被读取、有没有到期时间、以及撤销之后旧凭据是否仍然可用。明文秘密、附件、签名资产 URL 和遥测事件对这四个问题的答案都不一样，把它们混作「一个安全设置」会看漏边界。可以这么理解：这一章列的是边界清单，不是一个总开关。
