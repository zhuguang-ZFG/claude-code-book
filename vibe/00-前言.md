# 前言

<!-- block: vibe-front.b-opening -->
你大概见过这样的演示：对着 AI 说一句“做一个二手书交换网站”，几分钟后屏幕上出现一个能点的页面。它看起来像那么回事，直到你输入一条空记录，或者把书名里的引号贴进去。

Vibe coding 的吸引力正在这里：把“我想做一个东西”压缩成一句话，让模型补上代码、样式和命令。它确实能把周末的想法变成能跑的原型，也能让不写代码的人完成一次小工具。问题出在“能跑”之后。谁能确认它没有丢掉数据，没有把联系方式贴在公开页面上，下一次修改时还找得回原来的版本？

这本书不劝你回到逐行手写，也不把“自然语言写软件”说成万能。它给出一套可重复的流程：把感觉写成任务卡，用例子代替形容词，小步运行，把报错当证据，到了风险边界就停下来读代码，最后按验收单交付。全书用同一个案例走完：把一份旧书交换市集的 CSV，做成可发布、可维护的书架页面。

## 谁适合读

- 已经用聊天模型写过脚本、页面或小工具，但交付时心里没底的人。
- 不打算成为职业程序员，却需要可靠地维护一两个内部工具的人。
- 带团队做原型，想把“看起来能跑”变成“可以交给下一个人”的人。

不需要先学完 Python 或前端。书里的程序只用 Python 标准库，页面是单个 HTML 文件。你需要会打开终端、编辑文本文件，并愿意在运行结果前停一下。

## 这本书怎么读

全书分三篇，共十二章，另附四个附录：

- **第一篇 · 入门（第 1–4 章）**：说清 vibe coding 的边界，写任务卡，用例子固定期望，留下第一个可运行版本和回退点。
- **第二篇 · 进阶（第 5–8 章）**：用十分钟循环推进，把报错变成证据，用回归测试固定修复，按风险分级决定何时读代码。
- **第三篇 · 精通（第 9–12 章）**：做验收与回滚，处理数据、权限和隐私，把原型部署出去，最后完成团队交接与维护。
- **附录 A–D**：可直接抄的模板、固定提交的 GitHub 书目、术语表，以及一份从入门到精通的练习路线。

| 你现在的处境 | 从哪读 | 读完后手里有什么 |
| --- | --- | --- |
| 一句话生成的东西总是不符合预期 | 第 1–3 章 | 一张能执行的任务卡和一组输入输出例子 |

书中的“旧书市集”是虚构案例，CSV 里的书名、人名和联系方式均为教学数据。代码在 Python 3.12 下逐段运行过；不同模型和工具的输出不会相同，书中不把某次回答当作产品能力证明。

## 开始前的三个检查

动笔写提示之前，先确认三件事：

1. **每次改动前有一个能运行的版本。** 可以复制文件，也可以用 Git；形式不限，但要能退回。第 4 章会把运行命令、输入输出和第一个提交固定下来。
2. **判断结果时看终端输出、退出码、测试和页面。** 模型说“已完成”不构成证据。拿不到输出时，写“未验证”，不要补一个看起来合理的结果。
3. **任务碰到真实用户、真实数据或真实付款时，先读相关代码，再让模型改。** 个人周末脚本可以宽松一些；进入交付阶段后，验收标准要换成工程标准。第 8 章给出分级，第 10 章处理数据与权限。

## 这本书在系列中的位置

“大模型与智能体工程”系列里，《御舆》拆 Agent Harness 的内部结构，各工具分册讲具体产品的安装、权限与会话。本书站在使用者一侧：不讨论某个 Agent 的内部实现，只讨论怎样把一次生成变成可验收、可维护的交付。需要查某个工具的命令或配置时，回到对应分册；附录 B 给出可直接打开的 GitHub 入口。

书的章节安排参考了几本社区开源教材的进阶方式：先补软件工程基础，再进入 Agent 协作，最后处理安全、部署与维护。附录 B 列出这些书的固定提交、许可证和适合带着什么问题去读；附录 D 把它们对应到本书的三阶段练习。引用只用于确定阅读顺序和检查项，不转载正文。
