# 前言

<!-- block: vibe-front.b-opening -->
你大概见过这样的演示：对着 AI 说一句“做一个二手书交换网站”，几分钟后屏幕上出现一个能点的页面。它看起来像那么回事，直到你输入一条空记录，或者把书名里的引号贴进去。

Vibe coding 的吸引力正在这里：把“我想做一个东西”压缩成一句话，让模型补上代码、样式和命令。它确实能把周末的想法变成能跑的原型，也能让不写代码的人完成一次小工具。问题出在“能跑”之后。谁能确认它没有丢掉数据，没有把联系方式贴在公开页面上，下一次修改时还找得回原来的版本？

这本书不劝你回到逐行手写，也不把“自然语言写软件”说成万能。它讲一条可重复的路：把感觉写成任务卡，用例子代替形容词，小步运行，把报错当证据，到了风险边界就停下来读代码，最后按验收单交付。全书用同一个案例走完：把一份旧书交换市集的 CSV，做成可发布的书架页面。

## 谁适合读

- 已经用聊天模型写过脚本、页面或小工具，但交付时心里没底的人。
- 不打算成为职业程序员，却需要可靠地维护一两个内部工具的人。
- 带团队做原型，想把“看起来能跑”变成“可以交给下一个人”的人。

不需要先学完 Python 或前端。书里的程序只用 Python 标准库，页面是单个 HTML 文件。你需要会打开终端、编辑文本文件，并愿意在运行结果前停一下。

## 这本书怎么读

前三章处理起步：说清 vibe coding 的边界，写一张任务卡，先给例子再让模型写。第四到六章进入循环：小步改、读报错、在风险边界停下来。最后两章做交付：验收、回滚、交接。

| 你现在的处境 | 从哪读 | 读完后手里有什么 |
| --- | --- | --- |
| 一句话生成的东西总是不符合预期 | 第 1–3 章 | 一张能执行的任务卡和一组输入输出例子 |
| 改一处坏三处，越改越乱 | 第 4–5 章 | 一个十分钟循环和一份最小复现 |
| 不知道什么时候该自己看代码 | 第 6 章 | 一张风险分级表和必须停手的信号 |
| 想交给同事或上线 | 第 7–8 章 | 验收单、回滚点和交接记录 |

书中的“旧书市集”是虚构案例，CSV 里的书名、人名和联系方式均为教学数据。代码在 Python 3.12 下逐段运行过；不同模型和工具的输出不会相同，书中不把某次回答当作产品能力证明。

## 三个约定

第一，**先保存，再运行**。每次让模型改动前，保留当前可运行的版本。可以复制文件，也可以用 Git；形式不重要，能退回去才重要。

第二，**只把真实输出当证据**。模型说“已完成”不算，终端退出码、页面截图、测试结果才算。拿不到输出时，就写“未验证”，不要补一个看起来合理的结果。

第三，**风险越高，越早读代码**。个人周末脚本可以宽松一些；碰到真实用户、真实数据、真实付款，验收标准要换成工程标准。第 6 章给出分界线。

## 这本书在系列中的位置

“大模型与智能体工程”系列里，《御舆》拆 Agent Harness 的内部结构，各工具分册讲具体产品的安装、权限与会话。本书站在使用者一侧：不讨论某个 Agent 的内部实现，只讨论怎样把一次生成变成可验收的交付。需要查某个工具的命令或配置时，回到对应分册；本书的附录 B 给出可直接打开的 GitHub 入口。

Vibe coding 不是省掉工程，而是把工程判断挪到更靠前的位置：在写提示之前决定验收什么，在模型动手之前准备例子，在发布之前留下回滚点。下一页从边界开始。
