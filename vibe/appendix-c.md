# 附录 C：术语表

| 术语 | 本书用法 | 容易混淆的地方 |
| --- | --- | --- |
| Vibe coding | 用自然语言与运行结果驱动实现，允许暂时不逐行读代码，但交付前仍对边界负责 | 不等于“完全不读代码”或“不用测试” |
| 任务卡 | 写清目标、输入、规则、验收、回退的短合同 | 不是提示词模板，不追求固定措辞 |
| Fixture | 一份小而完整、可重复使用的测试输入 | 不是生产数据；不要放真实隐私 |
| 最小复现 | 能稳定触发问题的最短命令与输入 | 不是完整项目压缩包 |
| 验收条件 | 能判定通过或失败的可观察结果 | “看起来不错”不是验收条件 |
| 否定条件 | 什么出现就算失败，例如公开页出现邮箱 | 与正常路径同样重要 |
| 回滚点 | 出错后可以恢复的产物或提交 | 不是“再生成一版” |
| 风险梯子 | 按最坏损失给任务分级：只读、写文件、处理他人数据、调外部服务、动钱或权限 | 不按代码行数分级 |
| 交接包 | 运行方式、规则、决策记录三样合起来 | 不是代码压缩包 |
| 原子替换 | 先写临时文件，成功后再替换目标文件 | 避免失败时留下半成品 |
