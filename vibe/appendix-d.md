# 附录 D：从入门到精通的练习路线

正文按“入门—进阶—精通”组织，但读完不等于会做。这份路线把十二章压成三次练习，每次都有一个能检查的交付物。不要跳阶段；前一次的产物是后一次的输入。

## D.1 三个阶段

| 阶段 | 对应章节 | 交付物 | 通过条件 |
| --- | --- | --- | --- |
| 入门 | 第 1–4 章 | 任务卡、八行样例、可运行的最小脚本 | 一条命令打印正确行数；缺输入时非 0 退出且不留下半成品 |
| 进阶 | 第 5–8 章 | 十分钟循环记录、回归测试、风险清单 | 曾经出错的行为有测试；高风险点有处理方案 |
| 精通 | 第 9–12 章 | 验收单、部署记录、交接包 | 换一个人按 README 能跑通并完成回滚 |

每次练习都用同一个旧书市集案例。想换成自己的题目可以，但先按原案例走完一遍，否则很难判断失败是流程问题还是题目本身太复杂。

## D.2 入门：跑通一次交付

1. **写任务卡。** 按附录 A.1 填五块：目标、输入、规则、验收、回退。规则至少有一条否定条件。
2. **准备样例。** 从 `books.csv` 截八行，覆盖正常行、缺书名、缺摊主、重复书名、未知品相。把期望结果写在样例旁边。
3. **生成最小版本。** 只要求读取 CSV 并打印行数，不要求页面。命令固定为 `python shelf.py fixtures/books.csv`。终端应打印实际读到的行数。数字不对，先查编码和表头，不要加样式。
4. **保存第一个版本。** 复制目录或 `git init` 后提交。提交信息写“读取 CSV 并打印行数”，不要写“初始版本”。

入门阶段的常见失败是过早要求完整页面。页面会掩盖数据问题；先让计数正确，再让卡片出现。

## D.3 进阶：让错误可复现

1. **跑十分钟循环。** 按第 5 章选一个可观察行为，例如“跳过空书名并打印行号”。改一处、跑一次、对比输出、保存。记录每圈的命令和结果。
2. **制造一次真实失败。** 用第 5 章只按书名去重的版本，运行第 7 章的 `DuplicateKeyTests`，预期看到 `AssertionError: 1 != 2`。把失败信息、输入和命令抄进笔记。不要先改测试。
3. **只改一个原因。** 把去重键改为 `title + author`，重跑同一条测试。通过后，再跑完整套件，确认没有破坏其他行为。
4. **做风险分级。** 按第 8 章列出当前级别，找五个停手信号里最接近的一条，写下触发条件和最小修复。

进阶阶段不要求部署。要求是：同一个错误出现第二次时，你能用一条命令复现它，并指出哪条测试会失败。

## D.4 精通：部署与交接

1. **补验收。** 按第 9 章写四层检查：单元、端到端、人工、回滚。实际演练一次回滚：保留旧页面，删掉输入，确认程序非 0 退出且不覆盖旧产物。
2. **处理数据边界。** 按第 10 章画数据流：哪些字段进数据库、哪些进公开视图、谁能改哪一行。至少验证一次越权请求被拒绝。
3. **部署一次。** 按第 11 章准备环境变量、启动命令、日志和停止方式。部署后检查：页面可访问、日志有记录、旧版本可恢复。
4. **做交接演练。** 按第 12 章找一位没参与的人，只给目录和 README，让他完成：干净环境运行、缺输入报错、找到隐私规则、说出回滚位置。记录他卡住的步骤并补文档。

精通阶段要看别人能否接手；功能数量不是验收项。如果交接演练需要你在旁边解释，说明 README 或决策记录还缺内容。

## D.5 自评表

```text
[ ] 我能用一句话说清项目读什么、写什么、给谁用。
[ ] 我有一个不依赖聊天记录的任务卡。
[ ] 我能用一条命令复现当前版本。
[ ] 我知道最近一次失败测试叫什么名字。
[ ] 我能指出程序里处理隐私字段的位置。
[ ] 我实际回滚过一次，而不只是知道应该回滚。
[ ] 另一个人按 README 跑通过，没有问我命令。
```

七项里有任何一项做不到，回到对应章节补，不要用新功能掩盖。延伸书目见附录 B.3；每本书适合带着什么问题读，表里已经写明。
