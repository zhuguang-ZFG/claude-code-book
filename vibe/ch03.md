# 第 3 章：先给例子，再让模型写

<!-- block: vibe-ch03.b-opening -->
任务卡说“书名与作者相同算重复”。模型先给出一个只比较书名的版本。你说不对，它改成比较“书名 + 作者 + 品相”，又把同一本书的两个品相拆成两条。文字规则容易留下歧义，具体例子能固定边界。

下面用一组小而完整的输入输出，把“我想要的”变成模型能对照的东西。

## 用例子固定规格

对旧书市集，先准备一份八行的 `fixtures/books.csv`：

```csv
title,author,condition,owner,contact
夜航西飞,柏瑞尔·马卡姆,good,林,lin@example.com
夜航西飞,柏瑞尔·马卡姆,worn,周,zhou@example.com
小王子,圣埃克苏佩里,new,陈,chen@example.com
, ,good,吴,wu@example.com
孤独及其所创造的,保罗·奥斯特,unknown,林,lin@example.com
小王子,圣埃克苏佩里,good,陈,chen@example.com
局外人,加缪,worn,周,zhou@example.com
,无名氏,good,郑,zheng@example.com
```

这八行同时覆盖了正常记录、重复书名、重复作者、空书名、空摊主、未知品相和不同品相。它足够小，能在一屏内看完；也足够刁钻，能逼出实现里的假设。

配套写一份期望结果，不必是完整 HTML，抓住可判定的部分：

```text
卡片顺序：
1. 小王子 / 圣埃克苏佩里 / new / 陈
2. 夜航西飞 / 柏瑞尔·马卡姆 / good / 林、周
3. 孤独及其所创造的 / 保罗·奥斯特 / unknown / 林
4. 局外人 / 加缪 / worn / 周

终端输出：
重复组：2
跳过行：2（第 5 行、第 9 行）
公开页面不得出现：lin@example.com、chen@example.com、zhou@example.com
```

注意这里没有规定 HTML 的类名、字体或卡片圆角。那些属于实现自由度。例子约束的是数据行为，不是模型的审美。

## 三类例子，各管一件事

| 类型 | 作用 | 旧书案例 |
| --- | --- | --- |
| 正常例 | 证明主路径能走通 | 一条完整记录生成一张卡片 |
| 边界例 | 逼出空值、重复、极端值 | 空书名、空摊主、未知品相 |
| 反例 | 证明不该发生的事没有发生 | 页面源码不出现邮箱；缺文件时不生成半成品 |

只给正常例，模型会写出“一切顺利”的版本；只给反例，它不知道正常路径应该输出什么。三类一起给，才能覆盖主路径和边界。

如果界面是重点，再加一张截图或手绘草图。截图能说明布局和层级，但不能代替数据规则。把截图与文字规则并列，不要让模型从像素里猜“联系方式要不要显示”。

## 例子要能独立运行

例子最怕依赖你机器上的隐含状态：一个没提交的 CSV、一个全局安装的包、一个昨天改过的配置。把例子收进项目目录，用相对路径引用：

```text
vibe-shelf/
├── shelf.py
├── fixtures/
│   ├── books.csv
│   └── expected.txt
├── task-card.md
└── README.md
```

README 只写三件事：怎么运行、期望看到什么、失败时先查哪里。不要写“详见聊天记录”，聊天记录不是交付物。

## 让模型先复述例子

在写代码前，加一句：

> 先不要写实现。用三句话说明你会怎样处理空书名、重复记录和 contact 字段；然后列出你准备用来验证的三个输入。

模型复述错了，改例子或改任务卡；复述对了，再让它动手。这个停顿很短，却能拦住最常见的误解：把“去重”理解成删掉所有重复行，而不是合并摊主；把“不公开联系方式”理解成把邮箱换成星号，却仍然写进 HTML。

## 例子也会过时

需求一变，例子要跟着变。新增“中文品相映射”后，fixtures 里应出现“九成新”；新增“下架书籍”后，应出现一个 `status=off` 的行。例子不更新，测试就会继续保护旧行为，代码却已经走向新规则。

每次改例子，都在 `expected.txt` 顶部写一行变更原因。例如：

```text
2026-11-15 增加“九成新”映射用例；旧版把未知品相排到最后，现改为先映射再排序。
```

这不是形式主义。下一个人看到失败测试时，需要知道是代码坏了，还是期望变了。

## 动手做

为你的任务准备三样东西：

1. 一份不超过 10 行的输入样例。
2. 一份期望结果，至少包含一个否定条件。
3. 一句让模型先复述规则的指令。

把这三样放进项目目录，确认它们在另一台机器上也能用相对路径找到。

## 关键要点

- 例子约束数据行为，不约束实现风格。
- 正常例、边界例、反例各准备一条。
- 例子要独立、可运行、跟项目一起保存。
- 先让模型复述，再让它写代码。
