“看起来对”只能证明主路径走通。验收要同时检查退出码、产物时间、内容边界和回滚路径；缺一项，旧文件或旧行为就可能被当成新结果。

## 四层验收

| 层 | 检查什么 | 旧书案例 |
| --- | --- | --- |
| 单元 | 一个函数在给定输入下的输出 | `merge()` 保留较好品相并合并摊主 |
| 端到端 | 从命令到产物的完整路径 | 运行脚本生成 `shelf.html`，卡片数与终端输出一致 |
| 人工 | 页面实际看起来怎样 | 手机宽度下不横向滚动，书名不溢出 |
| 回滚 | 出错后能否恢复 | 上一版 HTML 与 Git 提交都在 |

四层各管一段：只做单元测试，页面可能丑得没法用；只看页面，数据可能已经错了；没有回滚，出错就只能重写。

## 把验收写成测试

Python 标准库的 `unittest` 就够。把下面存成 `test_shelf.py`，与 `shelf.py` 放在同一目录：

```python
import tempfile
import unittest
from pathlib import Path

import shelf


class ShelfTests(unittest.TestCase):
    def write(self, text: str) -> Path:
        folder = Path(tempfile.mkdtemp())
        path = folder / "books.csv"
        path.write_text(text, encoding="utf-8")
        return path

    def test_rows_without_title_or_owner_are_skipped(self):
        path = self.write("title,author,condition,owner\n"
                          "A,甲,new,林\n"
                          ",乙,good,周\n"
                          "B,丙,worn,\n")
        books, skipped = shelf.read_books(path)
        self.assertEqual([b["title"] for b in books], ["A"])
        self.assertEqual(skipped, [3, 4])

    def test_duplicates_keep_the_best_condition_and_merge_owners(self):
        path = self.write("title,author,condition,owner\n"
                          "A,甲,worn,林\n"
                          "A,甲,new,周\n")
        books, skipped = shelf.read_books(path)
        merged, groups = shelf.merge(books)
        self.assertEqual(skipped, [])
        self.assertEqual(groups, 1)
        self.assertEqual(merged[0]["condition"], "new")
        self.assertEqual(merged[0]["owners"], ["林", "周"])

    def test_public_page_escapes_html_and_hides_contact(self):
        books = [{"title": "<A>", "author": "甲", "condition": "new",
                  "owner": "林", "contact": "lin@example.com"}]
        merged, _ = shelf.merge(books)
        page = shelf.render(merged)
        self.assertIn("&lt;A&gt;", page)
        self.assertNotIn("<A>", page)
        self.assertNotIn("lin@example.com", page)

    def test_missing_input_leaves_no_output(self):
        folder = Path(tempfile.mkdtemp())
        target = folder / "shelf.html"
        self.assertEqual(shelf.main([str(folder / "missing.csv"),
                                    "-o", str(target)]), 2)
        self.assertFalse(target.exists())
```

## 套件要包含曾经出错的行为

第 7 章的同名不同作者测试也应留在 `test_shelf.py` 里。它和上面四条一起运行，把已经发生过的错误固定下来。测试数量本身不说明覆盖；每一条应对一个具体的失败假设，失败信息能直接指出哪条规则被破坏。

运行完整套件：

```bash
python -m unittest test_shelf.py -v
```

全部通过后，再跑一次端到端命令，确认终端计数与页面内容一致。测试通过但端到端输出变了，说明还有未覆盖的集成路径。

## 人工验收也要写下来

自动化测试管不到视觉。发布前用手机宽度打开页面，检查：

- 页面宽度等于屏幕宽度，没有横向滚动。
- 长书名换行，不覆盖摊主名。
- 卡片顺序与终端输出一致。
- 页面源码搜不到 `@` 或手机号。
- 断网后页面仍能打开（没有外部字体、脚本或图片）。

把这几条写进 `README.md`，下次换人发布时照单检查。

## 回滚要在出错前准备

具体做法：

1. 保留上一版 `shelf.html`，命名带日期，例如 `shelf-2026-11-15.html`。
2. 代码用 Git 提交，记录当前可用版本。
3. 数据源 `books.csv` 只读，程序不覆盖它。
4. 输出先写临时文件，成功后再替换，避免半成品。

前三条是人的动作，第四条是代码责任。`shelf.py` 里的 `temporary.replace(args.output)` 就是第四条：渲染失败时，旧页面还在。

如果发布后才发现错误，回滚顺序是：先恢复上一版页面，再修代码，最后重新验收。不要一边修一边让错误版本继续服务。

## 动手做

为你的工具补四层验收：

- 两条单元测试：一条正常路径，一条边界。
- 一条端到端命令，记录期望输出。
- 一张人工检查清单。
- 一个回滚动作，实际演练一次。

把测试命令写进 README，确保别人不用问你就知道怎么跑。

## 关键要点

- 验收分四层：单元、端到端、人工、回滚。
- 测试要覆盖曾经出错的那个假设，而不只是主路径。
- 视觉检查也要写成清单，发布前照单执行。
- 回滚在出错前准备：旧产物、Git、只读源、原子替换。
